# L1–P1/S1接続 v0.1 実施報告

## 結論

**同期復調した意味信号を、SS記憶の更新・照合・文章生成の実入力へ接続できました。** 人工離散ベースバンド上の実証であり、RF実機や、記憶内部の全演算を時間波形で実行する実装ではありません。

未使用12場面、2チャネルseed、主3条件のSS推定同期は72/72文書照会で意味を保持して生成し、144表現を独立パーサ・再読解で確認しました。事前に固定した数値受入基準9項目はすべて合格です。

ただし非拡散反復対照も72/72です。**接続と同期の必要性は確認しましたが、この実験でSS拡散が反復方式より優れるとは言えません。** また、既知のサンプリング折り返し条件では32フレームの同期誤受理がありました。

## 今回つながった部分

教師用意味信号を、P1単位位相符号による結合、4フレームのSS拡散、チャネル、パイロット同期、逆拡散、位相結合解除、L1部分相関回復に通します。受信した信号から指定2項目の値を取得して、SS記憶を更新しました。

次に、その2項目がともに未観測の別照会を送信します。教師のパケットや回答履歴を渡さず、保存・再読込したSS記憶と照会の復調信号から補完・生成しました。教師として受け入れる操作は外部が明示し、システム自身の推測を教師化しません。

8,192成分のL1信号を4つの2,048成分フレームへ分割します。S1の同期・拡散処理は既存コードをそのまま使用し、L1に適合する部分相関回復を追加しました。旧P1のR1向け役割別干渉除去受信器へ、そのままL1を渡したものではありません。[実装上の境界](SPECIFICATION.md) に区別を記載しています。

## 主比較

各セルは12場面×2チャネルseedの24文書照会です。各試行は教師1信号・指定2項目の学習と、照会1信号を含みます。正しい意味で両方の表現を生成できた文書数を示します。

|方式|無劣化|遅延・位相・周波数差・雑音|ずれ・雑音＋25%チップ観測|
|---|---:|---:|---:|
|直結・チャネルなし|24/24|24/24|24/24|
|SS＋推定同期|24/24|24/24|24/24|
|非拡散反復＋推定同期|24/24|24/24|24/24|
|SS＋同期無効|24/24|0/24|0/24|
|SS＋真値補正・評価専用|24/24|24/24|24/24|

主SSの誤教師更新・誤生成・同期誤受理はすべて0でした。教師と照会を合計した576フレームが同期受理され、監査基準にも一致しました。同期無効の48失敗は意味回復段階の保留で、誤った文章を出した成功扱いにはしていません。

25%チップ観測時、主SS照会のL1成分観測数は5,569～5,580/8,192、平均約68.05%でした。**意味成分の25%しかない状態から回復した結果ではありません。** 不足成分は相関で得た意味仮説から補いますが、観測済み成分はそのまま保持しています。

直結は機能上の基準であり、同じ通信費用の方式ではありません。SSと非拡散反復は同じチップ数、パイロット数、送信エネルギーです。SSの同期あり・なし・真値補正は、それぞれ同じ送受信チップを使ったことをハッシュで監査しました。

## 失敗側と識別限界

固定した4場面で、教師信号と照会信号の両方に各条件を加えました。同期誤受理の分母は各条件32フレームです。

|条件|教師学習 / 4|正しい生成 / 4|同期誤受理 / 32|主な結果|
|---|---:|---:|---:|---|
|10%チップ観測|0|0|0|同期保留|
|パイロット消失|0|0|0|同期保留|
|周波数差3 Hz|0|0|0|受理範囲外として同期保留|
|雑音のみ|0|0|0|同期保留|
|有効パイロット・データなし|0|0|0|同期は成立、意味回復で保留|
|フレーム入替え|0|0|0|一部フレームが同期できず全体保留|
|8,000.1 Hzの折り返し|4|4|32|0.1 Hzとして誤同期。文書意味は同じに回復|

最後の条件は成功率に隠さない識別限界です。このサンプリング方式で同じ離散信号になる周波数を、受信処理だけで区別できるとは主張しません。同期と意味回復が別の成否であることを、パイロットだけの条件と折り返し条件の両方で示しました。

全方式・全条件を合計すると388文書照会中316文書を正しく生成し、72文書を保留しました。776表現要求に対し632表現を生成し、生成文の意味・指定表現・再読解の不一致は0件でした。これには評価専用参照と識別限界条件も含むため、この合計を実運用受信器の成功率にはしません。[全22集計](results/SUMMARY.json) と [独立したログ監査](verification/LOG_AUDIT.json) に分母を残しています。

## 実際の文章

評価先頭の2事象・3事象を、成功を見て選び直さずデモにも使用しました。文章を既存読解器で読んでから教師信号を作り、25%チップ観測を経た受信値で学習し、別プロセスの欠測照会で生成しています。

2事象の出力例：

> 太郎が美咲を褒めなかった。その後、もし美咲が花子を見つめなかったら。

逆順を指定した出力：

> もし美咲が花子を見つめなかったら。その前に、太郎が美咲を褒めなかった。

3事象の出力例：

> 健太が美咲を訪ねなかった。太郎が花子を訪ねた。もし美咲が太郎を褒めたら。

これは限定文法の試験文です。「もし～たら。」のように条件節を単独の出来事として表示する既存仕様も残っており、一般的な自然さや自由文書の完成度を示す例ではありません。[デモと6回の実CLI実行](examples/run/DEMO.json)、[2事象のCLI記録](examples/run/case0/CLI.json)、[3事象のCLI記録](examples/run/case1/CLI.json) を同梱しました。

## 検証・費用

新規40試験に合格。原版側でもL1 v0.6の116試験、S1 v0.2の71試験、P1 v0.2の88試験、計275試験に合格しました。各原版自身の試験であり、入れ子の全世代試験をすべて再実行した意味ではありません。

全388条件を別ディレクトリで最初から再実行し、時間ファイルを除く1,555ファイルが一致しました。さらに保存記憶388件を読み込み、条件・方式・事象数別の代表44条件を教師受信・記憶更新から再実行して一致を確認しました。教師・評価資料を置かない最小環境でも、固定した2事象・3事象の両方が生成できました。

デモの元信号・逆拡散値・マスク・回復信号、計16数値配列も完全再現しました。資料・ZIP展開後の検証範囲は [VALIDATION.md](verification/VALIDATION.md) を参照してください。

1意味信号の送信は33,920チップ、正規化エネルギー229,376、8,000 chip/sで4.24秒です。教師＋照会ではその2倍です。ヘッダーやJSON転送・PC処理時間はこの通信費用に含めていません。

固定ソースのダイジェストは `9ab040223a73743808b22155af41984a17c44e5af142bcd0d5cebf950965270b`。旧3版の1,737ファイルと3つのZIPは変更していません。

## まだ実現していないもの

- RF実機、アナログ回路、分数チップ遅延、サンプル時計ずれ、マルチパス、任意連続ストリームからの同期。
- 送信者・教師の認証、内容の真偽判定。
- SS記憶内部の全演算を時間波形で実行すること。
- 文書全体を長期記憶だけから再生すること。本版で保持するのは指定2項目で、他の文脈は照会信号から受け取ります。
- v0.6の再確認先選択器の波形接続、後続の大量学習下での保持、新語・文法学習、自由長文。

次に接続側を強めるなら、分数チップ遅延と時計ずれを加え、同期失敗時の再取得を評価することが候補です。より広い「ほぼすべてをSS方式で」という目標に対しては、通信の接続とは別に、記憶照合・更新そのものの時間波形実装を段階的に検証する必要があります。
