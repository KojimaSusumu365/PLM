# 開発判断と評価前の固定

初期の分散配置（16,1104,4240,8400）を、開発用book 53101 / channel 62101で確認したところ、旧問題の約1.06 Hzは識別できても8 Hzが約0.356 Hzへ誤同期しました。これを受け、配置の比較へ進みました。

837配置の信号のみの周波数応答を比較し、近距離副ピーク≤0.80を満たす中で広い範囲の最大副ピークが最小の（16,3000,4700,8400）を選びました。全候補と選択規則をPILOT_LAYOUT_SEARCH.jsonに記録しています。コードブック、意味ラベル、評価seedを配置選択へ使っていません。ただし探索範囲や基準は開発判断であり、理論的最適性の主張ではありません。

受入±2 Hz、探索±4 Hz、0.125 Hz粗刻みと3段階の微調整、相関・候補差・ブロック整合性の閾値は最初の実装から維持。P1の閾値も変更していません。

2符号seed×2チャネルseedの開発評価を保存しました。4800比較照会、864同期判定、96状態照会。事前の46受入チェックを全て満たしました。主8条件の新SS回復は各32/32、負例誤受理は各0/64。旧S1の約±1.06 Hzでは4/4試行の同期誤受理と0/32回復を再現し、新SSは同じ条件で同期誤受理0、32/32回復でした。

指定した範囲外周波数・負例は開発で保留できました。一方、8000.1 Hzは0.1 Hzとして受理され、有効パイロットだけの入力でも同期は成立しました。この2つを除去した成功率ではなく、別分類の限界試験として全て残しています。

未知評価は8符号seed（54101〜54108）×4チャネルseed（63101〜63104）で、現時点では未実行です。方式・閾値・受入・ソース・文書・開発結果を先に固定し、開始記録と初回結果を保存します。未達ならそのまま報告し、未知結果に合わせて選び直しません。
