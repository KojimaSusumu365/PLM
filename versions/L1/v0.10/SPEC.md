# v0.10 技術仕様と実験上の境界

## 1. SSの役割と通常処理の境界

| 部分 | SS型の処理 | 通常処理・設計として残るもの |
|---|---|---|
| 特徴候補の評価 | 位相結合・重畳・逆結合・相関による予測 | 特徴項目、部分集合列挙、観測の集計、ラベル付き検証損失 |
| 複数候補の保持 | 候補別の独立した位相連想記憶 | 候補ID、候補数の上限、メタデータ・ファイル配置 |
| 受理 | 各候補の位相照会と意味信号回復 | 全候補の一致比較、上限超過の拒否、経験的な閾値調整 |
| 文書生成 | 数値意味信号からの回復、学習済み位相記憶の照会 | 文書分割、ID・意味構造、語句連結、生成ゴール、停止 |

候補を一つの複素信号へ重ねて取り出す実装ではない。候補間干渉を避けるため、今回は記憶を物理的に分離する。SS型記憶を複数使うことで不確実性を保持するが、候補管理自体を全てSS演算にしたとはしない。

## 2. 候補選択

入力は学習用と選択検証用の `(context, label)`。同一の1〜6特徴、各集合最大256一意文脈、最大20,000観測。完全な文脈・ラベルの組で重複を除く。ラベル候補は学習用からだけ作る。検証ラベルは採否へ使うが重みへ足さない。

全ての空でない特徴部分集合を候補とし、投影キー `u` とラベル `y` について条件付き平均値符号を構築する。

```text
mu_u = sum_y P(y | u) * v_y
H = sum_u conjugate(k_u) * mu_u
score(q, y) = Re[ conjugate(v_y) dot (k_q * H) ] / D
```

候補クラスの最大相関0.65以上、非負に切り上げた次点との差0.25以上なら予測を受理する。SS選択時のHは単一のD次元記憶。運用時はv0.9から継承したバンク分割・対証拠を持つ記憶へコンパイルするため、選択時と運用時の回復条件は完全には同じでない。最終照会の誤答・保留も別に測る。

訓練内の完全回復だけを要求するv0.9の条件を変更した。損失は `(誤答数 + 0.5 × 保留数) / 要求数`。

1. 訓練損失0.25以下、訓練回答率0.5以上の候補を残す。
2. その中の最良訓練損失との差が0.125以内の候補を残す。
3. その中の選択検証損失が最良と同率、かつ0.25以下の候補を残す。
4. 残った中で特徴数が最少の候補を、検証損失・訓練損失・キー数・正規化マスク順で並べる。
5. 最大4つを保持する。5つ以上あれば `overflow` とし、保持した4候補が一致しても確定しない。

候補なしの場合、完全キーの記憶を診断用に構築するが `supported=false` とし、確定しない。ラベルが1種類しかない正例だけの記憶は完全キーのままとし、未知キー一般の支持とは解釈しない。

ここでの「もっともらしい候補」は、この損失・複雑さ・設計済み特徴の範囲での定義であり、考えられる全ての文法仮説ではない。候補選択も教師ありである。

開発段階では選択検証損失に0.0625の許容幅を試したが、追加例を与えた後も弱い小マスクを残す事例があった。そのため本評価前に幅を0へ変更した。開発用の同率候補は保持できる。本評価結果に合わせた変更ではない。設定は `policy.py`、経緯は固定プロトコルに記録した。

## 3. スカラー照会とリスク調整

`MemoryCommittee` は各候補からラベルを照会する。全候補が受理し、全ラベルが一致し、候補群が支持されている場合だけ確定の候補とする。1候補でも未回復・不一致なら保留する。多数決で少数意見を消さない。

一致時の信頼度指標は、各位相照会における「最大相関−0.65」「候補差−0.25」「対証拠相関−0.65」の全候補・全ブロックでの最小値。非負に切り上げて8桁に丸める。**確率ではない。**

別のリスク調整用データで、この指標の閾値を選ぶ。経験的な受理誤答率が0.1以下となる閾値のうち回答数が最多のものを使い、正の回答数で条件を満たす閾値がなければ全保留とする。この場合の誤答率は0ではなく未定義と記録する。

この経験的閾値には統計的なリスク保証を付けない。調整データで誤答0でも、関係が変わる評価データでは誤答し得る。スカラー課題のこの調整器を、文章生成の正解確率保証へ流用しない。文章の標準経路は完全候補の一致と支持・上限検査を用いる。

参考となる評価観点は回答率と受理誤答率の組合せである：[Geifman & El-Yaniv, Selective Classification for Deep Neural Networks, 2017](https://arxiv.org/abs/1705.08500)。同論文のニューラル方式や理論保証をPLMに実装したという意味ではない。

## 4. 文章モデルの候補構成

一事象の8種類の記憶について、それぞれ特徴候補を選ぶ。その候補マスクの直積が文章処理の候補群になる。直積の総数が4以下なら全て構築する。4より多い場合は、混合基数で表した候補番号から間隔を空けて4つを診断用に構築するが、**未確認の組合せがあるため確定を禁止する**。実体化しない候補の有無をメタデータに残す。

各候補は独立した一事象モデルと時間モデルを持ち、候補IDと厳密指紋で識別する。時間の読み書きは従来の六つずつの完全関係キーのまま。新たに時間特徴を発見したわけではない。

読解では各候補が文章全体を読み、意味信号を復元する。全てが読めて、**全事象の全スロット・時間辺・提示順を含む意味全体が一致**した場合だけ新しい数値パケットを発行する。候補ごとに異なる主語・否定・時間などを抜き出して合成しない。

生成では、渡された数値パケットから意味を回復し、各候補で完全な文書を生成する。全ての生成が成功し、全文が一致し、候補群の支持・上限条件を満たす場合だけ確定する。言い換えとして意味が同じでも文字列が違えば、この最小実装では保留する。

不一致時の `candidate_audit` には個別の候補文が出る場合があるが、トップレベルの `text` はnull。診断情報を確定出力と混同しない。

## 5. 信号と更新の契約

パケットは `schema / model_fingerprint / dimension / real / imag / eligible_for_inference` のみ。数値配列に原文、候補文、正解一覧を同梱しない。読解経路では候補が一致して確定した意味だけを符号化し、未確定な意味を混合しない。別の `encode` 経路では外部から明示した意味を符号化できるが、それは学習モデルによる正しさの確認ではない。`recover` の数値復元成功も同様で、学習した文章を生成できるかはその後の全候補の検査で決まる。

各候補で意味コーデックの次元・seed・モード・候補在庫が一致することをモデル構築時に検査する。外側のv0.10パケット指紋は全候補の指紋と方針を結び付ける。内部のv0.9由来コーデックのスキーマと外側のv0.10スキーマは区別する。

追加例は教師付きのオフライン再学習へ渡す。既存モデルを変更せず新しいモデルを保存し、指紋も更新する。古いパケットは新モデルに流用できない。自動で例を探す機能、オンライン学習、概念更新はない。

## 6. 評価設計

新しい6二値特徴の5課題族×2置換に対して、学習8/16/24、候補選択用検証16、リスク調整8、最終評価16を用いる。完全な文脈の4集合は互いに重ならない。ノイズは訓練ラベルだけに0または約12.5%の反転を加え、検証・調整の教師は正しい設定である。この追加の教師情報を学習費用として数える。

標準は24学習・無反転を512/2048次元・二符号で測る。それ以外は2048次元・第一符号。SS複数候補、同条件の記号的複数候補、同じ選択検証を使うSS単一候補、v0.9訓練内完全回復の単一候補、学習＋選択検証データをまとめてv0.9へ与える対照を比較する。記号的方式も運用時は同じSS記憶コンパイラを使う。

別の4つの曖昧性課題では、二特徴が等しい例だけを学習8・選択検証4・リスク調整4で与え、異なる値になる8例で評価する。追加の8訓練例は候補を区別するため実験者が用意し、評価例とは重ならない。候補選びの自律性ではなく、追加教師で絞れることの試験である。

同じ回答率の比較では、同数の受理済み回答を、正解を見ない固定ハッシュ順で選び直す補助分析を行う。同じ入力集合ではなく同じ回答数の比較である。共通の正の回答数がなければ比較不能とし、全保留の勝利とは扱わない。本評価の正解ラベルで運用閾値を最適化しない。

文章では旧制御文法を再利用する。標準432学習対・192選択検証対・216時間対を使用し、864読解要求、432直接生成要求、864提示順反転往復を測る。864は816一意表面文、216意味記述を含む反復である。対照方式はカテゴリ・時間・提示順の54代表例で同じ比較をする。

文章の曖昧性試験は、一事象・選択検証・時間教師の**全て**から、肯否と仮定が分離する例を除く。否定なし・断定、または否定・仮定だけを残す。追加する2例は「太郎が花子を助けなかった。」「もし太郎が花子を助けたら。」と対応意味。選択検証や最終評価の例を訓練へ移動しない。9カテゴリ×2事象位置×2交差状態の36直接生成要求を前後で測る。

## 7. 費用・再現性・未実施

独立候補の数に応じて位相ブロック、照会キャッシュ、意味コーデック配列が増える。係数Dを候補ごとに維持する実験と、総係数数を維持して候補数で分ける実験を区別する。後者もヘッダや全プロセスRAMを一致させるものではない。端数は128単位で切り下げ、使用した実際の係数数を記録する。

環境依存の所有heapと時間はモデル指紋から除外する。厳密な配布完全性、係数許容差、離散的機能の一致を別々に検査する。主評価のコード・データ・条件を凍結後、2回実行して結果とモデルを比較する。後からの集計・補助ベンチマークは凍結実験の変更や閾値調整に使わない。

Linux実機、自然言語一般、特徴そのものの自律発見、三事象以上、記憶負荷の偏り改善、P1数値部分観測/S1チップ・同期接続、R1推論・Concept更新は今回未実施。既存の同一人物の主客は実行時の読解・生成で対応するが、同一人物例からの対学習は一意整列の限界で拒否する範囲を維持する。
