# v0.9 技術仕様

## 1. 変更対象

v0.8の「文章→部品意味→二事象・時間の位相信号→文書生成」のうち、一事象部品の**依存特徴の選択**を置き換える。標準は `ss`。時間の読取・生成は従来通り六つずつの完全関係キーを学ぶ。時間層自体に新しい特徴選択を適用したとはしない。

| 処理 | v0.9の実装 | SS以外に残るもの |
|---|---|---|
| 表面文の分解 | 内容語・マーカー・順序・隣接情報 | 明示語彙、分割規約、特徴項目の手設計 |
| 特徴選択 | 候補ごとに位相連想記憶を作り、相関・余裕・正回復率で採否判定 | 候補列挙、集計、正解ラベルとの比較、複雑さによる優先順位 |
| 選択後の記憶 | 部分キーと値の結合、重畳、バンク、対証拠信号 | 固定バンク配置、ハッシュルーティング、容量規約 |
| 意味保持 | ID付き事象・時間辺・提示順を一つの複素信号へ結合 | スロット、ID規約、意味グラフ、結合方法の手設計 |
| 生成 | 意味信号を復元し、学習済み順序・マーカー・語彙を照会 | 出力ゴール、停止条件、連結、受理契約 |

## 2. 選択器の入力と候補

入力は `(context, label)` のリストのみ。最大20,000観測、全観測で同一の1〜6特徴、ラベルは文字列。教師が与える依存マスク、推論手順、評価正解、旧重みは入力しない。初期語彙と対になった意味ラベルは与える。

完全な文脈とラベルの組で重複を除く。同じ完全文脈の異なるラベルは残し、曖昧性として測る。全ての空でない特徴部分集合を列挙する。最大6特徴なら63候補。空マスクを許さず、候補ラベルが一つしかない正例のみの記憶は完全キーを維持する。

選択器は**記憶ごとに一つの大域マスク**を選ぶ。ID3の条件付き・局所的な複数マスクとは表現クラスが異なる。同じマスクを得ることを合格条件にしない。

## 3. SSで行う採否判定

候補マスクに投影したキーを `u`、その位相符号を `k_u`、候補ラベル符号を `v_y` とする。各要素の振幅は1。SHAKE256で生成した位相を用い、意味的な埋め込み自体は学習しない。

同じ投影キーへ複数の観測が入る場合、重複除去後の完全文脈数に基づく条件付き平均値符号 `mu_u` を作る。

```text
mu_u = sum_y P(y | u) * v_y
H = sum_u conjugate(k_u) * mu_u
s(u, y) = Re[ conjugate(v_y) dot (k_u * H) ] / D
```

キーは特徴名集合の符号と、各特徴名・値の構造符号の要素積。照会時に同じキーを掛けて逆結合し、各候補値との相関を取る。

候補ラベルの最大相関が0.65以上、非負に切り上げた次点との差が0.25以上で受理する。全ての一意な訓練文脈・ラベルを正しく回復できた候補だけを採用可能とする。これは訓練内の経験的成績であり、外部一般化を保証する条件ではない。

採用可能な中から、特徴数、投影後のキー数、マスクの正規化文字列の順で小さいものを選ぶ。この順序付けは通常処理で、SS相関値を最大化する最適化ではない。採用可能なマスクがない場合は全特徴へ戻る。ID3や記号的純度への隠れた切替は行わない。

SS判定の寄与を確かめる対照は `H=0`。後段の記憶学習は止めず、選択段階だけを無効化する。全候補が不受理となり、完全キーへ戻ることを検査する。

## 4. 比較方式

- `ss`：上記の位相構築・相関による採否判定。
- `symbolic`：同じマスク候補・グループ・条件付き平均・閾値・複雑さ順序。相関の代わりに正確な条件付きラベル頻度を得点とする。SS固有性を判断する主要対照。
- `id3`：旧版の情報利得による局所的な依存葉。XORなどでの貪欲探索の弱さとSSの効果を混同しない。
- `full`：特徴選択なし。完全キーだけを記憶する。

全方式で、選択後は同じ位相記憶コンパイラを使用する。さらに通常の対応照会で選択されたキーを評価する。これにより「特徴の選択を誤った」のか「正しい選択を位相記憶から回復できなかった」のかを区別する。

同じDは**マスクブロックごとの係数予算**であり、ID3のように複数マスクを持つ方式と全体RAMが同じとはしない。SSとmatched symbolicの大域マスクは同じ下流構成で比較できる。ファイル化した対応表のバイト数は辞書プロセスの全RAMではない。

## 5. 後段コンパイルの変更

選択器が返す投影行を `selected_leaves` として渡せるようにした。投影キーが同じ行の値符号と対証拠符号は条件付き平均にする。反復入力による同一キーの振幅増加を防ぐ。異なるラベルが衝突する場合も、正解を一つに決め打ちせず混合状態を格納する。

運用時のブロックはパディング済みヘッダと複素係数のbytes。完全な投影キー一覧や正解対応辞書を運用時重みに併設しない。候補ラベル、特徴名、初期語彙、件数、構造規約はメタデータに残る。固定サイズの照会キャッシュは許すが学習済み対応表とは区別し、所有容量を報告する。

## 6. 評価分割

旧言語課題は旧版の制御文法・語彙を再利用する。432学習対と6対の手選び圧縮例を比較する。単文の評価は192入力文、96意味、192種類の意味・生成ゴール。384生成要求には同一意味からの反復が含まれる。

二事象評価は864要求、816種類の表面文。局所IDの再割当てを評価側で明示的に対応づけ、全事象スロット、時間辺、提示順、文内ゴールを採点する。今回のv0.9回帰は一つの標準時間符号・8192次元であり、v0.8の四符号・全低次元診断の再実施とは区別する。

新しい依存課題は、単一特徴、2入力XOR、2入力AND、3入力の条件分岐、3入力パリティの5族。各族2種類の特徴名・ラベル置換を作る。5つの二値特徴のうち最大3つを関係特徴、残りを非関係特徴とする。学習器にはこの区分を渡さない。

3つの関係候補値の各組合せについて、4つの非関係値組合せを無作為順に並べ、先頭1/2/3個を学習、末尾1個を評価する。訓練は8/16/24件、評価は8件。非関係特徴の一部だけを隠す分割であり、世界一般の因果同定課題ではない。少標本では偶然の相関による別マスクを選び得る。

標準24件・無反転条件は3次元×2符号×4方式。その他の学習数・ラベル反転条件は2048次元・第一符号・4方式。標準SSのゼロH対照も記録する。標準以外や低次元の完全正答は合格条件にせず、誤答と保留を隠さない。

新しい合成課題も自作の人工課題であり、独立した人による自然言語評価ではない。開発用と本評価用は別乱数指定を用いるが、同じ課題族と32点の小さい定義域を共有する。分布外一般化の証明ではない。

## 7. 受理と再現性

文章側の部品整合検査は、学習済みのマーカー生成と入力が一致するかを調べる。意味信号側の検査は、自分で組み立てた候補が数値信号から復元できるかを調べる。後者だけでは自己整合的な誤読を排除できない。独立実装の評価文法で別に採点する。

`thresholds.py` が現行版の閾値の単一ソース。モデルには使用した閾値を記録し、不一致のモデルを拒否する。旧版同梱ZIP内の定数は歴史資料として変更しない。

モデルの指紋はメタデータと重みbytesの厳密ハッシュのまま。`sys.getsizeof` と実行時間を指紋から取り除き、性能報告へ分離した。機能互換性はメタデータ・ヘッダ一致、係数許容差、離散的な機能結果の一致の積で判定する。係数が許容差内でも受理/保留や出力が変われば不合格。保存物の破損を機能許容差で見逃さない。

1 ULPの重み変更、大きな変更、係数許容差内での判定変更をテストする。これは機能比較器の制御試験であり、Linux実行や全入力上の等価性証明ではない。
