# v0.5：受理契約と測定仕様

## 数値本体は同一

algebra.py、projection.py、features.py、lexicon.pyはv0.4からバイト同一で継承する。各foldで同じ432対、初期語彙、seed、次元から再学習し、各マスク・候補・位相重み配列がv0.4と完全一致することを評価前提にする。
特徴付き部分キー、候補符号、役割結合はv0.4の仕様を維持する。相関の最低値0.65、次点または0からの余裕0.25、意味信号の相対再構成残差0.20以下は変更しない。
詳細な部品学習と数式はvendor/PLM-L1-v0.4/NUMERICAL_SPEC.mdを参照。

## 追加した不変条件

読解で得た内部候補をm、encode(m)をpとする。
readが成功するには、recover(p).status=recovered、かつrecover(p).meaning=mが必要。
復元不能ではmeaning_signal_unrecoverable、不一致ではmeaning_signal_mismatchとしてpacket=Noneで保留する。再試行・閾値緩和・次元の自動変更・正解値への差替えは行わない。
モデルメタデータにread_acceptance=recover_equals_candidate_v1を要求し、schemaとfingerprintで旧契約を区別する。
この検査は内部候補に対する信号整合であり、入力文の正しい意味を外部から保証するものではない。主客を反転した教師対で学習したモデルが、内部整合した誤読を受理し得ることも対照テストに含める。

受理後に信号が変わることは別の事象。生成側は毎回数値信号を再検査する。検証フラグをパケットへ追加して検査を省略する方法は認めない。
モデル識別子は暗号的出典認証ではない。別の有効な意味パケットを渡すと、その意味が復元される。

## 学習と採点の境界

学習APIはtext/meaningと初期語彙のみ。対象セル、fold番号、評価正解、正解操作列は入力しない。
読解単体・生成単体・往復を別実装の限定文法で採点する。生成単体では定義上正解意味から信号を作るが、往復ではreadが実際に出したパケット以外を渡さない。
誤受理を(1)読解受理後の復元不能、(2)復元できるが評価正解と違う意味、に分ける。誤った完成文と保留も区別する。
標準の比較では新旧の正解数維持に加え、受理した新版の信号/完成文が旧版の出力の部分集合であることを確認する。

## 数値雑音

元信号xに対し、固定seedから生成した複素ガウス方向zを z'=z*r*||x||/||z|| とし、x+z'を入力する。rは0,0.05,0.15,0.30,0.60。
PCG64初期化値はseedと評価入力識別子のSHA-256から得る。新旧と各rで同じ方向を使い、評価器だけが加える。モデルはrも正解意味も受け取らない。
これは有限次元数値信号のノルム制御摂動であり、通信路の帯域・電力スペクトル・同期・欠測成分を再現するモデルではない。
全192入力に対する読解数と、転送されたパケット数、受信回復、2語順の生成を別々に集計する。読解で保留した例を分母から隠さない。

## 記憶負荷

同じProjectionMemoryで、address=known:i→label:i mod8の8/32/128/256対応を格納する。partial=Falseで全アドレスを区別し、未格納missing:iを64件照会する。
候補数8は固定、数値重みは1本。単純なキー→値の通常辞書も同じ対応で実際に照会する。総バイト数・速度・省電力の公平比較ではない。
これは言語処理から切り出した記憶試験で、語彙や文法を拡張して測ったものではない。高負荷での誤回復・未格納誤受理があっても隠さず記録する。
256を超える対応を拒否する既存の上限は変えない。読み取りの自己整合ゲートはこの記憶部品を改良していない。

## 固定と受入

evaluation/PROTOCOL.jsonの条件・seed・範囲を固定後に評価する。標準16対比較×16条件=256、既知回帰2、次元契約16、全学習回帰1、雑音ゼロ契約6、辞書対照1、非学習対照1の計283条件。
標準正解率98%以上と旧版正解数維持は、単に保留を増やして合格することを防ぐ条件。ストレス下での意味精度・未格納誤受理のゼロを事後に要求/緩和せず、全結果を残す。
意味処理の範囲拡張、P1/S1接続、容量適応、全SS学習、R1推論は次段階であり、本版で実装済みとはしない。

# PLM-L1 v0.5：読解受理と意味信号の整合・干渉耐性の検証

v0.4の部品再利用型の読解・生成を維持し、読解が成功を返す条件に『出力する数値意味信号を復元でき、読解時に選んだ意味と一致すること』を加えます。

## 変更したこと

1. 文・意味対から学習した部品で、文章の意味候補を選ぶ（v0.4と同じ）。
2. 候補を5スロットの位相意味信号へ変換する（v0.4と同じ）。
3. その信号を復元し、候補との完全一致を確認する（v0.5で追加）。
4. 復元不能はmeaning_signal_unrecoverable、不一致はmeaning_signal_mismatchとして保留し、パケットを出さない。

正解意味を読解器へ与えません。自身の誤った意味候補を一貫して符号化できてしまう可能性はあるため、この確認だけで意味の正しさを証明したとは扱いません。別実装の限定文法による独立採点を続けます。
数値符号・学習された重み・特徴選択・相関閾値・残差閾値・生成方式は据え置きます。新旧は同じ432対・seed・次元で再学習し、数値重みが完全一致することを確認します。

## 起動方法

## 信号契約

読解成功の外側の応答にsignal_verified=trueと検証方法を付けますが、この情報を数値パケットに埋め込みません。受信側のgenerateは毎回recoverで検査し、以前の読解成功を根拠に検査を省略しません。
パケットはschema/model_fingerprint/dimension/real/imag/eligible_for_inferenceのみ。原文・意味ラベル・trace・検証済みフラグ等の追加は拒否します。
モデルschemaはplm-l1-checked-v1、パケットschemaはplm-l1-checked-meaning-v1。v0.4のモデル/パケットを暗黙に新版として読み込まず、同じ数値符号でも版を区別します。
fingerprintは整合性識別で、認証ではありません。別の有効な意味信号への置換を検知する機能はありません。

encodeコマンドは意味から数値信号を構成するだけです。低次元でその信号を復元可能だと保証するものではなく、readの受理契約とは区別します。

```powershell
python -B -m plm_l1_v05 encode --model results/model --meaning examples/MEANING.json --out work/direct.json
python -B -m plm_l1_v05 generate --model results/model --packet work/direct.json --goal object
```

## 試験を分ける理由

| 試験 | 変えるもの | 測るもの |
|---|---|---|
| 標準の新旧比較 | 受理ゲートのみ | 未学習組合せの読解・生成・往復の正解維持 |
| 言語モデルの低次元試験 | 次元・符号seed | 復元不能の受理、整合した誤読、保留 |
| 意味信号の雑音試験 | 読解後の数値信号に加える相対L2雑音 | 復元と生成の正解/誤受理/保留、入力全体での生成率 |
| 連想記憶の負荷試験 | 8候補のまま格納対応数を8〜256へ | 格納アドレスの回復と未格納アドレスの誤受理 |

負荷試験は独立した記憶部品の実験で、言語モデルの語彙や意味スロットを拡大する実装ではありません。
雑音は複素ガウス方向をノルム調整した数値摂動で、S1のチップ列や同期・RF環境のモデルではありません。
雑音後の成功率は転送できたパケットに条件付けた率と、読解保留も含む元の全要求に対する率を分けます。

標準条件では全6区分の正解率98%以上・v0.4の正解数維持・誤受理なしを要求します。全保留を合格としません。
低次元の既知2例は既知不具合の回帰で、未知評価とはしません。高負荷や雑音下での意味誤り・未格納誤受理は非合否の測定として残し、結果を見て閾値を変えません。
元コーパス576/192/192と4分割は既存v0.4からの再利用です。各foldの未学習組合せ48要求×4fold×4符号は、768種類の新規自然文を意味しません。
