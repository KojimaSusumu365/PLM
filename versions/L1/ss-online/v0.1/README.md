# SS型の逐次誤差訂正学習と忘却の検証 v0.1

PLM-L1の独立試験版。既存v0.13および重み付け試験版を変更せず、教師の回答一件ごとにSS記憶を更新する。既存言語コアの正式置換ではない。

## 実装した学習

各完全文脈を、項目／値の単位複素位相符号の積bで表す。クラス別記憶Hの相関は `s_y = Re[conj(H_y) dot b] / D`。

```text
target_y = 教師ラベルと一致すれば1、それ以外は0
H_y ← H_y + 0.5 × (target_y − s_y) × b
```

これを外部教師の回答後だけに行う。以前の全教師から行列を組み立て直す方式ではなく、その時点のHと現在の教師を使う逐次更新である。勾配更新の係数・クラス在庫・符号語彙は設計値であり、脳の学習機構やSTDPを実装したものではない。

比較方法：

- `accumulate`：教師の提示ごとに正解クラスへbをそのまま加える。重複提示も加算する単純対照。
- `delta`：上記の誤差訂正を一回。
- `delta5`：現在の同じ教師で五回。再提示方式と数値更新回数を比較する対照。
- `replay32`：現在の教師で一回、過去の教師例で四回。過去例は最大32観測の通常のreservoirバッファに保持する。空バッファ時は再提示なし。
- `exact`：同じ教師のキーとラベルを正確な対応表へ保存し、同じキーへの新しい教師で上書きする対照。

`replay32`のバッファはSS信号ではなく、教師付き文脈の通常データである。再提示に外部教師をもう一度呼ぶことはないが、過去教師の保存領域と追加計算は必要になる。32種類の異なるキーを保証するバッファでもない。新しい教師が届いたキーについてのみ、バッファ内の同じキーのラベルも訂正する。まだ新情報が届かないキーのラベルは、自動で真相に合わせて変更しない。

## 暫定回答と受理回答

`tentative`は最大相関のラベル。ただし一位と二位の差が1e-12以下なら未定。`accepted`は相関0.5以上のクラスが一つだけの場合の回答で、複数ヒットやヒットなしは保留する。相関・余裕は正解確率ではない。

暫定回答も受理回答も、教師入力へ自動接続しない。教師応答は専用の要求ID・状態指紋・sourceを持つ別のオブジェクトで受け取る。古い要求、改変要求、`model_prediction`をsourceとする応答、在庫外ラベルは拒否する。

`external_teacher`というsourceはAPI上の宣言であり、本物の人間・正しい教師であることの認証ではない。誤教師も入り得ることを試験する。全出力は `eligible_for_inference=false` を維持する。

## 試験設計

4項目・各8値、既知4ラベルの人工キーを使う。A/B/C各64キーを順番に四周ずつ教える。Aを一周再訪し、その後Aの16キーの正解を変更して、変更されたキーを四周教える。総896回の外部教師提示、192種類のキー。別の128キーは一度も教えない。

cleanと、Aの最初の一周だけ8回答を誤らせるnoisy_firstを比較する。正解変更後の適応は、正解が変わっていない記憶の忘却と区別する。全方式へ同じ教師順・同じ回答を与える。試験に使う本当のラベルは評価器だけが保持し、学習器にはその時点の教師ラベルだけを渡す。

SSはD64／128／512×二符号×三データseed×四方式×二シナリオ＝144取得過程。exactは三データ×二シナリオの6過程。合計150過程を二回実行する。教師提示前の回答、応答直後の変化、一周後の回復、B/C学習後のAの劣化、再訪、正解変更への適応を記録する。

独立のルール・自然文への汎化ではなく、教えたキーの記憶・再生・更新試験である。反復提示数やプローブ数を、独立した多数の課題数とはしない。忘却率はA学習終了時に正しく受理できた集合からの脱落で、初めから答えられないキーは分母に加えない。

## 実行

検証環境はWindows 11、Python 3.12.14、NumPy 2.3.5。配布フォルダに移動し、出力は未使用の別フォルダを指定する。

```powershell
python -m pip install -r requirements.txt
$env:OPENBLAS_NUM_THREADS='1'
$env:PYTHONIOENCODING='utf-8'
python -B -m unittest discover -s tests -v
python -B verify_release.py --out ../online-check
python -B evaluate.py --out ../online-rerun
```

## 一件ずつ学習するCLI

新しい学習器を作る。

```powershell
python -B -m ss_online start --method delta --dimension 128 --out ../learner0
```

`input.json`は、`{"f0":"0","f1":"1","f2":"2","f3":"3"}`のような一つの完全文脈。各値は文字列0〜7である。暫定回答を表示し、要求を別ファイルに保存する。

```powershell
python -B -m ss_online question --learner ../learner0 --input input.json --out ../request.json
```

教師は、要求のrequest_idを対応付け、既知ラベル0〜3から答えを返す。以下は形式例であり、正解を自動生成する規則ではない。

```json
{"schema":"plm-ss-online-feedback-01","request_id":"要求ファイルのrequest_id","source":"external_teacher","label":"0"}
```

```powershell
python -B -m ss_online teach --learner ../learner0 --request ../request.json --feedback feedback.json --out ../learner1
```

元のlearner0を上書きせず、更新したlearner1へ保存する。次の要求はlearner1から作る。受け取ったラベルが誤りなら、その誤りも学習し得る。

予測だけには、学習器全体ではなく `model/` を使う。query入力は文脈の配列。保留を含むqueryや不正なteachは終了コード2。

```powershell
python -B -m ss_online query --model ../learner1/model --input queries.json
```

配布済みの `results/delta-A`、`delta5-A`、`replay32-A` はA学習後。同名の `-C` はC学習後、`-drift` は正解変更への学習後である。`examples/`には保存済みdelta-Aに対する一件更新の要求と、人工教師の回答例を分離して同梱する。

## 記録と限界

`results/EVALUATION.json`に各教師提示前後の暫定／受理結果、教師ラベル、評価専用の真のラベル、反復誤り、一周ごとの指標を保存する。これは評価用証跡で、予測器へ渡すファイルではない。全プローブの生相関は `SCORES.npz`。結果の詳細は `REPORT.md`。

SS予測モデルに全教師表や再提示バッファを保存しない。バッファと履歴指紋は学習器側の `learner.json` に分離する。履歴指紋は監査用であり、そこから過去の教師を再生できる記憶ではない。

本試験は人間の脳の完全なモデルではなく、全SS制御・SSバッファ化・STDP・未知語彙獲得・自然文・v0.13依存候補との結合・P1/S1接続を実現したものでもない。誤りを許容する試験と、結果を事実として外部へ確定することを区別する。正の重み付け前版を自動的に置換しない。
