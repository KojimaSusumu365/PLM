# PLM-L1-SS-core v0.1 実施報告

## 結論

時間順に到着するSS記憶波形の照合、外部教師との差による列ごとの誤差更新、保存・再読込後の意味保持生成を実装した。**逐次コアの最小実証は成立したが、外部P1/S1接続を含む当初の全受信成功基準は未達**である。

主評価の逐次3条件では、12場面×3記憶seed×3条件=108照会の全てで意味を保持し、216個の正しい出力文書を生成した。一括基準方式も36/36照会で成功し、文章は一致した。したがって、時間順演算への移行を確認した結果であって、精度優位を示した結果ではない。

後続教師12件のうち1件を既存S1同期判定が保留したため、実際の学習は各方式で焦点12＋後続11=23文書。失敗文書を除外・再抽選せず、全方式で更新を保留した。このため `results/DECISION.json` は **passed=false** を保持する。ファイル検証や再現検証の `passed=true` と、実験基準の全合格を混同しない。

## 1. 何を実装したか

- 16パイロット＋736データ＋16パイロットの読出し窓を、4チャネルのI/Qサンプルとして逐次積算。
- 尾の検査終了までは結果を暫定扱いとし、欠測・順序異常・同期不良で確定しない。
- 正常な全観測から外部教師との差を求め、次の736tickの書込み窓で係数案を作成。
- 書込みack欠落や状態更新競合で案を破棄。2項目の途中で失敗しても元の係数・登録・版を保持。
- 読取り専用アダプターで既存の意味補完・SS短文書生成へ接続。教師履歴のない新規Sessionで動作。

既存L1言語モデル、P1/S1同期器、記憶次元、候補基底、受理しきい値は変更していない。仕様・数式・コストは `SPECIFICATION.md`。

## 2. 数値一致と主評価

反復する8キーに異なる教師を与える24更新×3seed=72更新で、一括方式との一致を検査した。同じキーへの訂正を含むため、新しい空キーへ追記するだけの試験ではない。

|---|---:|
| 更新前の照合スコア：一括 vs 逐次 | 6.661338147750939e-16 |
| 72更新の係数：一括 vs 逐次 | 5.458188813492739e-15 |
| 文書学習後の全係数：一括 vs 逐次3条件 | 1.1374233532693354e-14 |
| 事前許容差 | 1e-10 |
| 逐次チャンク1 vs 37 | 全seedで記憶フィンガープリント一致 |
| 登録集合・更新回数 | 数値比較の全更新で一致 |

一定の内部位相差も頭パイロットから補正した。位相補正ありと無しでは微小な浮動小数点差が残るため、その間のビット一致は主張しない。

| 主評価方式 | 正しい文書照会／要求 | 実際の正しい出力文書 | 誤生成／保留 |
|---|---:|---:|---:|
| 旧一括方式 | 36/36 | 72 | 0/0 |
| 逐次・チャンク1 | 36/36 | 72 | 0/0 |
| 逐次・チャンク37 | 36/36 | 72 | 0/0 |
| 逐次・一定位相差あり | 36/36 | 72 | 0/0 |

各36は12場面×3記憶seedである。4方式は同一教師・同一受信信号を共有し、独立した144場面を試したわけではない。対象意味、非対象意味、時間関係、順序・焦点を独立した限定文法パーサーとモデル再読で検査した。

## 3. 故障時の生成と更新

| 内部読出し条件 | 正しい照会 | 保留 | 誤生成 |
|---|---:|---:|---:|
| データ25%欠測（75%観測） | 12/12 | 0 | 0 |
| データ50%欠測 | 0/12 | 12 | 0 |
| 尾までに0.5rad位相変動 | 0/12 | 12 | 0 |
| パイロット欠測 | 0/12 | 12 | 0 |
| 尾を8tick切断 | 0/12 | 12 | 0 |
| データtick順序乱れ | 0/12 | 12 | 0 |
| 本文のみ強雑音・パイロット正常 | 5/12 | 7 | 0 |
| 学習係数をゼロ化、版情報は維持 | 0/12 | 12 | 0 |

各条件は4場面×3seed。25%欠測は周期的な内部消失であり、外部通信の「25%観測」とは異なる。外部は25%を残し、内部のこの条件は75%を残している。

主評価・故障・係数ゼロを合わせた全240照会では、161照会が正しく生成、79照会が保留、誤生成0。出力要求480件に対して実生成322件。有限の試験で0件だったのであり、誤生成確率0の保証ではない。

更新試験では、25%/50%欠測・位相変動・パイロット欠測・切断・順序乱れ・書込み中断の7条件×3seed=21/21で、更新を保留して返却記憶を完全に維持した。

一方、**パイロット正常・本文のみ強雑音の更新は3/3で学習処理を通過した**。この条件の更新後生成の正しさまでは評価していない。これは重要な未解決点であり、「同期検査で全ての誤更新を防ぐ」とは結論しない。また、誤った値を含む形式上正しい教師を学習できてしまうこと、後から正しい教師で訂正できることを別テストで確認した。

全12組の記憶（4方式×3seed）でそれぞれ教師24件を試み、23件を学習、1件を保留。各保存記憶はroot23、確認済み対象46、main更新46、protected更新24で一致した。誤った受信意味を学習した事例はなかった。

初回本評価とその反復は、評価側が全件成功をassertしていたため、この同じ箇所で停止した。初回の凍結ソースを保存し、保留を記録して先へ進む評価処理だけを修正した。符号・しきい値・場面・乱数・実験の合格基準は変更していない。修正履歴と前後ハッシュは `verification/AMENDMENT.json`、`AMENDMENT_DIFF.json`、`initial_harness/` に収録した。

## 5. 実際に生成できた文章

教師は次の2事象である。

> 花子が次郎を褒めなかった。その後、由紀が花子を見つめなかった。

照会では「2事象の時間関係」と「第2事象の主体」を未観測にした。保存したSS係数を読み、次を生成した。

> 花子が次郎を褒めなかった。その後、由紀が花子を見つめなかった。

逆順・先頭対象焦点を要求した実際の生成結果：

> 花子を由紀が見つめなかった。その前に、花子が次郎を褒めなかった。

「由紀」と「先後関係」を教師ファイルからコピーするのではなく、新規Sessionで保存記憶から補完した。語順を反転すると「その後」が「その前に」へ変わり、否定・行為・対象は維持された。

別の例では第1事象の主体と第2事象の対象を欠測にし、以下を生成した。

> もし健太が花子を見つめたら。健太が次郎を助けなかった。

> 次郎を健太が助けなかった。もし健太が花子を見つめたら。

この例では時間関係は未指定なので、順序反転時にも先後関係を勝手に付加しない。2例とも3つの別プロセス（学習、順序保持生成、逆順生成）で実行した。`examples/` に受信波形、学習記録、保存記憶、生成JSON、内部768tick波形と途中積算ログを収録する。

## 6. 検証と再現性

新規30テストを通過。旧Bridgeリリース自身の40テストも元ディレクトリで再実行して通過した。これは過去全バージョンの全テストを今回実行したという意味ではない。

本評価は同一の最終凍結ソースで2回実行し、時間記録を除く全56結果ファイルがバイト単位で一致した。保存記憶12組を全件ロードし、代表12照会と1組の全教師系列を再実行して一致を確認した。36受信の再生成も一致。教師データ・専用学習モジュール・評価コードを置かない隔離ディレクトリから、2例の生成に成功した。`verify_release.py` と `verification/VERIFY.json` に検証内容を記録する。

元Bridgeの1,718ファイルとZIP、継承コピー103ファイル（コーパス名変更1件・評価補助3件を含む）は変更されていないことを保全記録で検査した。

## 7. 次の課題

最優先は、正常パイロット下での本文破損に対し、独立なSS再照合や更新前後の整合検査で誤更新を減らせるかを試すこと。同時に正しい教師の過剰保留、追加チップ・メモリ・待ち時間のコストを測る。外部S1の保留についても、受理を緩めるだけでなく、独立な再確認・再送条件として扱う余地がある。

今回で物理回路化や汎用文書生成に到達したわけではないが、記憶演算の時間順処理から意味保持文章までの接続を具体的に検証する足場はできた。
