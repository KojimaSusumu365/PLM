# PLM-L1-SS-doc v0.1：SS型短文書生成の接続実証

## 結論

**限定された二文・三文について、「読む→SS意味信号を渡す→意味を保持して書き直す」経路を実装し、評価した。** 144種類の制御文を三つの文書符号で試し、2592件の接続生成要求で、人物・行為・対象・肯否・仮定・明示された前後関係を保持した。

ここで進んだのは、既存の二事象の読み書きを接続し直し、三事象を混同せずに保持・生成する手設計の構造拡張を加えたことである。自由な日本語の生成、文書構成の自律学習、最近の能動教師選択の言語統合を達成したのではない。

## 1. 実際の出力

入力：

> 太郎が花子を助けた。その後、花子が健太を褒めた。その後、健太が由紀を訪ねた。

SS信号だけを渡して、提示順を逆にして生成：

> 健太が由紀を訪ねた。その前に、花子が健太を褒めた。その前に、太郎が花子を助けた。

原文の単純コピーではない。生成器は原文を受け取らず、SS信号から各出来事と関係を復元し、既存のSS語彙・語順・マーカー記憶を照会して出力する。`examples/demo.py` でこの例を一コマンド実行できる。説明用の例は評価正答率の独立標本には数えない。

## 2. 継承したものと今回設計したもの

v0.9の言語コアをソース変更なしで同梱し、432文章・意味対と初期語彙、216二事象・時間関係対から再学習した。SS型特徴選択を使った学習後の基底モデル指紋は、旧v0.9の保存モデルと一致した。

一事象の読み書き、六つの時間読取対応と六つの時間生成対応は、この学習済みSS記憶を使う。生成時に「beforeならその後」という意味対応表や完成文テンプレートへ戻す処理は置いていない。一方で、語彙候補、特徴項目、分割、構造スキーマ、発生ID、接続処理の反復と端点の付け替えは設計として残る。

今回追加したのは、二／三という事象数、各事象の存在・五つの意味項目、各事象対の明示関係、提示順を一つの数値信号へ結合・重畳する処理である。三事象の教師対は使っておらず、**三事象の構造を学習で発見したのではなく、学習済み部品を設計した構造で組み合わせた実証**である。

意味の入出力契約と式は [SPECIFICATION.md](SPECIFICATION.md)。SS-active v0.3の人工キー用学習器・教師対応補助記憶は、この言語コアへまだ統合していない。

## 3. 何を保持するか

各出来事のsubject、object、predicate、polarity、modalityを局所発生IDに結合する。同じ内容が二回登場しても、同一の発生へまとめない。事象数と提示順もSS信号に含め、通常メタデータで答えを添付しない。

三文の接続prefixは直前の文との関係を示す。隣接二組の関係はbeforeの向きまたはunknown。隣接していない第一・第三文の関係は「明示記述なし」としてunknownを保持する。これはその二事象が実際には前後関係を持たないという否定ではない。推移的な時間推論は今回行わない。

提示順はそのまま／逆順だけを許す。任意の並べ替えでは書けなくなる関係を黙って落とさないためである。因果、代名詞、省略、未知語、自由な時制・構文は扱わない。

## 4. 主評価

学習と開発に使っていない、順序を無視した出来事の組を使った。二事象12組×時間関係3通り＝36文、三事象12組×隣接関係9通り＝108文、計144種類。語彙・文法・一事象の部品は既知であり、未知自然文コーパスではない。

開発48入力は別の出来事の組とし、主評価前にコード・条件を凍結した。閾値や次元を最終成績で選び直していない。基本の文書信号は8192複素次元で、文書符号シードを三つ変えた。言語学習モデルと入力文は三つの符号試験で共有する。

一入力ごとに、提示順そのまま／逆順と、主体先行・対象先行・交互という三つの文内語順指定の計六通りを生成した。

| 対象 | 入力文種類 | 符号込み読解要求 | 正しい読解 | 接続生成要求 | 意味保持生成 | 生成の誤答／保留 |
|---|---:|---:|---:|---:|---:|---|
| 二事象 | 36 | 108 | 108 | 648 | 648 | 0 / 0 |
| 三事象 | 108 | 324 | 324 | 1944 | 1944 | 0 / 0 |
| 合計 | 144 | 432 | 432 | 2592 | 2592 | 0 / 0 |

出力語順の指定も2592/2592で一致し、生成結果の再読解でも2592/2592で意味を保持した。意味JSONから直接符号化して生成する別経路は432/432で正答だった。

採点では、ランタイムと別の制御文法実装で出力を解析し、各出来事の五項目と全ての明示関係を照合した。単なる同じエンジンでの往復成功だけで正解としない。ただし、この採点器は別コードであって、独立した人手注釈や実世界の意味検証ではない。

2592は繰返しと語順指定を含む要求数で、独立した2592種類の文書ではない。完全文書としての組合せは未知でも、設計した語彙・構文・意味スキーマの内側の試験である。小さな閉じた領域の成功を、一般的な日本語能力の100%精度とは解釈しない。

## 5. 二事象の旧課題への接続

旧v0.9の864入力要求を、新しい文書信号経路で再評価した。864/864で読解でき、接続生成864/864、生成の再読解864/864、意味からの直接生成864/864で保持した。

この回帰の接続生成は提示順そのまま・主体先行、直接生成は提示順反転である。主評価の新しい二事象36文では反転を含む六通りを試している。旧864要求は旧版の再利用であり、新しい独立評価の標本には足さない。

## 6. SS信号と学習済み係数が機能しているか

本評価前に固定した小さな診断集合、二／三事象各6文×3符号＝各18入力で比較した。この集合は各事象数の先頭6文で、結果を見て選んだものではないが、主評価全体より狭い。

| 条件 | 二事象：意味保持接続生成／18 | 三事象：意味保持接続生成／18 |
|---|---:|---:|
| 文書信号1024次元 | 18 | 18 |
| 文書信号128次元 | 9 | 3 |
| 発生IDと意味項目の結合を除去 | 0 | 0 |
| 時間の向きを消去 | 6 | 3 |
| 時間読取の学習係数をゼロ | 0 | 0 |
| 時間生成の学習係数をゼロ | 0 | 0 |
| 語彙生成の学習係数をゼロ | 0 | 0 |

この表で生成できなかった要求は全て保留または読解保留による生成未実行で、誤った完成文を成功として出した例はなかった。時間の向きを消しても生成できたのは、明示された方向がない文である。

時間読取をゼロにした場合は、文からの読解は失敗する一方、直接意味を符号化した生成は二／三事象各18/18で成功する。時間生成または語彙生成をゼロにすると、読解は各18/18で成功しても生成は全て保留する。読解・生成の役割を区別した比較であり、係数を消してもPythonの完成文テンプレートから出力する仕組みではないことを確認した。

ここで小さくした次元は**文書意味信号のみ**であり、言語のSS連想記憶は8192次元のまま。1024次元の少数例の成功から、全体の記憶容量や一般的な最小次元を決めたとは言わない。

## 7. 部分欠落、未知表現、局所編集

未対応・不正文14種類を三符号で試し、42/42で文書全体を保留した。四文、未知人物、未登録行為、代名詞、因果接続、終端欠落などを含む。部分的な文書を完成品として返していない。

三事象の代表信号について、ゼロ化、事象一つの削除、競合する主体の追加、信号成分の半分消去、強い複素雑音の五条件×三符号を試した。15/15で保留し、今回の破損試験での誤生成は0件だった。ただし一種類の代表内容と強い破損条件に限る。あらゆる雑音や、別の有効な意味への変化を拒否できる保証ではない。

SS信号上で第二事象の主体だけを置換する編集は3/3、隣接関係だけを変更する編集は3/3で、意図した部分だけを変えて生成できた。変更する値は検査側から明示しており、自律的な意味編集の学習ではない。

**検査上の補足**：固定された主評価の `clean_edge_edit` は、最初の三事象例のunknown関係をbeforeへ変更していた。事前計画の「向きの反転」とは同一ではないため、そのままの結果を残した。既にbeforeと分かっている関係を反対向きへ変更する検査を、主評価後の別枠で三符号に追加し、3/3で意図した生成・再読解を確認した。証拠は `verification/EDGE_REVERSAL.json`。これを主評価の追加独立標本や設定選定には使っていない。

これらは一般の数値信号の検査であり、P1の部分観測、S1の実チップ列・拡散逆拡散・パイロット同期へ接続した試験ではない。

## 8. 生成器の情報境界と再現性

生成器へ渡すパケットはschema、モデル指紋、次元、real、imag、eligible_for_inferenceの六項目だけ。原文、出来事配列、関係JSON、出来事数、提示順のヒントを追加すると拒否する。

別ディレクトリ・別プロセスでreader、trainer、SS選択器、評価器、教師データを除き、モデルと数値パケットだけから二文と三文を生成する検査に通った。出来事数をgoals引数で教えることもしない。モデルに既知語彙や候補集合が必要なことと、入力文書の正解を別経路で渡すことを区別する。

再学習も既存モデル・reader・採点器を除いた別ディレクトリで行い、学習対と初期語彙から同じモデルになることを確認した。検証の記録は [VALIDATION.md](verification/VALIDATION.md)、機械可読な結果は `verification/RELEASE_VERIFY.json` にまとめた。

本評価前のソース凍結：`09839680bf6ba791d3336befc5dd75730d740214c868e88703cb792369a0548a`。

本評価は二回実行し、時間記録を除く124ファイルでモデル・生信号・生成全文・採点がバイト単位で一致した。さらに保存物から、主評価432入力と診断252入力の合計684記録、24保存モデル、1266生信号配列を再検証した。既存二事象864件の回帰、42不正入力、信号編集・破損の結果も省略せず保存した。単体試験は26件全て通過した。

## 9. 費用と限界

8192次元の複素信号本体は131072bytesで、二文でも三文でも同じ次元。JSON転送量や、符号候補の基底配列、学習済みSS係数、通常の語彙メタデータ、固定サイズ照会キャッシュは別に必要である。構造を保持できたことを、そのまま省メモリや速度の優位性とは呼ばない。

`verification/BENCHMARK.json` に二／三文の代表例での読解・生成時間、パケットのJSONサイズを記録した。読解／生成の中央値は二文25.46／9.93ms、三文32.55／14.92msだった。文書符号の基底配列だけで10747904bytesを別途使用し、言語の学習係数等はさらに必要となる。キャッシュを温めた七反復の実測で、他のホスト負荷は隔離していない。全RSS、消費電力、全FLOPsは未測定。Windows以外の実機検証は未実施。

現在も手設計の構造・制御が多い。通常の記号的な実装との同費用比較を行っていないため、SS固有の性能優位性は結論づけない。SS-activeの訂正保持、未知語・照応・省略、意味の推論、自由長文、文書計画、P1/S1接続は未実装で、`eligible_for_inference=false` を維持する。

## 10. 次の判断

短文書生成への接続は、限定範囲で成立した。これからは記憶単体の成績だけでなく、生成された文書が何を保持・欠落・付加したかを継続して測る土台にできる。

次の小さな拡張としては、曖昧・欠落した一項目を勝手に補わず保留し、外部から追加情報を受け取った後に、修正箇所以外を変えずに文書を生成する実証が考えられる。SS-activeの仕組みを接続する場合も、候補不一致を正解そのものとして書き込まず、限定された人物・行為・時間関係のどこに教師情報が必要かを別途評価する。今回の成功を理由に、語彙や文書長を一度に無制限へ広げない。
