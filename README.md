# PLM — Phase Language Machine

**SS型の表現・演算・記憶・学習を基盤に、文章を読み、意味を保持し、その意味から文章を書く言語処理系を探究する研究プロジェクトです。**

このリポジトリには、最初の **PLM-C0 v0.1** から **PLM-L1-SS-core v0.4** までのコード、データ、試験、数値結果、設計資料、レビュー、開発途中の記録を保存しています。これは研究履歴の公開アーカイブであり、一般自然言語を自由に扱える完成品ではありません。

## PLMの目的

目指すのは、既存の言語モデルが出した答えをSS信号で伝送することではありません。**読解・意味処理・記憶の照会と更新・生成の主要な判断そのものを、符号と信号の演算で実行すること**です。

文章の表現が違っても同じ概念や出来事を扱い、誰が誰に何をしたか、否定・仮定・時間関係を取り違えずに保持する。そのうえで、経験と訂正から対応を学び、不十分な情報を勝手に確定せず、意味を保って別の文章へ書き直すことを目標にしています。

「ほぼすべてをSS型で動かす」は今後の研究目標です。コード行数や内積の個数でSS化率を決めず、**重要な判断を実際にどの処理が担っているか**を監査します。文字入出力、資源管理、数値ライブラリ等の補助処理と、言語判断を代行する通常の記号処理を区別します。

## 基本的な考え方

### 1. 意味を、結合・重畳できる信号で表す

ここでSSは *Spread Spectrum*（スペクトラム拡散）に由来します。識別用符号、位相表現、役割と値の結合、信号の重ね合わせ、相関による照合を言語処理へ接続します。複数の情報を重畳し、対象に対応する符号で参照することを基礎とします。

ただし、**位相・高次元ベクトル上の演算、明示的チップ列の拡散・逆拡散、物理的な通信装置は同じものではありません**。P1、S1、L1の各実装で、どこまで実証したかを分けて記録しています。

### 2. 語だけでなく、役割と関係を保つ

「太郎が花子を助けた」と「花子が太郎を助けた」は、同じ語を含んでも意味が違います。概念・個体・事象・役割・順序・否定・仮定などを区別し、読み取りと生成の間で失われない表現を目指します。

### 3. 記憶は、検索だけでなく学習と訂正に使う

文章と意味の対応、照会と教師の対応、訂正履歴を連想記憶として保持し、加算・結合や誤差に基づく更新を検討します。複数符号、重み付け、再照合、追加教師の選択、忘却等は、干渉や誤受理を減らすために比較する実験対象です。導入しただけで優位性が証明されたとは扱いません。

### 4. 分からないことを、分からないまま保持する

証拠不足、未登録、複数候補、矛盾は、無理に一つの答えへ押し込めません。必要に応じて保留し、追加情報を求め、訂正対象以外の意味を維持できるかを検査します。**相関の高さや信号の数値整合は、記載内容が事実として正しいことの証明ではありません。**

### 5. 生成は、保持した意味から行う

原文の丸写しや評価用の正解文章を生成器へ渡す経路と、意味からの生成を区別します。学習済みの部品を用いた語順変更、二事象の提示順変更、局所訂正後の再生成などを、小さく検証可能な課題として積み重ねます。

### 6. 仮説・実装・実測を混同しない

学習した対応と人手で設計した語彙・構造・教師を区別します。通常方式との比較、独立採点、未見組合せ、保留・失敗例、隔離実行、ソース固定、再現性を記録し、成功例だけで判断しません。脳との類似は着想・仮説であり、生物学的な脳の再現を実証したという主張ではありません。

基本方針の原記録は [SS型言語処理系への重点移動](docs/history/PLM-SS-LANGUAGE-DIRECTION.md)、最新の境界は [v0.4 SS化境界監査](versions/L1/ss-core/v0.4/BOUNDARY_AUDIT.md) を参照してください。過去の文書にある「次に行うこと」は、その時点の計画であり、現在の実施済み事項や自動実行の指示ではありません。

## 開発の流れ

|段階|中心となる問い|
|---|---|
|C0 → C1 → C2|概念候補、三値証拠、残差・矛盾、意味境界をどう扱うか|
|R1|役割・Relationを観察し、出典や推論の境界を保てるか|
|P1 → S1|位相符号・部分相関を、チップ列と同期復調へどう接続するか|
|L1 v0.1–v0.13|限定言語の読解と生成を学び、未見組合せ・曖昧性・二事象を扱えるか|
|L1 SS-weighting / online / multicode / active|重み・誤差訂正・複数符号・追加教師で記憶をどう改善するか|
|L1 SS-doc / P1-S1接続|短文書、訂正、再確認、意味信号の同期復調をどう結ぶか|
|L1 SS-core v0.1–v0.4|時間波形SSの照合・更新・読解・生成と意味ワーキングメモリを接続できるか|

全版への入口は [版別索引](docs/VERSION_INDEX.md) です。各版の内部構造を保ち、異なる世代のコードを一つの `src/` に混ぜていません。

## 現在の到達点：SS-core v0.4

限定された二事象の言語範囲で、**SS意味ワーキングメモリ → 役割参照 → 局所訂正 → 生成** を、対象経路で意味辞書へ復元せずに接続しました。意味内容と不確実性の状態を2本の重畳信号として保持します。

保存済みの [実施報告](versions/L1/ss-core/v0.4/REPORT.md) には、次の結果を記録しています。これらは当該版の有限な試験条件での結果であり、今回のGitHub移管時に全歴代実験を再実行した数値ではありません。

- 単体・回帰試験 **95/95**（新規20、従来75）。
- 主評価の生成 **80/80**。局所訂正 **12/12**、非対象項目保持 **132/132**。
- 未観測・読取不能・複数候補・競合の4状態を保留し、追加教師後に生成。
- 2回の実行で時間計測以外の **314ファイルが一致**。

実際の生成例（同報告から）：

> 入力：次郎を由紀が褒めなかった。その後、もし花子が健太を褒めたら。
>
> 主語先行：由紀が次郎を褒めなかった。その後、もし花子が健太を褒めたら。
>
> 逆順・第1文を目的語先行：もし健太を花子が褒めたら。その前に、由紀が次郎を褒めなかった。

人物の役割、否定、仮定、時間関係を保ちながら表現を変えています。自由な長文作文ではありません。

### まだ実現していないこと

旧読解器内の文字処理・構造組立て・意味辞書、固定命令の実行、保留閾値、停止規則等には通常処理が残っています。新ワーキングメモリは2事象・12項目という固定範囲です。未知語・未知構文・一般的な照応・多数事象・自由長文・長期連続学習は未達または未評価です。

新しい自然文コーパスから言語体系を自律獲得したわけではなく、既存の学習済み部品や設計された教師を再利用しています。実機の無線通信、脳の再現、LLMに対する性能優位性、省電力性、事実の正しさの保証も実証していません。詳細は [境界監査](versions/L1/ss-core/v0.4/BOUNDARY_AUDIT.md) を参照してください。

## リポジトリの構成と取得方法

```text
PLM/
├─ versions/              # 段階別・版別のコード、試験、設計、読める大きさの結果
│  ├─ C0/ C1/ C2/ R1/ P1/ S1/
│  └─ L1/                # v0.1…v0.13、ss-*、p1-s1
├─ docs/                  # 方針、版別索引、格納方針、再現方法
├─ reviews/               # Claude向け技術資料・受領レビュー・関連原資料
├─ archive/               # 配布後の検証記録、開発補助スクリプト等
├─ manifests/             # 全原本パス、SHA-256、版・保存先の対応
└─ tools/                 # 完全復元と照合（Python標準ライブラリ）
```

**Gitのツリーは閲覧用です。大容量の配列・モデル・全評価個票・元ZIP・作業記録まで含む完全保存データは、[このリポジトリのRelease](https://github.com/KojimaSusumu365/PLM/releases/tag/archive-c0-v0.1-to-ss-core-v0.4) にあります。** Git cloneやGitHub自動生成の「Source code.zip」だけでは全データを取得できません。

最も簡単なのは、[版別索引](docs/VERSION_INDEX.md) から目的の版の原本ZIPを取得する方法です。全履歴・開発途中の記録も復元する場合は、[復元・検証手順](docs/REPRODUCING.md) を参照してください。全原本パスを維持したまま、内容が同じファイルだけをSHA-256で重複排除しています。

```sh
# クローンしたPLMのルートで実行：最新対象版を完全復元
python tools/restore_archive.py --version PLM-L1-SS-core-v0.4 --download --dest ../PLM-restored
```

復元後の実行方法・依存関係は [その版のREADME](versions/L1/ss-core/v0.4/README.md) に従ってください。各版は独立したスナップショットであり、全版共通の一つの実行コマンドや依存環境はありません。
