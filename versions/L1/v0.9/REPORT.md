# PLM-L1 v0.9 実施結果

## 結論

**レビュー是正と、SS型特徴選択を実際の読み書きへ接続する最小実証は完了した。SS固有の精度・速度の優位性は示されなかった。**

位相記憶の構築・相関によって候補特徴集合の採否を決める処理を追加し、標準モデルからID3を外した。従来の単文・二事象・時間関係の標準回帰を維持した。一方、同じ特徴候補を通常処理で選ぶ方式も同等以上で、SS選択は計算費用が大きい。低次元・少標本・誤った教師ラベルでの失敗を全条件で記録した。

現在の価値は「SS演算を学習上の判断へ一段接続し、その寄与と限界を測定可能にした」ことにある。全SS学習や自律的な文法発見を達成したという結論ではない。

## 1. 旧言語課題の回帰

単文は192種類の評価入力、96意味。生成は384要求だが、意味とゴールの一意な組合せは192種類であり、反復を含む。初期語彙は全方式で与えた。

| 部品学習方式 | 学習対 | 読解：正解／誤答／保留 | 生成：正解／誤答／保留 | 対からの対応＋初期語彙対応 |
|---|---:|---:|---:|---:|
| SS型選択 | 432 | 192 / 0 / 0 | 384 / 0 / 0 | 32 + 20 |
| 同条件の記号的選択 | 432 | 192 / 0 / 0 | 384 / 0 / 0 | 32 + 20 |
| ID3 | 432 | 192 / 0 / 0 | 384 / 0 / 0 | 24 + 20 |
| 完全キー | 432 | 144 / 0 / 48 | 288 / 0 / 96 | 58 + 20 |
| SS選択のHだけゼロ | 432 | 144 / 0 / 48 | 288 / 0 / 96 | 58 + 20 |
| SS型・手選び6対 | 6 | 192 / 0 / 0 | 384 / 0 / 0 | 32 + 20 |

SS型の選択結果は、役割が `right`、肯否が `predicate_markers`、仮定が `leading_markers`、マーカー生成が `anchor + modality + polarity`。その他は順序・ゴール・語彙のキーである。ここで使う特徴項目そのものは設計済みである。

6対と432対のSSモデルは**全位相ブロックがbytesで一致**した。同条件の記号的選択とSS型も全ブロック一致。v0.9のID3対照とv0.8の部品モデルも全ブロック一致した。学習履歴や方式を記すメタデータが異なるため、モデル全体の指紋一致を意味しない。`verification/WEIGHT_COMPARISONS.json` に記録した。

SS型の32対応が旧ID3の24対応より多いのは、局所分岐葉を単一の大域マスクへ変え、マーカー対応が8から16へ増えたため。意味能力や発見規則数の向上とは解釈しない。6対が数学的な最小必要数とも主張しない。

二事象モデルはSS型部品で再学習し、標準8192次元・一つの時間符号で次を通過した。

| 検査 | 正解 | 誤答 | 保留 |
|---|---:|---:|---:|
| 二事象読解 | 864 / 864 | 0 | 0 |
| 意味から直接生成 | 432 / 432 | 0 | 0 |
| 読解→提示順反転生成→再読解 | 864 / 864 | 0 | 0 |

864読解要求は816種類の表面文、216種類のID付き意味記述。時間層は216対から読取6対応、生成6対応を学ぶまま。旧版と同じ36種類の順序を無視した事象対を再利用した制御言語課題である。v0.8の全符号・低次元・雑音試験を新選択器で再実施した結果ではない。

## 2. 新しい合成依存課題

5課題族×2特徴/ラベル置換。標準は24学習例と8評価例、二つの符号。したがって各Dの160要求は、80件の課題付き評価例を二符号で反復した数である。独立した160個の言語課題ではない。

以下は選択後の**位相記憶による照会**の結果。記号的選択も後段は同じ位相記憶を用いた。

| D | 方式 | 正解 | 誤答 | 保留 |
|---:|---|---:|---:|---:|
| 128 | SS型 | 131 | 0 | 29 |
| 128 | 同条件の記号的選択 | 145 | 0 | 15 |
| 128 | ID3 | 121 | 24 | 15 |
| 128 | 完全キー | 0 | 1 | 159 |
| 512 | SS型 | 160 | 0 | 0 |
| 512 | 同条件の記号的選択 | 160 | 0 | 0 |
| 512 | ID3 | 133 | 26 | 1 |
| 512 | 完全キー | 0 | 0 | 160 |
| 2048 | SS型 | 160 | 0 | 0 |
| 2048 | 同条件の記号的選択 | 160 | 0 | 0 |
| 2048 | ID3 | 134 | 26 | 0 |
| 2048 | 完全キー | 0 | 0 | 160 |

ID3の誤りには相互作用特徴を貪欲な分岐で選ぶことによる限界が含まれる。記号的な大域候補探索でも解けているため、この差をSSの固有の利点に帰属させない。

128次元のSS選択は20条件中2条件で、全候補が訓練回復条件を満たさず完全キーへ戻った。通常の対応照会で選択結果だけを採点すると144正解・16保留で、後段の位相照会ではさらに13件保留して131正解になった。対照の記号選択は選択のみなら160正解、位相照会で145正解。**選択時の干渉と、運用時の記憶回復の損失を分けて確認できた。**

SS選択のHをゼロにした10条件では、全候補が不受理となり完全キーへ戻り、80評価要求を全て保留した。後段記憶は学習したままであり、選択段階のSS演算が採否に影響することの制御試験である。

## 3. 少標本・誤ラベルへの弱さ

標準以外の50条件を2048次元・第一符号で実行した。8/16/24学習例と、0または約10%のラベル反転を含む。下表の400要求は条件間で評価例を再利用している。

| 方式 | 正解 | 誤答 | 保留 |
|---|---:|---:|---:|
| SS型 | 264 | 47 | 89 |
| 同条件の記号的選択 | 264 | 47 | 89 |
| ID3 | 294 | 106 | 0 |
| 完全キー | 0 | 0 | 400 |

SS型はこの設定ではID3より誤答が少ないが、正答数も少なく、多くを保留する。しかもmatched symbolicと同成績である。精度全面改善や、誤受理を解決した証拠ではない。

例えば `evaluation/unary/0/8/1` は真の依存が `f3` のみなのに、SS型は `f3 + f4` を選び、8件中2件を誤答した。訓練内100%回復は、少標本や誤教師によって生まれた見かけ上の依存を排除しない。候補の保留・複数候補保持・別データでの不確実性評価が次の論点になる。

全特徴値を訓練外の2にした極端な未登録照会は450条件で0/450受理だった。ただし各条件1キーだけの小さな診断である。同じ二値定義域内の未学習完全文脈では、上表の完全キー・128次元で誤受理1件があった。未登録照会全般が安全とはしない。

## 4. 費用

同じマスクブロックのDは揃えたが、方式ごとのマスク数は異なる。単文のSS型とmatched symbolicは8ブロック、計1,064,960 bytes。ID3は10ブロック、計1,331,200 bytes。どちらも固定照会キャッシュ容量は1,048,576 bytes。これは記憶サブシステムであり、意味コーデック、学習用行列、Python/NumPy、全プロセスRAMではない。

主評価の並行実行が終了してから、標準合成課題D2048を方式順序を無作為化して3反復した補助計測を実施した。各方式60条件実行の中央値は次の通り。

| 方式 | 特徴選択時間 | 後段コンパイル | 8件の位相照会 |
|---|---:|---:|---:|
| SS型 | 約152.64 ms | 約2.86 ms | 約6.54 ms |
| 同条件の記号的選択 | 約4.60 ms | 約2.77 ms | 約6.34 ms |
| ID3 | 約1.01 ms | 約4.04 ms | 約10.11 ms |
| 完全キー | 約0.20 ms | 約8.41 ms | 約3.49 ms |

現実装のSS選択はmatched symbolicより約33倍遅かった。低次元での不利も合わせ、現時点で高速化や効率向上の手段として推奨できる結果ではない。SS構成の学習上の役割を調べる研究用実装として位置付ける。

この測定はローカルの小規模マイクロベンチマークで、OS負荷・全体RAM・一般的な処理速度を厳密に統制したものではない。`results/PERFORMANCE.json` は主評価中の測定、`verification/BENCHMARK.json` は後段の補助計測であり区別する。計測値はモデル指紋や固定結果digestに含めない。

## 5. 検証と是正の証拠

- 主評価ソース・データ・プロトコルを凍結後、全v0.9数値評価を2回実行。結果JSON、二事象/部品のモデルJSONとNPZが全てbytes一致した。
- 現行版の36単体テストに合格。旧版を変更せず、その旧版自身の441テストと隔離CLIを別に実行して合格した。旧441テストを全てv0.9エンジンへ移植したという意味ではない。
- 924件の固定チェックに合格。ただしうち900件は各条件・各採点経路の件数整合検査である。924個の独立能力試験という数字ではない。
- 学習専用の別ディレクトリから読解器・評価器・旧重みを外し、文章/意味対と初期語彙だけで厳密に同じモデルを再学習した。
- 生成専用の別ディレクトリから読解器・学習器・選択器・コーパス・評価器を除き、数値パケットだけを転送する3例を検証した。構造ヘルパーと学習済みモデルは共有する。
- 816種類の評価表面文と3拒否プローブについて、再学習モデルとの読解・生成・保留の機能署名819件が一致した。
- 1 ULP、約4.44e-16の重み差は厳密指紋では異なり、機能比較では合格。0.01の差は係数比較で不合格。許容差内でも離散判定を変えた制御試験は不合格になる。変更モデルに元のパケットを渡すと厳密な指紋不一致で保留する。
- 現行閾値を共通ソースに統合。意味信号の回復可能性を外部の意味正解と区別。同一人物の主客を推論で支持しつつ、学習時には一意整列の限界で明示拒否する範囲を固定した。
- 旧成果物4,573ファイルをハッシュで照合し、全て保持した。旧v0.8 ZIPも元のハッシュ・CRC・492件のマニフェスト内容を確認した。

配布前検証は `verification/strict/VERIFICATION.json`、旧版検証は `verification/legacy/VERIFICATION.json`。ZIP実展開後の検証結果はZIPの隣の `PLM-L1-v0.9-VERIFICATION.json` に記録する。配布前の記録の `not_yet_packaged` は、その時点では配布マニフェストをまだ作成していなかったことを表す。

## 6. 到達点と未実施

「文章と意味の対応から得た候補の採否に、SS型の回復演算を使い、その結果で読み書きできる」は今回実証した。「特徴自体、文法、意味構造、停止条件までSSだけで学ぶ」は未達である。

Linux実機の再現試験は未実施。WSLは未導入であり、導入は行っていない。通常の浮動小数差を許す検証経路と、厳密な配布完全性検査を分けたが、これだけでクロスOS互換性を確認したとはしない。

三事象以上、照応・省略、未知自然文、一般時間論理、因果推論、偏った記憶負荷の改善、P1数値部分観測/S1チップ列・同期との接続、R1推論・Concept更新は開放していない。`eligible_for_inference=false`。

次は、独立Linuxでの機能検証と、少標本で複数の依存候補があり得る場合に不確実性を保持する小規模実験を優先したい。特徴選択をSS化できたことと、SS化が有利であることを引き続き別々に判定する。
