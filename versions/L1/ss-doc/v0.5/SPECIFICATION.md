# v0.5 仕様と実装境界

## 1. 目的

既知値として与えられた入力であっても、過去の訂正に反する古い値である可能性があります。v0.4では「既知値と強いSS記憶が不一致」なら保留しましたが、SSが弱くなると既知値をそのまま通す経路がありました。v0.5は、訂正管理対象の値を生成に利用する根拠を明示し、足りない場合に局所的な再確認を要求します。

目標は、(a)誤生成の抑制、(b)必要以上の再確認の回避、(c)回答をSS記憶へ反映した後の再照会、の分離評価です。「何でも保留すれば優れている」とは評価しません。

## 2. 数値意味信号と永続SS記憶

入力は既存PartialModelの8192次元複素信号です。事象の主体、対象、行為、肯否、仮定、時間関係などの各セルが `known / ambiguous / unobserved / unreadable / conflict` を表します。内部復号・検査は列挙候補と通常のPython構造を使います。文字列を一切扱わない純粋な波形機械ではありません。

スコープの根は次の内容のSHA-256です。

`root = hash(episode, mutable targets, event count, presentation, fixed known cells)`

改訂アドレスは `hash(root, target, revision)`。訂正対象の答えそのものは根・アドレスに入れません。可変対象以外は既知でなければなりません。外部の出来事IDや可変対象指定、提示順が変わると別スコープになります。同一出来事の自動同定は未実装です。

4符号チャネルの文脈符号を `c_k`、候補値符号を `v_kl`、SS重みを `W_k` とすると、結合型記憶の照合は概ね次式です。

`s_kl = Re(sum(conj(v_kl) * W_k * conj(c_k))) / D`

チャネル平均から候補順位を求め、既存の次の条件をすべて満たした場合に支持ありとします。

- 上位平均スコアが0.5以上。
- 0.5以上の候補がちょうど1つ。
- 2位または0との差が0.15以上。
- 4チャネル中3以上が同じ候補を1位とする。
- 照会アドレスが登録済み。保護領域と共有領域がそれぞれ強く別候補を返す場合は保留。

これらのスコアは校正済みの正答確率ではありません。「不確実性」は本版では弱支持・不一致・未登録などの離散判定です。評価を見て閾値を変更していません。

外部教師だけが共有誤差を作り、`e_l = one_hot(y)_l - mean_k(s_kl)`、`W_k += sum_l(e_l * v_kl * c_k)` と更新します。生成した予測は教師に使いません。改訂番号を進めた新しいアドレスに更新するため、同じ値の再確認も新しい登録と係数更新を伴います。

本評価の記憶構成：

|方式|SS係数構成|係数容量|背景更新|
|---|---|---:|---|
|versioned_shared|4 × 1472 complex128|94,208 byte|全体へ更新|
|versioned_pair|共有4 × 736 + 保護4 × 736 complex128|94,208 byte|共有のみ更新|

焦点事象は保護対象、背景事象は非保護と事前に指定します。これは外部制御であり、重要度を学習したわけではありません。係数容量は等しくても、符号基底、登録表、改訂メタデータ、キャッシュ、計算量は同一ではありません。詳細コストは各条件の `cost` に残します。

## 3. セッションと生成許可

新設した `Session` は短期的な対話状態です。数値パケット、スコープ、SS記憶フィンガープリント、および `target -> confirmed revision` を保持します。

|根拠|本版での扱い|
|---|---|
|現在の対話で正式に外部確認済み|その数値セルを利用可能。SSが弱くても直後の生成は可能|
|既知の入力値とSSの強い支持が一致|入力値を利用可能|
|未観測・曖昧セルにSSの強い支持|候補制約内なら数値信号を局所補完|
|既知値とSSの強い支持が不一致|入力を勝手に書き換えず再確認|
|既知値だがSSの支持が弱い|新方式は再確認。従来比較方式は入力を受け入れる|
|明示的矛盾・支持領域間の不一致|再確認|

セッション確認表は値の辞書を保存しません。ただし、セッションの数値パケット自体には教師が確定した値が入っています。したがって、確認直後の成功を「SS記憶から思い出せた」と数えてはいけません。

永続SS記憶は係数、符号生成設定、登録キー、改訂番号、保護フラグを保存し、教師回答テーブルは保存しません。冷間再照会ではSS記憶だけを保存・再読込し、訂正対象2つを未観測にした新しい数値入力から `Session` を作ります。古い確認済みパケットやセッション確認表を渡しません。

`assess / complete / generate` は学習しません。照合用キャッシュは変わり得ますが、永続係数・登録・改訂状態・入力数値信号を変更しません。正式な確認は `learning.confirm` だけが行います。

## 4. 再確認の選択と外部回答

優先順位は設計した規則です。順に、明示的矛盾100、記憶領域の不一致95、既知値の不一致または候補外90、弱い既知値80、支持のない部分観測70。同点は対象名の辞書順です。`always`比較は全対象を優先度10で確認します。1回答後には計画を作り直し、更新後のSS記憶を使います。

質問は対象、理由、スコープ、基準改訂番号、入力と記憶のハッシュを含み、隠れた正解値を含みません。質問文は「事象2の主体を確認してください。」等の定型文です。質問の価値を学習したものではなく、以前のSS-active選択器を接続したものでもありません。

回答は `{"question": 質問オブジェクト, "value": 候補識別子}`。確認時には質問が現在の計画に存在することを検査します。`known`には明示改訂、`conflict`には明示解消、その他には供給操作を使い、既存の局所更新契約と改訂契約を通します。古い質問、不正な対象、未知語、適用できない候補を拒否します。回答はGUIでなくPython APIまたはCLI JSONで受け取ります。

これらのハッシュは信頼されたローカル処理内の整合性確認です。改訂番号は真実性の証明ではなく、チェックサムは署名でもありません。悪意ある利用者がファイルとハッシュを両方作り直す攻撃を防ぎません。正しい形式の誤回答は学習され得ます。SSも誤って強い支持を返し得ます。無誤生成の一般保証はありません。

## 5. CLIと状態遷移

`start`で登録済みスコープから対話状態を作成し、`plan`で照合・再確認を提示し、`confirm`で1件回答を反映し、`generate`で全セルが確定した場合に文章化します。新規スコープの登録・初期学習は既存 `ss_revision` APIで行います。未登録スコープを勝手に学習・登録しません。

再確認が残る場合の終了コードは2。出力先は新規作成のみです。記憶が途中で別更新された場合はセッション全体を失効させます。並行書込み調停や、記憶ディレクトリとセッションファイルの停電時一括コミットは実装していません。

## 6. 固定評価設計

[PROTOCOL.json](evaluation/PROTOCOL.json) と [FREEZE.json](evaluation/FREEZE.json) が実行前の固定条件です。

開発6焦点+24背景、評価は2分割それぞれ12焦点+256背景です。焦点は2事象6件と3事象6件。各焦点の2対象にA1→B1→A2→B2→A3の5回確認後、背景256件を各2回確認して干渉を加えます。訂正箇所は主体、対象、行為、肯否、仮定、時間関係を含みます。

新しい主評価の全エピソードについて、初期・途中改訂・最終・古い既知値入力の場面指紋を使い、開発/評価分割間だけでなく別エピソード間の重複も除外しました。場面指紋は事象ID・提示順・時間関係を捨て、事象内容を整列した厳しい粗い一致基準です。同一エピソード内で同じ内容に戻ることは許します。`temporal_train`、`doc_v01_regression`、`doc_v02_scenes`、v0.4のデータ200/201の初期・改訂・古い既知値入力から得た1,279指紋も除外しています。すべての歴代実験ファイルを無条件に監査したという主張ではなく、既知単語・文型の共有を禁止するものでもありません。

主評価は2データ分割 × 2符号seed × 2記憶構成 × 3確認方針 × 3教師上限 = 72条件。各条件は12文書の固定シャッフル順です。教師上限0/6/24は12文書全体に対する上限であり、各文書の上限ではありません。実際の回答数を同数に強制していません。質問対象を選ぶ推論側に正解を見せず、評価側だけが求められた対象の正解を返します。

比較名 `legacy` はv0.4の既知値受理方針を新しい共通の再確認ループへ組み込んだ対照条件です。v0.4の保存済み全評価と本版の数値をそのまま同一条件として比較しているわけではありません。新しいデータ・教師上限・逐次再確認ループをそろえた方針比較です。

12文書は現在既知、古い既知、古い既知+欠測、両方欠測、明示的矛盾、両方曖昧の6種類を各2件含みます。逐次回答が後続文書のSS状態を変えるため、全体を1ストリームとして評価します。

各主評価後、SS記憶を再読込し、同じ12場面の2対象をともに未観測にした新しい照会で冷間保持を測ります。すべて共通の `ss_selective` 判定を使い、外部教師も確認済みセッションも使いません。比較用にフィードバック前の同一欠測入力も測ります。ただし前測定は意味補完と必要確認対象数だけで、文章生成は行いません。

主評価864エピソード、冷間864照会。それぞれ提示順保持と逆順・焦点変更の2文章要求、計1,728要求ずつです。独立した焦点場面は24件であり、864件の独立な自然文サンプルではありません。2seedしかないため統計的な一般化主張は控えます。

採点は復号結果と真値の一致、独立した表面文パーサによる意味一致、生成文の再読解、非対象の不変性を分けます。独立パーサは生成モデルの学習重みを利用しませんが、人手の盲検評価や未知文法の評価ではありません。v0.4の誤生成3例は別回帰枠とし、主評価へ混ぜません。旧言語生成144例も別に維持します。

## 7. 非目標と次段階

自由な長文、語彙・文法の新規獲得、任意個数の出来事、世界の真偽検証、質問方策の学習、P1/S1の物理的同期復調、長期間の忘却制御は今回の実装範囲外です。冷間保持には同じストリーム内の後続確認による干渉は含みますが、回答後に新しい背景事象を大量追加する遅延保持試験は含みません。古い既知値を再提示すると、正しい記憶と矛盾するため再び確認が必要となることも正常です。

今後の有力候補は、確認対象の価値をSS側で学習し、同じ教師コストで比較すること、および誤教師・遅延干渉・より多くのseedを用いた耐久評価です。これらは本版の達成結果と区別します。
