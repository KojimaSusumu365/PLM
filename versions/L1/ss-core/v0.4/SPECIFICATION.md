# PLM-L1-SS-core v0.4 仕様

対象：SS意味ワーキングメモリによる役割参照・局所更新・生成の直結。

## 1. 今回置き換える境界

v0.3 の時間波形型読解器が出す数値 DocumentPacket を受け、従来の「意味辞書へ復元→役割名で値を参照→生成器へ渡す」を置き換える。対象内では、意味の値・役割・事象・生成操作のオペランドを位相信号として受け渡す。既存のテキスト読解器そのものを無記号化したわけではない。

限定言語：既知の人名6、述語4、肯定/否定、通常/仮定、2事象、時間関係3、提示順2、主語先行/目的語先行。自由な日本語・長文・未知語・照応一般・推論を対象としない。「役割参照」は、事象と役割に対応した値の信号参照を意味し、自然言語の代名詞解決ではない。

## 2. 永続状態

`WorkingMemory.signal` は complex128 の `(2,8192)` 配列だけで意味状態を保持する。262,144 bytes。`__slots__` は signal/schema/engine の3つで、意味辞書・役割別の値リスト・文章キャッシュを保持しない。schema は全事例共通の公開参照符号、engine は数値受信器と監査ログである。

各チップ n について、内容チャネル M と状態チャネル Q を以下で定義する。

```
M[n] = header[n] + Σ_address a[n] × Σ_candidate v[n]
Q[n] = Σ_address a[n] × (state[n] + arity[n])
```

通常のアドレスは occurrence × role。2事象×5役割の10個に、時間関係と提示順のアドレスを加えた12個。候補の共通符号集合は19個。状態5種（known/ambiguous/unobserved/unreadable/conflict）と候補数0～6もそれぞれ位相信号で重畳する。状態の意味付けと許される候補数は設計した規約であり、今回学習した分類器ではない。

DocumentPacket の内容信号を既存スケールから戻し、既知状態の Q を追加する。インポート時には意味復元を行わず、生成前の照合と残差検査で数値的整合を確認する。モデル指紋は符号互換性の検査であり、入力の真実性や送信者を認証しない。

## 3. 参照と状態検査

1. 入力アドレス信号を公開アドレス基底で照合する。
2. M/Q を共役アドレスで逆結合し、値・状態・候補数の公開基底とチップごとに相関を累積する。
3. 最大支持0.65以上、次点差0.25以上、規定候補数外の支持0.35以下を要求する。
4. アドレスと値の合法組合せを加算学習したドメイン証拠信号で照合する。
5. 一時的な `Cell` に候補位相信号と状態位相信号を返す。状態番号・候補数の整数は汎用保留判定だけに使う。意味ラベルは返さない。

全体検査では12アドレスを再照合し、2つのクリーンな重畳波形だけを再構成する。元波形との差の相対ノルムが各チャネル0.20以下であることを要求する。値辞書へは戻さないが、残差ノルム、閾値比較、候補ランキングは通常の数値処理である。

候補が複数・未観測・読取不能・競合なら保持できる。ただし今回の生成器は全12項目が known かつ単一候補の場合のみ出力する。部分的に確定した内容だけを文章化する機能は実装していない。

## 4. 局所更新

入力はアドレス信号 a と外部教師の値信号 t。内部で自然言語の訂正文を解析しない。

```
M'[n] = M[n] + a[n] × (t[n] - old_candidate_sum[n])
Q'[n] = Q[n] + a[n] × (known[n] + arity1[n] - old_state[n] - old_arity[n])
```

8192チップを順に更新したステージング配列を作成し、以下を全て確認してから新しい WorkingMemory を返す。

- 更新前/更新後の全体整合。
- 教師符号の受理とアドレスのドメイン適合。
- 対象を再照合すると教師信号が回収されること。
- 非対象11項目全ての状態・候補数・候補信号和が変わらないこと。

失敗時は元メモリを変更せず `held` を返す。`Core.revise_and_generate` は更新が保留なら文章を一切返さず、同じリクエストで旧内容を再生成しない。低水準 `update` の戻り値の状態を無視して呼出元が旧メモリを別途生成することまでは防げない。永続的な未処理訂正管理・多者間トランザクション・ハードウェア書込みACKは今回の新WMでは実装しない。

未知/競合状態も、外部教師が与えられれば known に更新できる。ドメイン内の誤教師は受理されうる。これを事実の正しさを学んだ証拠とは扱わない。

この局所更新は作業中の意味状態の書換えである。語彙重み・生成プログラム重み・訂正方策をオンラインで再学習する操作ではない。オフラインのSS符号対応学習と、個別文書のWM更新を同じ学習成績として合算しない。

## 5. 生成経路

数値の提示順信号から文書プログラムの文脈を作り、時間波形SSプログラムが操作信号と次状態信号を回収する。操作はSS対応記憶で汎用opcodeとオペランド信号へ移す。

- 事象オペランドは事象位相信号。
- 語彙オペランドは役割位相信号。事象×役割をWMへ直接照会する。
- 回収した値信号は語彙SS対応記憶に入り、表層信号になる。
- 肯否と法の値信号は文脈コードへSS対応付けし、文プログラムを制御する。
- 時間関係×先行して出力する事象の信号から時間接続表層を回収する。
- 文字列化は `Terminal.emit` に限定する。文の連結は通常のPython文字列処理。

内部に意味役割名による分岐や `meaning[role]` 参照はない。一方、opcode 0/1/2 を実行する汎用インタプリタ、繰返し上限、2つの固定文脈ポート、重複検査、終了条件はPythonのまま残る。

## 6. SS対応記憶の作成

`compile_bundle` はオフラインの符号体系間接続であり、オンライン生成には含まれない。

```
H[n] += conjugate(input_code[n]) × output_code[n]
```

既存の語彙/時間関係SS記憶から回収した対応と、設計した操作/オペランド/ドメイン教師を用いる。新たな自然文コーパスから文法を獲得したわけではない。v0.3の文/文書プログラム重みは再利用する。

9つの接続記憶の教師数は polarity 2、modality 2、presentation 2、lexical 10、temporal 6、sentence_op 12、sentence_operand 12、document_op 3、document_operand 3。計52対応。ドメイン証拠45対応を加え、97×8192=794,624チップ加算。

新規学習重みは10ベクトル=1,310,720 bytes。全公開基底と旧プログラム重みを含む `signals.npz` の非圧縮配列合計は27,394,048 bytes。WM本体だけを数えてモデルが小さいと評価してはならない。

これらは配列のデータbytesであり、Pythonオブジェクト、照合用一時配列、監査ログ、旧読解モデルを含むプロセス全体の常駐メモリではない。Engineの監査ログは照会ごとに増えるため、継続運用のログ管理やメモリ上限は別途必要である。

## 7. 時間波形とP1/S1境界

v0.3の `Engine/Receiver` を変更せず共用する。相関は先頭パイロット16、ペイロードN、末尾パイロット16を順に受信し、末尾確認前の値では判定しない。一定位相回転の推定、受信長、欠落、非有限値、読取中のソース変化を確認する。受信側が未来サンプルや学習元の全配列へアクセスして一括内積する経路はない。

ただしシミュレーションのDAC側は配列を持つ。位相コード生成・積・残差・清浄化・重みファイルはデジタルPython/NumPyである。v0.4の2チャネルWM全体を新たにRF搬送し、周波数探索や物理チャンネルを通して復調する試験はしていない。従来bridgeとその回帰試験は同梱するが、それを新WMの物理実装実証とは数えない。

## 8. 保存・監査

WMの保存は `signal.npz` と `state.json` の2ファイル。後者はスキーマ・符号束指紋・信号SHA256のみ。意味ラベルや正解文章は含まない。モデル束の `IO.json` は境界/教師/評価器用であり、Coreのload/generateは読み込まない。

監査ログは各窓のタグ、サンプル数、ソース/受信指紋、受理状態を記録する。ログの窓タグは建築上の機能名で、意味の値を保持しない。任意入力への完全安全性や秘密情報保護を保証するログではない。
