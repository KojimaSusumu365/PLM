# SS記憶の重み付け・比較試験 v0.1：実施報告

2026-09-08。独立試験版として実装・試験した。PLM-L1 v0.13の正式な置換ではない。

## 1. 結論

SS記憶への重み付けには、改善する条件が実際にあった。特に「正の個別重み」の学習は、512次元に256キーを記憶する条件で、正しい回復を1,390/1,536から1,500/1,536へ増やし、登録済みキーの誤答を4から0、未登録キーの誤受理を132/1,536から65/1,536へ減らした。同じ教師・符号・保存する複素重み配列サイズでの比較である。

ただし、未登録誤受理65件は残る。大きな座標欠落では誤答を増やす条件もあった。重み付けをすれば安全になる、あるいは常に全指標が良くなるとはいえない。

符号付きの補正は保存済みキーをさらによく回復できるが、未登録キーを受理する危険も大きい。512次元では保存済みキーの回復は全正答となった反面、未登録誤受理は157件で均等加算の132件より増えた。訓練済み記憶の再生と、知らないものを拒む能力は別の評価軸である。

記号的な対応表は今回の清浄な記憶課題を全正答・未登録誤受理0で解いた。今回示せたのはSS内部での改善であり、記号的対照に対するSS固有の優位性ではない。

## 2. 実装したもの

比較方法は四つ。位相符号・積結合・相関照会の基本はv0.13のものを利用した。

| 方法 | 保存する記憶の作り方 | 学習上の自由度 |
| --- | --- | --- |
| uniform | 観測した各キーの符号をクラス別に等しく加算 | 個別の重み学習なし |
| positive | 同じクラスの各キーに0.25〜2の正の重みを付けて加算 | 各記憶の寄与度を学習 |
| residual | 教師済みの全キーから各クラスへ、負の補正も含めて加算 | 他クラスへの補正を含む、より大きな自由度 |
| gain2 | uniform全体を単に2倍 | 診断用。採用候補ではない |

positiveは教師応答の目標を正解クラス1・他クラス0とする二乗誤差と、重み1からの逸脱への正則化を用いた。正則化係数0.1、固定128回の射影勾配法。residualは同様の目的を符号付き係数へ拡張し、線形方程式で解く。詳細な式はREADMEを参照。

学習器に渡すのは観測済みのキー／ラベル対だけ。教師済みの他クラスは負例になるが、未観測のキーを正解ラベル付き・不在ラベル付きで学習させていない。同じキーの重複は除くため、単純な出現頻度の増加を学習効果としない。

SS保存モデルはクラス数×次元の複素重みHとメタデータを保持し、教師キー表・教師符号行列B・相関行列G・学習した個別係数を保存しない。学習時にはB、G、最適化用行列を作る。通常の行列計算と最適化を用いるので、全SS学習・STDP・オンライン局所学習ではない。OnlineHDそのものの再実装でもない。

## 3. 試験条件と分離

二種類の試験を分けた。

### 独立した記憶バンクの負荷試験

4項目・各8値の計4,096キーから、4クラスが均等になるよう16／64／256キーを保存した。別の256キーは「保存されていないので保留すべき入力」とした。教師ラベルは固定した擬似乱数的な割当てであり、未知の意味規則を学ぶ課題ではない。

D64／128／256／512、三つのデータseedと二つの符号seedを使用。72条件×4方法＝288 SSモデル、清浄条件のexact対照9モデル。各モデルに清浄、75%座標欠落、4-bit相当丸め、重みへの加法雑音の四条件を適用し、1,152個の全相関配列を保存した。

登録済みキーの回復は訓練した記憶の取り出し試験で、未知キーへの正解ラベルの一般化試験ではない。三つのキー集合は重なり得て、二符号も同じ課題の反復である。合計1,536照会を1,536種類の独立な世界と解釈しない。

### 元の構造化課題への回帰

元の16課題に対し、初期教師と、元のuniformモデルが選んだ追加教師一件後を全方法へ同じように渡した。SSはD128／512／2048×二符号×三方法、exactは一条件。範囲外二課題は候補ゼロのため追加教師なし。合計570モデル。

`plm_l1_v013/core.py`と候補整合性を調べる元の学習コードは無改変で利用した。重みを理由に依存候補を消す変更も、部分入力の全候補一致規則の緩和も行っていない。重み付け後のモデルによるオンラインSessionや、新しい能動教師効率の評価は今回接続していない。

本評価前にソース・テスト・評価条件・データを凍結し、本評価を二回実行した。閾値0.5・重み範囲・正則化係数・反復数は最終結果を見て変更していない。最適な閾値を別の検証集合で選んだ比較ではない点には注意が必要である。

## 4. 高負荷・清浄条件の結果

保存数256キー。各行の登録済み照会も未登録照会も、三データ×二符号の合計1,536件。正答率は保留も分母に含む。

| 次元 | 方法 | 登録済み：正答／誤答／保留 | 未登録の誤受理 |
| ---: | --- | ---: | ---: |
| 64 | uniform | 551 / 152 / 833 | 645 |
| 64 | positive | 497 / 107 / 932 | 325 |
| 64 | residual | 682 / 51 / 803 | 519 |
| 128 | uniform | 810 / 68 / 658 | 598 |
| 128 | positive | 963 / 44 / 529 | 252 |
| 128 | residual | 1,303 / 5 / 228 | 472 |
| 256 | uniform | 1,124 / 27 / 385 | 354 |
| 256 | positive | 1,370 / 3 / 163 | 184 |
| 256 | residual | 1,533 / 0 / 3 | 377 |
| 512 | uniform | 1,390 / 4 / 142 | 132 |
| 512 | positive | 1,500 / 0 / 36 | 65 |
| 512 | residual | 1,536 / 0 / 0 | 157 |

512次元のpositiveは回復率90.49%→97.66%、未登録誤受理率8.59%→4.23%。128／256次元でも正答・誤答・未登録誤受理が同時に改善した。一方64次元ではpositiveが誤答・誤受理を減らす代わりに正答も54件失い、保留が99件増えた。全次元で回復率が上がったわけではない。

residualは512次元で回復率100%となるが、未登録誤受理率は10.22%。256次元でも未登録誤受理が354→377へ増えた。教師済みキーへの当てはまりを良くするほど、未知の入力にも強い相関が出る場合がある。重みの強さを真である確率と見なしてはいけない。

この結果から「positiveが最良の重み学習法」とは結論しない。今回の固定閾値・正則化・クラス負荷において、採用検討の余地が見えたという位置付けである。

## 5. 座標欠落・丸め・雑音

512次元・保存256キー、各1,536件の結果。各欄は登録済み「正答／誤答／保留」と未登録誤受理を示す。

| 条件 | uniform | positive | residual |
| --- | --- | --- | --- |
| 清浄 | 1390 / 4 / 142；132 | 1500 / 0 / 36；65 | 1536 / 0 / 0；157 |
| 75%座標欠落 | 759 / 85 / 692；617 | 833 / 91 / 612；541 | 841 / 92 / 603；610 |
| 4-bit相当丸め | 1378 / 2 / 156；139 | 1497 / 0 / 39；61 | 1536 / 0 / 0；167 |
| 加法雑音 | 1390 / 3 / 143；133 | 1500 / 0 / 36；64 | 1536 / 0 / 0；159 |

座標欠落ではpositiveの正答は74件増えるが誤答も6件増えた。さらに厳しい64次元・保存256キー・75%欠落では、positiveは正答を94件増やす一方、誤答を86件、未登録誤受理を98件増やした。この方式をそのまま部分観測に安全な復号器として採用しない。

欠落は同じ明示マスクでD/4座標だけを照会し、相関を観測座標数で割る。マスクや観測数を信号から推定したものではない。丸めは実部・虚部を各15段階へ丸める数値シミュレーションで、保存サイズを4-bitにした実装ではない。雑音は全方法へ同じ実現値を加え、各モデルの振幅に合わせた再正規化はしていない。P1/S1通信の接続実績ではない。

exactへ同じ座標欠落を強制するような恣意的な対照は置かなかった。これらはSS内部の耐性比較であり、記号的対照との同一障害モデルでの優位性を示す試験ではない。

## 6. 単なる増幅は改善しなかった

gain2は全72条件で、重みを2で割るとuniformの配列へbytes単位で一致した。内部信号と内部干渉を一律に拡大しただけである。

512次元・保存256の清浄条件ではgain2が913正答・0誤答・623保留、未登録誤受理615となった。uniformの1,390正答・4誤答・142保留、未登録誤受理132より、正答を大きく失い未知を多く受理した。閾値を越えるクラスが複数あれば保留するため、増幅しても回答数が単調に増えるわけではない。

したがってpositiveの改善を「全体を大きくしたため」とは説明できない。補助計測の同じ512次元・256キーでは、positiveの重みエネルギーはむしろuniformより小さかった。ただし全条件で同じ信号エネルギー・ダイナミックレンジを固定した試験ではない。

## 7. v0.13の候補保持・意味的保留は維持

570構造化モデルのうち、positive/residualの360条件を対応するuniformへ照合し、候補集合と離散予測（値・保留理由・可能ラベル）が全て一致した。従来の小さい候補内記憶には、この重み学習による新しい精度改善は見られなかった。

例えばD512・二符号の標準10課題では、完全入力480要求が初期462正答・18保留、一教師後480正答。部分入力2,432要求は初期1,692正答・740保留、一教師後1,764正答・668保留で、全方法とも誤確定0だった。

隠れた依存世界の完全54要求は初期42正答・12保留、一教師後54正答。部分254要求は168正答・86保留から204正答・50保留となり、真に曖昧な50要求を保留した。四特徴パリティは候補ゼロのまま、完全96・部分488要求を全保留。範囲外を学習できるようになったわけではない。

これは同じ追加教師を使う制御された再学習比較である。新しい重み付けで教師要求数が減ったという結果ではない。文章読解・生成器やR1推論は変更せず、`eligible_for_inference=false`を維持した。

## 8. 記憶容量・計算費用・exact対照

SS各方法は同じクラス数×次元のcomplex128配列を保存する。四クラスD512なら32,768 bytesで、学習済みの個別係数・教師キー表を予測器へ追加保存していない。メタデータ、位相原子キャッシュ、学習用行列は別である。

本評価二回は並行実行したので、その計時を方式の速度比較の主根拠にしない。終了後の単独プロセスで四つの事前指定形状を各3回計測した。D512・256キーの学習時間中央値は次のとおり。

| 方法 | 学習＋共通診断 | 保存重み | 計測用教師集合での重みエネルギー |
| --- | ---: | ---: | ---: |
| uniform | 15.43 ms | 32,768 bytes | 128,458 |
| positive | 25.86 ms | 32,768 bytes | 98,137 |
| residual | 23.29 ms | 32,768 bytes | 139,694 |
| exact | 2.68 ms | 対応表をメタデータへ保存 | SSエネルギー比較対象外 |

positiveは約1.68倍、residualは約1.51倍の学習時間を要した。この計時は入力検査・符号化・学習・診断を含み、教師待ちやオンライン一件更新の時間ではない。

同形状の教師符号行列だけで2,097,152 bytes。別に把握した学習配列はuniform約90KB、positive約706KB、residual約1.07MBで、保存Hより大きい。これらは名前を付けて数えた配列の会計であり、同時ピークRAM・BLAS内部配列・電力の全量ではない。

exactは同じ教師を完全一致の対応表に保存し、九つの清浄条件全てで登録済みを全正答、未登録を全拒否した。相関行列が単位行列ならpositive/residualの最適係数は元のone-hotのままになることを単体テストで確認した。SSへ有利にするためexactの教師を減らしたり、誤差を加えたりしていない。

exactの上記256キーのJSONメタデータは15,688 bytesで、既にSS重みより小さい。JSON表現が記号的記憶の最適圧縮形式でもない。低次元でSS配列が小さく見える条件だけを選んで、記号的表より省記憶と主張しない。今回は総学習RAM・電力・校正ラベルまで揃えた優位性試験ではない。

## 9. 再現性・配布検証

- 新規33＋v0.13継承54＝87テストに合格。目的関数、正係数範囲、符号付き補正の停留条件、単位相関対照、重複教師、未知キー、保留規約、保存・改変検出等を含む。
- 最終本評価を二回実施。結果JSON、全相関配列ファイル、保存モデルと教師ファイルの計26ファイルがbytes一致。環境・計時は除外。
- 保存した独立記憶4モデルと構造化6モデルを、観測済み教師だけの隔離環境で再学習。全モデルで係数差0・厳密指紋一致。独立記憶4×512＋構造化6×154＝2,972照会の離散予測が一致。
- 教師・学習器・最適化器・評価器・正解表を除いた環境でも10モデルの予測が一致。
- 1,152個の生スコア配列をハッシュ照合し、保存結果の指標をそこから再計算して一致。
- 従来成果物5,084ファイルは全て無変更。元のv0.13 ZIPのCRC・manifest83項目も確認した。

v0.13全480取得過程の再評価は今回行っていない。継承54テストと、上記の固定教師による570モデルの回帰を区別する。さらに古い版の全テストも再実施していない。Linux実機は未検証。

開発用の別分割で16記憶モデル・exact2・構造化32を先に実行した。開発段階から未登録誤受理が残ることは把握し、その失敗も `verification/development/` に保存した。重み方式・閾値を本評価結果に合わせて再調整していない。

## 10. 判断

「重み付けで改善するか」には、今回の範囲では「はい、特に正の個別重みで改善する条件を確認できた」と答えられる。しかし、現行言語系の置換や未登録受理の安全性を満たすには不十分なので、自動的な採用は行わない。

次に検討するなら、positiveを候補として、別の校正集合による未登録受理の抑制と、同じ誤受理率での回復率比較を優先する。その際も調整に使った教師・不在情報・メモリ・計算時間を対照へ公平に計上する。P1/S1や文章系へ接続する前に、低観測率での誤答増加を解決する必要がある。
