# PLM-L1-SS-doc v0.6 実施報告

## 結論

「SSの照合状態から再確認先の価値を学習し、後続学習の後にも意味を保持して文章化する」実装と比較試験を完了しました。

**共有SS記憶では、同じ確認回数での保持が改善しました。ただし全条件で優れるわけではなく、共有＋保護記憶では1文書の悪化がありました。** 内容記憶の安全な受理条件はv0.5のままです。

共有記憶の3負荷段階を合計した216文書照会では、後続学習後に正しく生成できた文書は次のとおりです。各方式とも追加確認は108回です。

- 現行規則：117/216。
- 無作為選択：110/216。
- SSで学習した選択：131/216。規則より14件、無作為より21件多い。

共有＋保護記憶では、規則・無作為の216/216に対し、SS選択は215/216でした。主評価の全方式で誤生成は0件で、残りは保留です。これは今回の限定試験の観測値であり、一般的な無誤生成の保証ではありません。

## 何を実装したか

内容を覚える既存SSとは別に、「どの照合状態を確認すると、その後の保持に役立ちやすいか」を覚えるSS価値記憶を追加しました。

選択器は18個の数値特徴を4チャネルの複素符号へ重畳し、学習済み係数との相関で候補を評価します。学習に使用したのは576件の確認あり／なしの対比較です。両方の枝に同じ新規背景64件を学習させ、その後の文書・対象の正しさの差を教師値にしました。

学習するのは候補の価値であり、質問の文面や文法ではありません。手設計特徴に対して線形な小さなSS近似器です。選択器の予測値は確率ではなく、生成を許可する根拠にも使いません。自分の推測値を正解として内容記憶へ学習することはありません。

## 全比較結果

## 確認しなかった場合との比較

共有記憶で追加確認を行わない対照の遅延意味正解は、0→64で70/72、64→128で31/72、256→320で0/72でした。SS選択はそれぞれ71、49、11です。対照は意味保持だけの測定で、文章出力要求には含めません。

特に64→128では、確認を始める時点の無確認状態は70/72が意味正解でした。それでも後続学習後には31/72へ低下します。現在すでに明確な欠測がある箇所だけでなく、保持のためにどこを確認するかを選ぶ余地がある、という結果です。

一方、共有＋保護記憶は無確認対照でも遅延216/216でした。ここでは追加確認の利益は実証できず、SS選択の一部更新はむしろ保留を増やしました。

本比較は正確に同じ回答数を使うため、すでに支持が十分な対象にも任意確認を行います。全648確認のうち必要確認110、任意確認538でした。これは通常運用でも必ず6回質問すべきという意味ではありません。「確認しない」を選択する停止方策は、今回まだありません。

## 残った問題をどう読むか

高負荷の共有記憶256→320では、SS選択は規則の4/72に対し11/72まで改善しました。しかし61/72はなお保留です。確認直後の意味正解26件から、さらに15件分減っています。選び方だけで記憶の干渉や容量問題を解消したとは言えません。

共有＋保護で悪化した具体例は `d400-c0-versioned_pair-l256-ss_learned` の `d06-q400/6` です。確認直後は正しかったものの、後続学習後に `event:0/object` で共有・保護領域の不一致が生じ、生成を保留しました。同じ文書は無確認対照では保持できており、この文書自体はそのラウンドで確認されていません。

他文書への確認更新がある状態での副作用を、結果から切り離して評価する必要があります。今回の教師値は選択した文書の保持を中心にしており、他文書への影響は記録だけで教師値には含めていません。これを全面的な価値学習と呼ばず、最小実証の限界とします。[対応条件ごとの改善・悪化例](verification/RETENTION_CHANGES.json) を残しています。

また、SS選択は共有記憶でもすべてのseed・場面条件で勝っているわけではありません。例えば `d401-c0-versioned_shared-l64` では規則10/12に対しSS選択9/12でした。上表は対応する6条件を合計した記述結果で、有意差や普遍的優位性の主張ではありません。

## 実際の生成例

操作を確認する読みやすい別枠デモでは、SS選択器が次を選びました。

> 事象2の対象を確認してください。

外部回答は「健太」。回答後のSS記憶を保存・再読込し、主体と対象をともに未観測にした元の数値入力から、次を生成しました。

> 太郎が花子を助けた。その後、由紀が健太を褒めた。

この小例では元からSS支持が十分なので、任意確認の操作例です。後続干渉への有効性を示す比較例ではありません。[DEMO.json](examples/run/DEMO.json) と [CLI実行記録](verification/CLI_WORKFLOW.json) に区別して保存しました。主評価の実際の2事象・3事象の全生成文は、[結果索引](results/INDEX.json) から各条件ログへたどれます。

主評価では、SS選択の432照会中346文書で両方の表現を正しく生成し、86文書を保留しました。生成した692出力は、独立パーサの意味照合と再読解で一致しています。全3方式では1,296照会中1,005文書を正しく生成、291保留、誤生成0。2,592出力要求のうち2,010出力を実際に生成しました。成功した出力だけを分母にしていません。

教師・評価データを置かない最小ランタイムでも質問選択を再現しました。そこで固定した2事象・3事象の2照会は、1件生成・1件保留でした。成功例への差替えは行っていません。

## コーパス・費用・再現性

合成コーパスは1,430エピソード。選択器学習用と評価用の焦点場面は各24件、開発用は6件です。全改訂段階を含めて別場面・別分割との重複を除き、過去2,431場面指紋も除外しました。[CORPUS.md](CORPUS.md) に教材の構造と教師値を説明しています。

独立な評価焦点場面は24件、評価符号seedは3つです。1,296照会を独立な1,296文章とみなしていません。選択器は576教師例を12周、6,912回更新しました。学習内平均二乗誤差は約0.02814ですが、これを未知文書の正答率とは解釈しません。

内容SS係数は各方式94,208 byte。SS選択器には16,384 byteの追加学習係数と、294,912 byteの特徴符号基底RAMが必要です。18個の通常の数値特徴に対する線形な価値近似であり、一般的な線形モデルに比べた効率・精度の優位性は比較していません。オフライン教材作成576確認分と学習計算も、評価時の6確認とは別の費用です。[計算費用の実測](verification/COMPUTE_COST.json) に選択器・内容記憶の照合呼出しと小規模時間測定を残しています。

固定した12文書・6確認の1ラウンドでは、内容SSの照合は各方式312回、学習選択器の追加予測は129回でした。3回測定の中央値は規則5.97秒、無作為5.84秒、SS選択5.77秒でしたが、この小さな時間差を速度優位性とは解釈しません。読み込み・後続背景学習・文章生成は測定範囲外です。

116単体試験、旧言語生成144例、旧失敗3例の別回帰を維持しました。全108条件を別フォルダでもう一度実行し、時間ファイル以外の907ファイルが完全一致しました。選択器も教材作成から再学習し、時間を除く6ファイルが完全一致しました。

固定ダイジェストは `8807c88a47bc66a7b225bf86fa349d661307fc08274b2eb696b4b85111ce3029`。学習済み選択器フィンガープリントは `abdac33ac00072c8d1ee3466b5fb64604e0ca51ab54b9c44d5505f06d7040076` です。検証範囲と最小ランタイムでの推論分離は [VALIDATION.md](verification/VALIDATION.md) を参照してください。

## 達成範囲と次の候補

達成したのは、確認先をSS価値記憶で学び、同じ教師回答数で後続学習後の意味保持・実際の文章生成まで比較できるようにしたことです。共有記憶では改善を確認しましたが、保護記憶への無条件な置き換えは勧めません。

次の候補は「確認しない選択」と「他文書への副作用も含む価値学習」です。今の記憶が十分なときに更新を控えることと、選んだ文書だけでなく保持すべき全体を評価することを、新しい未使用場面で検証するのが妥当です。今回の失敗を見て本版の教師値・閾値を変更したわけではなく、次段階への提案です。

今回は既存語彙・文型の2～3事象、外部指定2項目、合成教材での実証です。質問文・新語・文法の学習、自由長文、教師の真偽判定、選択器のオンライン再学習、P1/S1の物理的同期復調は追加していません。SS以外の通常の制御も残っています。
