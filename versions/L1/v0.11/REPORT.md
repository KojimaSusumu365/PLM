# PLM-L1 v0.11 実施報告

2026-09-08。Windows / Python 3.12.14 / NumPy 2.3.5。

## 1. 結論：比較実証は完了、言語コアへの全面採用は見送る

加算型、積結合型、1〜3項の組合せを加算するhybrid3を、特徴選択の有無とSS／明示的な記号カーネルの二軸で比較した。v0.10の言語実装・受理規約は変更していない。

重要な結果は次の三つである。

1. **単純な加算だけでは組合せ依存を十分に読めない。** XORと3項パリティは加算型＋選択でも全保留になった。組合せ項を持つ二方式は標準の完全入力を全件処理した。
2. **意味情報の不足と、数値信号の部分観測は別問題である。** 必要特徴が欠けると積結合型は保留する一方、特徴は完全なまま数値座標だけを1/8に減らした試験では、選択付き積結合型は全件を正しく照会できた。
3. **部分一致による回答増加には誤確定の代償がある。** hybrid3は、一意に決まる意味不足入力を積結合型より多く正答したが、複数の答えが成立する入力にも確定を出した。現状のまま言語コアへ置き換えない。

SSの主要な傾向は記号的対照でも再現された。SS固有の精度・速度・容量の優位性、全SS学習、脳の再現を示したとはしない。

## 2. 実施範囲と公平性

独立した記憶モジュールであり、新しい日本語読解器・生成器ではない。主客と肯否・仮定の試験も、入力をあらかじめ項目化した構造化課題である。文章からその特徴を抽出できたと数えない。

標準は依存課題5族×2置換と構造化課題2つ。各課題は24訓練＋16選択検証＋8リスク調整＋16最終評価で、完全文脈は四集合で分離する。少標本5課題は訓練だけ8。相関で区別できない2課題は8/4/4/8で、別の8教師を追加した後も測る。真の依存や完備化表は評価側だけが持ち、学習器へ渡さない。

SSはD512/2048×二符号、記号的対照は次元・符号で重複させず実行。主要630条件、曖昧性での固定総係数追加48条件、ゼロ重み5条件、合計683学習条件を評価した。候補の選択、学習重み、経験的な受理閾値を最終評価正解で変更しない。

「選択なし」は全6特徴を使う。選択ありは教師付き検証を利用するため、その追加教師の効果を表現方式と混同しない。hybrid3の項数は全6特徴なら41で、正解を見て項を選んでいない。重みはクラス別の位相平均であり、v0.10のバンク・対証拠方式のままではない。

## 3. 完全入力での成績

以下は標準の依存課題5族×2置換、D2048、二符号合計320要求。数値は独立calibrationで調整した閾値を適用した後の「正答 / 誤答 / 保留」。

| 表現 | 特徴選択なし | 特徴選択あり |
|---|---:|---:|
| 加算型 | 111 / 0 / 209 | 130 / 0 / 190 |
| 積結合型 | 0 / 0 / 320 | 320 / 0 / 0 |
| hybrid3 | 130 / 3 / 187 | 320 / 0 / 0 |

積結合型が全特徴のまま未学習の完全文脈を読めないことと、適切な特徴へ絞ると読めることは別である。「積を使えば学習できる」「和にすれば特徴選択が不要」とは結論しない。

加算型の選択ありは、単項64/64、AND34/64、切替32/64が正答で、残りは保留。XORと3項パリティは各0正答・64保留だった。この実装のクラス平均・閾値の結果であり、ANDや切替一般についての表現不可能性を意味しない。単純な加算＋線形判定でXORを完全識別できない点は、別の完全真理値表による単体テストでも確認した。

構造化した主客交換では、選択付き加算が16正答・16保留、積結合とhybrid3が各32正答。構造化した肯否・仮定は三方式とも32正答だった。

記号的対照でも、選択付き積結合とhybrid3は標準160/160、構造化課題32/32。記号的方式は一回、SSは二符号なので、要求数の違いを成績差と解釈しない。

## 4. 意味情報を削除した場合

一つの特徴を削除した部分文脈を重複除去し、全特徴なしも加えた。評価側は残った情報と矛盾しない全ての完備化から可能なラベル集合を作る。一意なら正答を採点し、複数なら一ラベルへの確定はどれでも「根拠不足の誤確定」とする。隠れた元の答えに偶然合った確定を正答にしていない。

標準依存課題、D2048、二符号の計1,750照会には、一意に決まる1,262照会と、複数の答えが成立する488照会が含まれる。

| 選択付きSS方式 | 正答 | 誤確定 | 保留 | 一意な照会での正答率 |
|---|---:|---:|---:|---:|
| 加算型 | 553 | 14 | 1,183 | 43.82% |
| 積結合型 | 1,114 | 0 | 636 | 88.27% |
| hybrid3 | 1,262 | 114 | 374 | 100% |

この表の誤答は全て複数解が成立する入力への確定だった。hybrid3は積結合型より一意な入力を148件多く正答した代わりに、曖昧な入力へ114件確定した。閾値は完全入力で調整したままであり、欠落入力での経験的リスクを保証しない。

記号的な選択付き積結合は557正答・0誤確定・318保留、hybrid3は631・57・187。SSの二符号合計の半分と一致する主要な傾向であり、問題の全てを位相干渉のせいにはできない。

構造化主客・肯否・仮定の欠落354照会では、選択付きSS積結合は212正答・0誤確定・142保留、hybrid3は226正答・68誤確定・60保留だった。こちらでも、部分的な特徴一致を完全な意味の十分な根拠とすることに問題が残った。

## 5. 数値座標だけを減らした場合

完全な文脈を符号化した後、ランダムな座標を削除する。欠測を示す観測マスクは補助情報として与え、観測座標数で相関を正規化する。ゼロ値から欠測を推定した実験ではない。

標準依存課題・選択ありの結果。観測率1/2と1/8は二つのマスクを使うため、各Dで二符号×二マスクの640要求となる。

| 方式 | D | 全観測：正答 / 誤答 / 保留（320要求） | 1/2観測（640要求） | 1/8観測（640要求） |
|---|---:|---:|---:|---:|
| 積結合型 | 512 | 320 / 0 / 0 | 640 / 0 / 0 | 640 / 0 / 0 |
| 積結合型 | 2048 | 320 / 0 / 0 | 640 / 0 / 0 | 640 / 0 / 0 |
| hybrid3 | 512 | 320 / 0 / 0 | 634 / 0 / 6 | 592 / 0 / 48 |
| hybrid3 | 2048 | 320 / 0 / 0 | 640 / 0 / 0 | 632 / 0 / 8 |

全消去は全方式で保留した。加算型は元から組合せ課題を読めないため、座標を維持しても完全な回答にはならない。

この結果は、積結合でも数値信号の部分相関が成立し得ることを、今回の小規模・選択済み特徴の条件で示す。誤答ゼロの一般保証、任意の雑音への頑健性、P1やS1との接続完了は意味しない。連続欠測、同期ずれ、周波数ずれ、チップ列伝送は試していない。

## 6. 少標本・未登録・複数候補

少標本5課題、D2048、二符号160要求の選択付きSSでは、積結合とhybrid3が各128正答・0誤答・32保留。選択なしでは加算が69正答・12誤答、hybrid3が61正答・17誤答、積結合も1正答・7誤答を出した。未学習キーへのランダム相関を絶対に受理しない実装ではない。

初期の相関で二特徴を見分けられない2課題では、選択付きの三表現ともD2048二符号32要求を全保留した。各課題へ別の8教師を追加すると全32正答になった。選択なし加算は追加前20正答・11誤答・1保留、hybrid3は17・13・2であり、単純な重畳だけで不確実性が安全に扱えるとは言えない。

固定総係数の条件でも、D512/2048の各次元で三表現とも追加前32要求を全保留、追加後32要求を全正答した。候補数でDを分割するため、同一の数値係数予算での変化を調べられるが、メタデータや符号帳まで同じ全RAMではない。

全フィールドを明示的な未登録文字列にした試験は在庫検査で保留する。これはSS相関だけによる未知検出の成果ではない。ゼロ重み対照は標準依存課題5つの完全入力80要求を全保留し、意味不足・座標欠落でも確定を出さなかった。

## 7. 同回答数での補助比較

D2048第一符号と記号的対照の六方式を、特徴選択の有無ごとに比較した。正解を見ない固定ハッシュ順で受理回答を同数に間引くが、同じ入力集合とは限らない。

選択なしは積結合の回答数が0で、全21条件の共通の正の回答数がなく比較不能だった。全保留の方式を勝者としない。

選択ありは21条件中8条件が共通回答数0。残りを合計すると、完全入力は各136回答・全方式誤答0。意味不足は各581回答に揃えて、加算SS／記号が各19誤答、積結合SS／記号が各0、hybrid3 SS／記号が各39だった。これも全入力で同じ回答率・誤答率を達成する運用閾値を学習した実験ではない。

## 8. 費用

標準D2048の二クラス・一候補のSS重みは65,536 bytes。選択付き積結合・hybrid3は全20モデルで一候補だった。実行時の位相符号帳配列は65,536〜196,608 bytesを別に使用し、モデルメタデータも別である。

同じ二方式の記号的対照は、積結合が4〜16個、hybrid3が4〜52個の整数カウント成分を使う。JSONメタデータはそれぞれ約1.4〜1.8 KB、約1.4〜2.5 KBで、その中にカウント表を含む。整数カウント数とcomplex128のbytesを直接同じ容量とは呼ばない。この小規模課題でSSが省記憶だとは示せなかった。

特徴選択中の最大項キャッシュはD2048で積結合約82.6 MB、hybrid3約53.7 MB。保存されるモデル重みや全プロセスRSSとは別の一時配列である。

所要時間の主評価記録は二回目の実行と並行した値。実行時間・演算カウンタ・データ構造・数値係数を別々に報告し、一つの同一予算へまとめない。

全数値実行の終了後、単独プロセスで単項・XOR・3項パリティの第一置換、D2048・第一符号を各3回計測した。以下は各課題の3回中央値を取り、さらに三課題の中央値を取った値。選択付きの条件を示す。

| 表現 | SS学習（秒） | 記号的学習（秒） | SS照会（ms/要求） | 記号的照会（ms/要求） |
|---|---:|---:|---:|---:|
| 加算型 | 0.1110 | 0.0857 | 1.1643 | 0.0668 |
| 積結合型 | 0.1075 | 0.0411 | 1.3145 | 0.0300 |
| hybrid3 | 0.1484 | 0.2450 | 1.1376 | 0.0463 |

学習時間は特徴選択込み・calibration抜き。照会は符号帳を暖めた後の完全文脈入力で、SS側は数値符号化とパケット検証まで含む。純粋な内積カーネル同士の速度比較ではない。この実装ではhybrid3の学習だけSS側が短かったが、照会は三表現とも記号的対照が短かった。全12方式の生計測は `verification/BENCHMARK.json` に保存した。全言語系・全RAM・総消費エネルギーの測定ではなく、正答や保留の改善と速度を同一視しない。

## 9. 検証・不具合修正の記録

新しい57テストで、XOR対照、候補保持と上限、追加教師、重みゼロ、未知値境界、情報不足の採点、数値パケット、厳密指紋、係数許容差と離散的判断を確認した。

本評価は683学習条件で12,068項目を検査し、全項目を通過した。内訳は分割整合1、候補数契約683、会計10,782、消去・ゼロ重み対照602。12,068種類の独立能力を証明したという意味ではない。

実装中に二つの不備を是正した。

1. 最初の凍結実行は、少標本学習にない特徴値が選択検証へ現れたとき例外終了した。学習在庫は増やさず、未知値を保留として検証・calibrationへ数えるよう修正。データ・閾値は変更しなかった。
2. 次の二回の全数値実行は一致したが、配布検証がunittestのstderr出力を読めず停止した。検証器のログ処理だけを修正し、凍結に検証器も含むため改めて全数値実行を繰り返した。

修正前ソース・凍結・中間の一致記録は `verification/failed-freeze-1/` と `pre-verifier-fix/` に残す。失敗や中間成果を最終成果に読み替えない。

最終的な凍結で結果JSONと三モデルの6ファイル、計7ファイルが二回の全数値実行でbytes一致した。時間・環境のPERFORMANCE.jsonは一致対象外。検証器のログ修正前後も、凍結識別とその結果digestを除く全数値結果が一致した。

配布前のstrict検証では57テストが合格。評価器・完備化oracle・旧重みを渡さない隔離再学習で三モデルの係数差は0、厳密指紋が一致し、104＋55＋55＝214入力の離散的判断も一致した。学習器とデータを除いた復号専用環境で全観測／半観測／全消去の数値パケットと不正パケット拒否を確認した。

- ソース凍結SHA-256：`c2e1b8662f818257a616014dc6daadc62bece4eef32870cde8529c5f3b9bc7fc`
- 結果digest：`b5942654b2407d873fc49aee49993ecb03ddd44b62c7acae299129db39dd0109`

詳細は `verification/REPEATABILITY.json` と配布前の `verification/strict/VERIFICATION.json`、ZIP実展開後の外側 `PLM-L1-v0.11-VERIFICATION.json` を参照。結果digestはJSONファイルそのもののSHA-256とは別である。Linux実機検証ではない。

v0.10は無改変のまま、その版自身の47テスト・隔離再学習・819入力の機能比較を今回再実行して通過した。v0.10の全数値評価を今回繰り返したものではない。さらに古い版群のテストは今回繰り返していない。旧成果物4,822ファイルをハッシュ照合で保全した。

## 10. 採用判断と次の課題

v0.10の言語コアは維持する。加算だけへの置換、hybrid3への全面置換、候補保留規約の緩和は行わない。

次に検討するなら、意味情報が欠けた照会で「残る手掛かりだけで答えが一意と判断できるか」を、学習済み記憶から検査する方法が先になる。今回の評価側完備化表を実行時へ移すのは、未知の正解を学習器へ与えることになるため解決策にはしない。

その後、固定した表現・受理規約で位相量子化と疎化を別々に評価できる。数値座標の欠落に強いことを、スパイクの沈黙・意味の不明・通信上の欠測が全て同じだという主張へ拡張しない。

P1/S1統合、スパイク・STDP・固定7スロット、新しい自然文処理、Linux実機、R1推論・Concept更新は未実施。`eligible_for_inference=false` を維持する。
