# PLM-L1 v0.13 実施報告

未確定な依存関係の保持と追加教師の能動選択。実施日：2026-09-08。

## 1. 結論

学習例に合う最も単純な依存へ直ちに絞らず、最大3特徴までの整合する依存候補と、その未観測セルを保持する機構を実装した。その記憶から追加教師を求める入力を選び、一件の回答を受け取って再学習し、保留から回答へ移る過程を検証した。

初期教師だけでは区別できない二世界のうち、隠れた依存がある世界では、標準SS条件の各試行で追加教師1件後に未使用の完全入力27件を全正答した。2符号×2取得seedの合計は108正答・0誤答・0保留。同じ初期教師と未ラベルプールを使うランダム選択は、追加1〜4件では84正答・0誤答・24保留だった。

一方、最小依存だけへ絞る対照は、追加前から84正答・24誤答・0保留となった。候補保持の効果は「知らない依存を知っていたことにしない」点、能動選択の効果は「その保留の解消に役立つ教師を先に求める」点に分けて確認できた。

これは有限の人工課題上の実証である。SSと通常の対応記憶は全384比較で同じ離散的結果となり、SS固有の精度・教師効率の優位性は示せなかった。全SS化、任意の未知規則発見、自然文の読解・生成への接続、P1/S1接続は今回の成果に含めない。

## 2. 前版から変えたこと

v0.12は選択済みの依存と学習済みキーの裏付けに基づく拒否専用ゲートだった。選択した依存の外に未知の依存がある場合、それを除外できないという限界を残した。

v0.13はv0.12の重みへ別のゲートを追加するのではなく、独立した構造化学習器・記憶器として次を実装した。

1. 最大6個の二値語彙特徴から、1〜3特徴の全ての依存集合を検査する。最大41候補。
2. 訓練例に矛盾しない候補を全て残す。未観測キーは全既知ラベルを可能性として持ち、否定やゼロへ埋めない。
3. 全候補・全入力補完が同じ一ラベルを支持する場合だけ回答する。学習不足と入力不足は別フラグにし、併存も許す。
4. 未ラベルプール上の候補票の不一致と未知率から追加教師を選ぶ。未知セルはラベルへの均等票にするため、既知の予測同士が食い違う入力だけに対象を限定しない。
5. モデル指紋と選択結果を照合し、正当な教師回答一件だけを追加して再学習する。古い要求・改変要求・在庫外ラベルは拒否する。

候補の整合性検査、補完列挙、教師管理、選択順位、回答制御は通常のPython処理である。SSが担当するのは、候補ごとの観測キーとラベルを位相積・加算で記憶し、相関から照会する部分である。SS保存モデルには観測キーの正確な対応表を入れないが、特徴マスク・語彙・ラベル在庫等のメタデータは残る。

SSの相関値、候補票、Gini型選択スコアは確率ではない。同じ規則を複数候補が重複して表す場合もあり、選択スコアは厳密な期待情報利得でもない。仕様・式・CLI契約は `SPEC.md` と `README.md` に記載した。

## 3. 教師・評価の分離

全16課題を用意した。依存課題5族×2置換が10、構造化した主客・肯否／仮定が2、初期情報の同じ単純世界／隠れた依存世界が2、仮説範囲外の4特徴パリティが2である。

通常課題は初期教師24件、未ラベルプール16件、最終評価24件。二世界は21／16／27件。完全な文脈は三集合間で重複させない。射影された意味キーは重なり得るため、既知の意味部品の新しい組合せを試す設計であり、未知語彙・未知自然文の試験ではない。

選択器へ渡すプールは `id / context` だけで、labelやoracle等の追加項目を拒否する。IDもラベルを含まず文脈から作る。人工教師役は選ばれたIDのラベル一件だけを回答する。最終評価の入力・正解は選択・学習に渡さない。

今回の教師は評価器内の人工教師であり、人間に実際に質問した実績や外部の教師データを収集した実績ではない。CLIから人が一ラベルずつ答える受け渡しは実装・隔離検証済みだが、誤教師・応答不能・費用の異なる教師は主評価に含めない。

追加教師のcheckpointは0・1・2・4・8・16件。同じ取得過程内のcheckpointは独立試行ではない。SSはD512／2048×2位相符号×2取得seed、記号的対照は2取得seedで、all/active・all/random・minimal/activeを比較した。全480取得過程、2,880 checkpointである。

前版の選択検証・calibration教師セットは用いず、今回の初期教師＋選ばれた追加教師だけを使う。したがってv0.12の数値との直接差を、同一教師予算での改善量とはしない。

| ---: | ---: | ---: | ---: |
| 0 | 84 / 0 / 24 | 84 / 0 / 24 | 84 / 24 / 0 |
| 1 | 108 / 0 / 0 | 84 / 0 / 24 | 84 / 24 / 0 |
| 2 | 108 / 0 / 0 | 84 / 0 / 24 | 84 / 24 / 0 |

| 8 | 108 / 0 / 0 | 96 / 0 / 12 | 96 / 12 / 0 |
| 16 | 108 / 0 / 0 | 108 / 0 / 0 | 108 / 0 / 0 |

候補を一つへ早期に絞ると未知の反例に気付かず、誤確定を続けた。全候補方式はその箇所を保留でき、能動選択は候補を区別する教師を先に求めた。この最終分割では、初期21教師に一件加えた22教師から27件の独立な完全入力を全正答した。

開発用の別分割では全正答まで能動選択4件、ランダム選択8件を必要とした。最終分割の「一件」は一般的な必要教師数の保証ではない。二つの取得seedや位相符号の反復も、独立した多数の世界を試したことにはならない。

対となる単純世界も全候補方式の追加前は84正答・24保留で、能動一件後に108正答となった。こちらでは最小候補方式が初めから108正答する。つまり候補保持は、世界が本当に単純な場合にも慎重さの代償を払う。

全30組の二世界対照で、教師回答前のモデルと最初の要求は一致した。学習器が未観測の世界の真相を先に参照して分岐したものではない。全プールを使用できた140組の能動／ランダム対照では、最終教師集合と学習された対応記憶の指紋が一致した。取得順を含む全モデル指紋の一致は要求していない。範囲外20組は取得停止のため、この比較から除いた。

全候補保持は初期に36件の回答を余分に保留する。能動一件でそれを回復したが、最小候補方式より常に教師効率が良いわけではない。隠れた依存への備えと、単純な課題での速い確定を区別して評価する必要がある。

構造化した主客・肯否／仮定の完全入力192要求は、全候補方式も追加前から全正答した。この二課題では追加教師の利得はなかった。固定予算比較のため、解けた後も教師を取得している。仮説範囲・プールの枯渇以外の、費用に応じた最適な取得停止規則は未実装である。

## 6. 入力不足と学習不足

部分入力は最終評価文脈から一特徴を除いた入力を重複除去し、空入力も加える。真の可能ラベルを評価側だけで求め、複数解がある入力への確定は、隠れた元の正解に偶然合っても誤確定とする。

以下もSS D2048・2符号×2取得seed、全候補＋能動選択。追加前／追加一件後の「正答／誤確定／保留」を示す。

| 課題群 | 部分入力要求 | 追加前 | 追加一件後 | 真に複数解の要求 |
| --- | ---: | ---: | ---: | ---: |
| 標準10課題 | 4,864 | 3,384 / 0 / 1,480 | 3,528 / 0 / 1,336 | 1,336 |
| 主客・肯否／仮定 | 1,000 | 640 / 0 / 360 | 640 / 0 / 360 | 360 |
| 単純世界 | 508 | 336 / 0 / 172 | 432 / 0 / 76 | 76 |
| 隠れた依存世界 | 508 | 336 / 0 / 172 | 408 / 0 / 100 | 100 |

この分割では追加一件後に、一意に答えられる部分入力を全て正答し、真に複数解が残る入力は保留した。「教師を増やせば欠けた入力も全て確定する」という動作ではない。

ただし保留理由は学習された候補に基づく診断で、真の原因を知るoracleではない。例えば二世界は初期予測・診断が同じなのに、真に曖昧な要求数は76と100で異なる。「学習不足」のフラグが真の世界の因果的説明と常に一致することは保証しない。

## 7. 範囲外・SS対照・ゼロ重み

最大3特徴という仮説範囲外の4特徴パリティ二課題では、初期教師に矛盾しない候補がゼロとなった。SS D2048の完全入力192要求、部分入力976要求は全て `hypothesis_family_exhausted` で保留。要求上限を16件としても実際の追加教師は0件である。

これは範囲外課題の学習成功ではない。また、今回の範囲外課題を検出できたからといって、任意の範囲外規則を初期教師だけから必ず検出できるわけでもない。偽の小規模依存が観測例に一致したまま残る場合がある。

SSの全384取得過程について、対応するexact対照と、選択した教師ID・教師ラベル・候補集合・各checkpointの値／保留理由／可能ラベルが一致した。D512もD2048と同じ離散的結果である。位相係数や時間の同一性を意味せず、SSによる独自の精度・教師効率の優位性を示す結果でもない。

別枠の実ゼロ重み対照5件と単体テストでは、HをゼロにしたSS照会が正しい対応表へ迂回せず、裏付けなしとして保留することを確認した。一方、低次元・大容量・雑音下の一般的な誤ヒット保証は今回評価していない。訓練整合性の候補採否は通常処理なので、ゼロ重み対照の成功を「全判断がSSで行われた証拠」とはしない。

## 8. 容量と時間の費用

標準D2048の初期全候補方式は候補数1〜16、中央値5。複素重み配列は65,536〜1,048,576 bytes、中央値327,680 bytesだった。最小候補方式は一候補、65,536 bytesである。初期全候補方式のメタデータは755〜1,755 bytes、温まった位相原子キャッシュは196,608〜393,216 bytesで、重みとは別に必要になる。

隠れた依存世界は初期16候補・1,048,576 bytesから、能動一件後に一候補・65,536 bytesへ縮小した。候補保持の費用は一定ではなく、学習によって減る場合がある。ただし全候補の列挙・整合性検査自体は再学習時に行う。

本評価二回は並行実行したため、その計時だけで方式の速度差を判定しない。完了後、単独プロセスで三課題の初期状態を各3回測った補助結果が次である。各課題内中央値を取り、三課題の中央値を掲載。単位はms、D2048、最初の符号seed。照会は完全入力、位相原子キャッシュを温めた状態。

| 記憶／保持 | 学習1回 | スカラー照会1件 | バッチ照会1件換算 | 能動選択・16入力 | ランダム選択・16入力 |
| --- | ---: | ---: | ---: | ---: | ---: |
| SS／全候補 | 10.611 | 5.475 | 0.250 | 6.546 | 0.199 |
| SS／最小候補 | 3.525 | 0.117 | 0.013 | 0.490 | 0.203 |
| exact／全候補 | 3.122 | 0.881 | 0.085 | 1.972 | 0.204 |
| exact／最小候補 | 3.115 | 0.032 | 0.010 | 0.401 | 0.197 |

SSのスカラー照会は呼出しごとに有限キーの相関回復表を作る。バッチではその一時表を共有できるため、一件換算の費用が小さい。観測キーの正解表を保存・参照した結果ではない。

この小規模測定ではSSがexactより速いとは示せなかった。表の選択時間は選択器単体で、教師の回答待ち・要求再検証・再学習までの全費用ではない。重みbytesも全プロセスRAM、セッション教師保存、一時配列、電力を含まない。最大41候補の負荷試験や同一総メモリ予算での優劣は未検証である。原記録は `verification/BENCHMARK.json`。

## 9. 検証と再現性

- 新規54単体テストに合格。独立した完全規則の列挙によるexactの照合、未観測セル、部分入力、範囲外、全候補未知の教師選択、教師漏洩を防ぐ入力契約、古い／改変要求、保存復元、係数摂動を含む。
- 本評価の21,128検査に合格。内訳は整合性1、対照2,887、契約12,480、会計5,760。多数は反復された契約・集計検査であり、21,128種類の独立能力ではない。
- 最終凍結後に本評価480過程を二回実行。結果JSONと五つの保存セッション／モデルの計16ファイルがbytes一致。環境・計時を含む `PERFORMANCE.json` は対象外。
- 評価器・未取得教師・最終正解を除いた隔離環境で五モデルを再学習。係数差0、厳密指紋一致、計764文脈の離散予測と教師選択が一致した。
- 学習器と教師管理器を除いた予測／選択専用環境でも、モデル＋構造化入力／未ラベルプールだけで動作した。観測済み教師を必要とするセッション更新とは検証境界を分けた。
- 隔離環境の一教師更新は保存済みhidden-b1と一致。古い要求は終了コード2で拒否し、指定した出力先を作らなかった。
- v0.12自身の97テスト（同版40＋継承57）と四モデルの隔離再学習を別途実施し合格。891文脈×4ポリシー＝3,564判断が一致した。v0.12の295モデル全評価、v0.10以前の全テスト・数値評価は今回再実施していない。
- 従来成果物4,993ファイルをハッシュ照合し、変更なし。v0.12 ZIPと、その中の位相代数の同一性を確認した。共有履歴だけを末尾追記の対象として分離した。

## 10. 保存モデルで確かめられる例

`examples/query.json` は初期教師にも未ラベルプールにもない最終評価の一文脈である。`results/hidden-b0/model` では16候補、候補の未観測セルが残り、`value=null / learning_insufficient`。能動教師一件後の `results/hidden-b1/model` では一候補、`value="0" / accepted` になる。

この教材で最初に求める教師IDは `963ab058b51ccf5cf89a`、教師回答例は文字列 `"0"`。教師回答は `examples/EXPECTED.json` に分離し、選択器へ渡すのは `examples/pool.json` だけとする。要求生成と教師回答のCLIはREADMEに掲載した。全16教師後のモデルも保存した。

一教師後も `eligible_for_inference=false` を維持する。ここでのacceptedはこの構造化分類部品の受理であり、R1推論や文章生成システムの安全な運用開始を許可する値ではない。

## 11. 残る課題と次段階

今回の部品は、設計した特徴・語彙・ラベル・最大3項の範囲で動く。特徴の自律発見、範囲外仮説の自動追加、誤教師への頑健化、教師選択の最適性、信頼度の確率校正は未実施である。学習は追加教師を得た後のバッチ再学習で、SS演算だけのオンライン学習・スパイク・STDPではない。

次の優先候補は、既存の二事象の読解・意味保持生成へ、この「学習不足の保留→必要な教師の要求→再学習」を限定接続する実証である。例えば肯否と仮定、主客、時間関係のうち一つだけを対象とし、追加前に勝手な意味や文章を確定せず、選ばれた文章・意味対を教えた後で正しく往復できるかを測る。教師の意味ラベルから文章教師対への変換が新しい設計課題になるため、今回接続済みとはしない。

当面はv0.10の既存言語系を維持し、全体の置換やR1開放を行わない。P1の数値部分観測・S1のチップ列／同期経路との接続も未実施である。SS中心の言語処理系という方向は維持するが、本版の効果のうち候補制御によるものとSS記憶によるものを引き続き分けて評価する。
