# PLM-L1-SS-core v0.2 技術仕様

## 1. 目的と境界

SS記憶の読出しデータが乱れたとき、誤差更新によって記憶を損なう危険を減らす最小比較実証。2事象・指定2項目の外部教師による訂正を対象とし、更新後の保存、再ロード、後続学習、意味保持生成まで評価する。

Python/NumPyの離散時間I/Qシミュレーションであり、実回路、連続時間装置、汎用言語処理、全層SS実装ではない。既存SS記憶は元から位相符号の結合・重畳を使っている。今回追加するのは再観測、更新案の検査、回答値を含まない保留台帳である。

既存 `ss_core/`、L1/P1/S1、言語モデルを変更せず、新コードを `ss_core_v02/` に分離した。通常の意味符号化、候補判定、版管理、原子的なソフトウェア更新、語順指定は引き続きPython制御を含む。推論用コードに評価の正解を渡さない。

## 2. 四つの比較方式

| 方式 | 更新前読出し | 更新案の読出し | 意味整合ゲート |
|---|---:|---:|---|
| single | 1 | 0 | なし。前版と同じ更新式 |
| mean4 | 4を平均 | 0 | なし。単純な反復平均 |
| unchecked | 2を平均 | 2 | 記録するが受理判断には使わない |
| guard | 2を平均 | 2 | 更新前・更新後の整合を検査 |

全方式が既存パイロット・完全観測・書込み完了・古い状態からの確定防止を利用する。uncheckedでも窓そのものが未完了なら保留する。「意味ゲートなし」であって、全安全検査を無効にする対照ではない。

mean4/unchecked/guardの正常完走時の読出し予算は同じ4窓。guardが途中で保留した場合は消費量が減るため、予算上限だけでなく実際の処理tickと書込みack数も記録する。singleは低コストの基準で、予算が等しい比較とは扱わない。

## 3. 観測と誤差更新

各読出しは既存の頭16＋データ736＋尾16=768tick、4チャネル。既知の文脈符号Cと候補符号Vに対し、現在到着した係数列だけを相関積算する。窓終端までスコアは確定しない。照合は全23ラベル、4チャネルについて行う。

更新前2窓のスコアをS0、S1とし、guardでは以下を要求する。

```text
sqrt(mean((S0-S1)^2)) <= 0.15
S = (S0+S1)/2
e[l] = teacher_one_hot[l] - mean_channel(S[:,l])
delta[:,j] = sum_l(e[l] * V[:,l,j] * C[:,j])
W_candidate[:,j] = W[:,j] + delta[:,j]
```

新しいnonceを使うたびにportを新たに呼び、別窓の数値サンプルを受け取る。同じ受信配列を二度計算して独立照合と呼ぶ設計ではない。ただし、nonceの違いが雑音の統計的独立性を保証するわけではない。評価には独立雑音と共通雑音の両方を含む。

誤差更新は1列ずつ候補23個を加算し、一時領域へ書く。旧一括スコア関数に戻ることはない。教師と古い記憶の一致は前提にしない。正しい外部訂正を「古い記憶と違う」と拒否しないよう、読出し同士の整合と更新案の教師整合を分ける。

## 4. 更新案の検査

更新案を配列上の一時記憶として、別の2窓で再読出しする。更新前の観測値を検証用に再利用しない。

- 更新後2窓の全候補スコアRMS差が0.15以下。
- 2窓平均を既存の候補受理方針に通し、外部教師の値が受理される。
- 教師one-hotと平均スコアのL2誤差が `max(0.15, 更新前誤差×0.85)` 以下。

候補受理は既存の平均スコア0.5、余裕0.15、4チャネル中3票等を維持する。校正済み確率ではない。候補基底は同一であり、別符号系で記憶を二重化した実装ではない。

検査は各対象・各区画の更新時点で行う。後の対象更新による再干渉や、全ての既存記憶の保持を一般に保証する検査ではない。そうした影響は最終生成と後続学習後の評価でも調べるが、有限の照会に限られる。

## 5. 原状保持と保留台帳

2項目の教師取込みは `RevisionMemory` のコピー上で行い、どこかで保留すれば元の学習係数・登録集合・版番号を返す。書込み窓の未完了、ack欠落、更新中の状態変化にも同様に対応する。物理的な書込み確認、マルチスレッドロック、ディスク電源断からの回復までは実装していない。

重要な追加は `Store` のpending台帳である。訂正を保留して古い記憶だけを残すと、後の新規照会で古い値を断定し得る。そのため、全比較方式共通で対象scopeの「要再確認」を永続化する。

保存物は次の構成。

```text
store/
  pending.json
  memory/revision.json
  memory/ss/state.json
  memory/ss/weights.npz
```

pendingにはepisodeと対象項目集合から計算したハッシュだけを保存し、教師値・正解文・意味ベクトルを保存しない。失敗時にSS記憶は不変でも、Store全体のフィンガープリントはpending追加によって変わる。

生成前にpendingを確認し、該当scopeは `needs_confirmation` として文章を出さない。新しい正常な外部教師を受理したときにだけ解除する。この効果は通常メタデータの制御であり、SS相関だけの誤り抑制と混同しない。

scopeはepisode＋対象項目集合で識別する。同じepisodeと対象集合を異なる固定文脈へ使い回すと、保留が広く及ぶ可能性がある。呼出し側はepisodeを区別する必要がある。台帳や保存ハッシュは送信者認証ではない。

## 6. 故障モデル

故障注入は `evaluation/faults.py` だけに置く。受信器へ真の雑音、condition、正解スコアを渡さない。

| 条件 | データ区間への注入 |
|---|---|
| clean | なし |
| independent1/4/16 | 各窓で別の複素ガウス雑音。実部・虚部それぞれの標準偏差1/4/16 |
| pre_shared16 | 更新前の窓では共通雑音、更新案の読出しでは雑音なし |
| shared16 | 更新前後を通じ、同じキー・区画には同じ雑音を加える |
| coherent_bias | 教師候補の結合符号成分を、全読出しへ同じ振幅で加える構成的反例 |

パイロットは主比較では正常。coherent_biasは正解を知る評価器が、検査の限界を見るため意図的に作る最悪条件であり、自然雑音の頻度モデルではない。注入用の教師値をランタイムの判定へ渡すことはない。

post_noise16、post_truncate、ack欠落、古い状態からの確定、偽教師などは単体試験で追加検査する。

## 7. 意味保持の測定

主比較では焦点4場面の初期値を保存し、明示的な新しい教師で2項目を訂正する。対象は主体・対象・行為・肯否・仮定・時間関係を含む。更新直後の保存→再ロード後に対象を照会し、別の後続教師2件を取り込んで再保存→再ロードした後に対象と既存の別場面1件を照会する。

各照会で順序保持・主体焦点と、逆順・先頭対象焦点の2文書を実際に生成する。独立の限定文法パーサーで事象・時間関係・順序・焦点を比較し、既存モデルの再読も併用する。

`committed_but_target_not_correct` は、更新を受理したのに、直後または後続学習後の対象照会が正しく生成できなかった試行数。誤文書だけでなく生成保留を含む。この値をそのまま「誤った文章を出した件数」と呼ばない。保留した正しい教師の数、誤文書数、既存場面の保持も別に示す。

保留台帳は全方式共通。評価時の正解は採点専用で、生成器も更新ゲートも参照しない。既存場面を一つ保持できたことで全記憶の保持を保証することはできない。

## 8. 費用と残る限界

既存の永続SS学習係数は94,208 byteで同一。候補基底2,166,784 byteと文脈キャッシュ、既存L1モデルは別。追加のスコア配列、更新案、文書単位のdeepcopy、pendingメタデータ等のRAMが必要であり、省メモリ実装ではない。

protectedな2項目訂正の正常完走は、singleで読出し3,072＋書込み2,944=6,016tick、他の3方式で12,288＋2,944=15,232tick。説明用8,000tick/sなら0.752秒対1.904秒相当。外部転送や言語処理を除いた設定上の換算であり、実測ハードウェア性能ではない。各試行の消費量を結果に保存する。

共通の破損は複数窓で一致してしまう。誤った教師も、整合した形で入力されれば学習できる。pending台帳は検査が保留したものにしか効かず、検査を通過する一貫した破損を防ぐものではない。今回のgateに完全な安全保証を与えない。

## 9. 固定・再現

開発時に定めたしきい値は開発結果を見て変更せず、本評価前にsource/model/dataとプロトコルを凍結した。開発試験では一部条件で基準方式が失敗しなかったため、優位を示せない判定も残した。結果をよく見せるために評価場面や乱数を再抽選しない。

前版で保留された外部S1の1件を修正する実験ではない。今回の主比較は外部P1/S1を正常条件で接続し、その後の内部記憶読出しに故障を注入する。前版の全受信成功基準がこの版で自動的に達成されたとは扱わない。
