# コーパス・評価の読み方

## 固定データ

`data/WORKING04_CORPUS.json` は開発4件、回帰24件、拡張16件。回帰はv0.3の既存評価文であり、今回新規の未知テストとは呼ばない。拡張は固定seed 90404で作り、以前の開発/評価28文との文字列重複がないことを検査した。

拡張16件では、一事象の状態「肯定通常・肯定仮定・否定通常・否定仮定」の4通りを二事象で4×4にする。同じ肯否/法を持つ二事象も含む。人名・述語・時間関係は限定集合から選ぶ。全語彙×全時間関係×全出力順の巨大な直積ではない。

各40文を、提示順を維持し双方主語先行、提示順を反転し第1文目的語先行/第2文主語先行、の2様式で生成し計80要求とする。符号束の教師としてこれらの意味/文章を投入しない。ただし語彙・文法構成要素は既知であり、過去全履歴の意味組合せとの排他性は主張しない。

## 採点の分離

実行対象の入口は自然文→旧v0.3読解器→数値DocumentPacket→新WM→新生成器。評価器の正解意味は新WM/生成器へ渡さない。出力を別実装の限定言語パーサで解釈し、事象の全役割、出力順、時間関係、先行形式を比較する。回帰48件では保存済みv0.3統合版出力との文字列一致も別に確認する。

この別実装パーサも、同じ限定言語仕様を知るプログラムである。人間の独立注釈や自然文ベンチマークの評価ではなく、仕様の共通欠陥を排除しきるものではない。v0.3との比較は同梱 `data/V03_MAIN.json` の保存結果であり、このリリースで旧版を新たに80件走らせた比較ではない。

「正しく生成」はこの限定仕様における意味・形式の一致を指す。仮定を示す `もし…たら。` という条件節止めの形式も含むため、通常の日本語としての完結性・流暢さ・文章品質を高得点と認定したものではない。

## 局所訂正

回帰の同じ基準文から、12アドレスをそれぞれ独立に1回ずつ別値へ訂正する。対象の値が変わったこと、非対象11項目の状態/候補が不変であることを診断器で確認する。更新内部でも全11項目の信号照合を行う。保存再ロードした数値状態から、逆順生成も採点する。

これは12段連続改訂ではなく、12種類の対象への独立訂正試験である。長時間の蓄積更新、符号長や事象数を増やした容量試験は今回対象外。

## 未確定・障害

- unobserved / unreadable / ambiguous / conflict を外部注釈として1項目に与える4件。状態保持、生成保留、外部教師による解決、非対象保持、解決後生成を確認する。自然文から未確定状態を学習抽出した実証ではない。
- 内容ゼロ、状態ゼロ、余分候補、末尾欠落、語彙重みゼロ、文オペランド重みゼロ、文書操作重みゼロ、ドメイン証拠ゼロは保留を期待する。
- 一定位相回転0.73 radはパイロットによる補正後の正しい生成を期待する。
- 値符号は正規でも役割ドメインが違う教師は拒否し、一体APIが古い文章も返さないことを確認する。

固定された有限事例の通過であり、母集団の誤り率ゼロ、未知語の任意照会安全、物理通信路の耐性範囲を推定するものではない。

## 再現性

評価開始前にコード・データ・既存モデル・旧プログラム・新符号束・プロトコルを `verification/FREEZE04.json` へ固定した。実行開始/終了で指紋を確認し、2回の個票・受信窓ログ・保存信号の指紋を比較する。壁時計時間だけは比較から除く。旧v0.3の348ファイルとZIPを別途不変検査する。

固定後の実行基盤変更は2件ある。Windowsの隔離子プロセスが `-I` により環境変数の文字コード指定を無視したため、隔離検証ヘルパーに `-X utf8` を明示した。その後、全時間窓の逐次シミュレーションに時間を要したため、各事例の演算を変えず独立事例を8プロセスへ分配した。元の途中実行は指紋とログごと `verification/interrupted-run*` に保存し、最終評価は最初の事例から2回やり直す。

数値アルゴリズム・重み・閾値・データ・採点規約は不変。各事例に新しい受信器を作るため、パイロットnonceの範囲は事例単位となる。最終2回は同じ分割なので窓ログも比較できる。初回固定は `FREEZE04-initial.json`、文字コード修正後は `FREEZE04-encoding.json`、最終固定は `FREEZE04.json`。変更理由・旧ソースは `AMENDMENT04*.json` と保存ソースを参照。成績を見た閾値調整ではない。途中実行は最終の分母にも再現性の成績にも加算しない。
