# 開発段階での方式選択

初回開発比較を `results/DEVELOPMENT_INITIAL.json` に保存しました。4符号seed × 2チャネルseed、各条件64正例・128負例です。評価用seedはまだ実行していない段階で本書とソースを固定します。

| 方式 | 部分観測の回復 | 部分観測の負例誤受理 | 過負荷寄り条件の回復 / 誤受理 |
|---|---:|---:|---:|
| v0.1固定判定 | 64/64 | 1/128 | 18/64 / 40/128 |
| 原信号＋適応判定 | 58/64 | 0/128 | 3/64 / 1/128 |
| 干渉除去＋固定判定 | 64/64 | 0/128 | 0/64 / 0/128 |
| 干渉除去＋適応判定 | 64/64 | 0/128 | 0/64 / 0/128 |
| 2領域分割＋固定判定 | 64/64 | 0/128 | 34/64 / 23/128 |

採用は **干渉除去＋適応判定**。分割方式にも改善はありますが、現行符号・状態情報をそのまま保存できること、候補数・観測数・残留干渉を判定に反映できることを優先しました。干渉除去＋固定判定との開発スコアは同点であり、適応判定の一意な最適性や優越性は主張しません。

最初に設定したAdaptivePolicyは変更していません。家族誤差用alpha=0.01はガウス近似の工学的設定で、実際の誤受理率1%保証ではありません。未知評価結果に基づく閾値変更は禁止します。目標未達ならそのまま公表します。

v0.1既知失敗5件では、正例4件はすべて真値が首位でした。状態・述語由来の干渉が真値スコアを約0.22〜0.41押し下げ、負例誤受理では約0.45押し上げていました。新方式で5件とも回帰照合に一致しましたが、この結果は新規性能評価に含めません。

高負荷・観測不足での0誤受理は、すべて保留した結果です。これを回復能力の改善と読み替えません。新方式は公開語彙と公開アドレス名前空間の指定を必要とし、未知語彙や広すぎる候補空間には限界があります。
