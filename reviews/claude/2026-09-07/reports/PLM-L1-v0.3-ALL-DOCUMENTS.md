## 初期知識と自動導出

内容語の表面・語種・意味ID、意味5スロット、候補集合、内容語3役割をコピーしてmarkerを文字化する演算系は手設計。

最初に対応付いた内容語の役割を生成目標とする。学習時に別途goal/orderの正解は受け取らない。生成時のgoalは出力方針として利用者が指定する。
このような自動対応付けが可能な一意の学習例だけを受け付ける。教師なし学習や潜在状態の無制約探索ではない。

## Phase表現

初期符号はv0.1と同一のSHAKE256/u53に基づく単位複素位相生成（algebra.pyをバイト保存して再利用）。識別符号は固定乱数で、学習されるのは連想ベクトルの重み。
新生成器の標準次元8192。語順はprefix内の記号コードに位置依存の成分巡回置換roll(17*i)を適用してから結合する。

prefixキー = code(prefix-present) × Π_i roll(code(emitted_symbol, symbol_i), 17*i)

次記号の照会キー = prefixキー × code(goal) × code(polarity) × code(modality)

内容語の個体IDや動詞IDは次記号の構文照会キーに含めず、選択されたslotに対応する値を語彙記憶で表面化する。この分離は設計上の事前知識である。
キーはprefix全体を丸ごとハッシュしたものではなく、構成記号から位相演算で作る。ただし学習済みprefixを条件とする有限対応の学習で、未知構造への合成的一般化を保証しない。

## 3本の新しい連想記憶

- support：肯否・仮定・goalの対応が学習に現れたか。標準訓練で8一意キー。
- steps：状態条件と生成済みprefixから次のslot/literal/endへ。標準訓練で68一意キー、4896観測。
- lexical：初期内容語の意味IDから表面へ。10一意キー。文対学習を無効化しても保持する。

各キーの教師候補符号を頻度で平均し、H=Σ_k conj(k)×mean(target|k)で重ね合わせる。繰り返し例で振幅を水増ししない。
取得はH×query-keyと候補符号の相関。実部の平均が0.65以上、次点（少なくとも0）との差が0.25以上で採用する。相関は確率ではない。
モデル保存時は集計した対応表を破棄し、候補在庫・数値ベクトル・統計のみ残す。同一キーの数値計算結果は実行時にキャッシュする。
3×8192×16=393216 bytesが新生成器の圧縮前数値重み。読解器・候補符号・キャッシュ・メタデータ・プロセスの総メモリではない。

## 意味信号と実行境界

M=Σ_r code(semantic_role,r)×code(value,x_r)。5スロットの各値を役割逆結合と相関で回復する。最小相関0.65、余裕0.25、回復全slotの再構成に対する相対残差0.20以下が必要。
数値パケットはschema/writer_fingerprint/dimension/real/imag/eligible_for_inferenceのみ。原文・正解意味・trace等の追加項目を拒否する。
値は有限、成分絶対値32以下、指定次元と一致する配列。fingerprintは整合性検査であって認証ではない。
固定v0.2読解器との橋渡しは、読解信号を相関回復して新bookへ再結合する。旧生成器のコード・重みは使用しない。

生成の次記号は学習記憶の相関で選択する。slotを選んだ後の値参照、markerの文字化、役割の重複/欠損・先頭役割の検査、最大9語・256文字・通常12stepでの停止制御は通常のPython補助処理。
停止は学習記憶のend選択で行い、最大stepは異常時の保留上限である。未完成出力はtext=Noneとする。
これらの一般的構造ガードだけで日本語文法を保証するわけではない。誤った完成出力があれば独立採点で誤生成として数える。

## 何を教え、何を学ぶか

各学習例は `text` と `meaning` のみ。意味は主体・対象・述語・肯否・断定形/仮定形の5スロットです。`order`、`goal`、`actions`、`states`、役割位置や操作列などを例に付け加えると拒否します。

学習器が文中の内容語と正解意味を照合し、「主体に対応する語」「対象に対応する語」「そのまま出す表面記号」を自動で対応付けます。最初に現れた内容語の役割から出力目標も導出します。

## 生成時

生成器の入力は数値意味パケットと先頭に出したい役割（`subject` または `object`）です。
意味信号の回復、生成途中の抽象語列prefix、肯否・仮定、先頭役割から、次の出力記号または終了を相関で選びます。選んだ内容役割の語は別の語彙連想記憶から出力します。
生成時は自分自身の出力prefixを使い、正解prefix・原文・正解文章を参照しません。未知の対応・弱い相関・競合・役割の欠落/重複・停止失敗は保留し、不完全な文章を最終出力しません。
旧生成器、外部LLM、全文検索、手書きの日本語文法へフォールバックする経路はありません。

モデルには全文やprefix→記号の対応表を保存せず、数値重み・候補記号・公開語種・統計とハッシュを保存します。同一数値照会の実行時キャッシュは使用します。
有限の学習済みprefix対応を用いるので、未知構文への一般化を実証したわけではありません。

## 実行方法

Python 3.12.14 / NumPy 2.3.5で検証します。Python本体は同梱しません。ZIPを展開したPLM-L1-v0.3フォルダで実行してください。
出力名は未使用のものを指定します。既存のモデルとパケットは上書きしません。

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$env:PYTHONIOENCODING='utf-8'
python -B -m plm_l1_v03 train --pairs data/train.json --lexicon data/lexicon.json --out work/my-writer
python -B -m plm_l1_v03 read --model work/my-writer --text '太郎が花子を助けた。' --out work/meaning.json
python -B -m plm_l1_v03 generate --model work/my-writer --packet work/meaning.json --goal object
```

出力例：`花子を太郎が助けた。`。`--goal subject` は主体を先に出す目標です。
付属生成モデルは `--model results/writer` で利用できます。`read` コマンドは固定v0.2読解器で読み、意味信号を新生成器の符号へ橋渡しします。

生成器だけを試す場合、5スロットの意味JSONを用意して、次のように意味信号へ符号化します。この経路に読解器は不要です。

```powershell
python -B -m plm_l1_v03 encode --model results/writer --meaning examples/MEANING.json --out work/direct-meaning.json
python -B -m plm_l1_v03 generate --model results/writer --packet work/direct-meaning.json --goal object
```

保留時は終了コード2、形式誤りや既存出力への上書き要求は終了コード1。生成成功以外で完成文を捏造しません。
