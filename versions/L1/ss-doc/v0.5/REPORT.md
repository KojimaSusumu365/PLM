# PLM-L1-SS-doc v0.5 実施報告

## 結論

「SSの支持が弱い／入力と矛盾する箇所を再確認し、回答がなければ生成を保留する」仕組みを実装しました。外部回答は対象セルだけを訂正し、改訂付きSS記憶へ学習します。確認直後の生成と、回答履歴を外してSS記憶だけから再生成する成績を分離して検証しました。

高負荷の共有SS記憶で、各12文書ストリームの教師上限を24回とした4条件の合計は次のとおりです。

- 新方式：確認80回で48/48文書が正しく生成され、誤生成0、保留0。
- 全項目確認：確認96回で48/48文書が正しく生成。新方式の確認数は16回、16.7%少ない。
- 従来判定：確認43回で正しい文書36、誤った文書12。確認数が少なくても、古い既知値を通す誤りが残る。
- 新方式の保存・再読込後の冷間再照会：正しい文書47/48、誤生成0、保留1。全項目確認は48/48。

したがって、**今回の限定課題では、誤生成を抑えながら全項目確認より確認負担を減らせました。ただし、確認回数の節約と、その後のSS保持の完全性にはトレードオフが残ります。** 無誤生成や優位性の一般保証ではありません。

## 全比較結果

各行は2データ分割 × 2符号seedの4ストリーム、48文書です。「上限」は1ストリーム12文書全体への教師上限、「確認実数」は4ストリームの合計です。たとえば上限6なら合計上限は24回。実際の確認数を同数に強制した実験ではありません。

`legacy`はv0.4の受理方針を共通の再確認ループに接続した対照、`always`は毎回全対象を確認する対照、`ss_selective`が新方式です。実測の全18行は [SUMMARY.json](verification/SUMMARY.json) と照合しています。

共有＋保護では、新方式は上限6でも24回の確認で48文書をすべて正しく生成できました。全項目確認が48文書を生成する96回に対し75%少ない確認数です。ただし、この条件では従来判定も同じ成績です。ここを新方式固有の改善とは主張しません。

上限6の共有記憶では、新方式は誤りを0にしましたが、正しい生成も14/48にとどまります。従来判定の正しい生成24/48より少なく、全項目確認12/48よりは2件多い結果です。正答率だけでなく保留件数を含めると、教師予算が足りない場合の代償が分かります。

## 実際に生成した文章

読みやすい別枠デモでは、次の意味をSS記憶に保持しています。

> 太郎が花子を助けた。その後、由紀が健太を褒めた。

新しい入力は「2番目の出来事の主体は古い値の花子、対象は未観測」です。

1. システムは **「事象2の主体を確認してください。」** と質問します。
2. 外部から「由紀」と1回だけ回答します。
3. 対象の「健太」は追加回答を求めず、SS記憶から補います。
4. 次の文章を実際に生成しました。

> 太郎が花子を助けた。その後、由紀が健太を褒めた。

SS記憶を保存・再読込し、主体と対象の両方を未観測にした新規入力でも、教師回答なし・確認済み履歴なしで同じ文章を生成できました。[DEMO.json](examples/run/DEMO.json) に質問、数値更新監査、即時生成、冷間生成を残し、別プロセスのCLIでも同じ流れを検証しています。

旧失敗例の回帰では、例えば次の誤った生成を再現しました。

> もし美咲が花子を助けたら。その前に、花子が太郎を褒めなかった。

行為を1回再確認した後の出力：

> もし美咲が花子を見つめたら。その前に、花子が太郎を褒めなかった。

対象外の2番目の出来事や時間関係を変えずに訂正しています。旧失敗3例すべてで、従来の誤生成→新方式の再確認→1回の回答で正しく生成→回答履歴なしの冷間再生成、を確認しました。これらは [旧失敗回帰ログ](results/V04_FAILURE_REGRESSION.json) の別枠で、主評価48件の分母へ混ぜていません。

## 記憶に何が残ったか

新方式の共有記憶・上限24について、同じ両方欠測入力で比較すると、フィードバック前は48文書中1件が補完可能で、必要確認対象が73箇所ありました。フィードバック後の保存・再読込では47件が補完可能で、必要確認対象は1箇所に減っています。これは、異なる欠測条件の前後比較ではありません。前測定は意味補完のみで文章生成を行っていない点も区別しています。

残った保留は `d300-c1-versioned_shared-ss_selective-b24` の `q300/0`、事象2の主体です。その場の入力ではSS支持が十分だったため、確認0回で正しく生成しています。しかし後続文書への確認更新を経た冷間照会では、上位平均スコア0.543、差0.382でも、符号チャネルの一致が2/4となり、必要な3/4に達しませんでした。弱い候補を確定せず、再確認を要求したものです。

この1件を見て閾値を緩めたり、場面を入れ替えたりしていません。今後は、いったん十分だった記憶も後続更新によって弱まるという保持問題を、遅延再照会・追加教師の選択と合わせて扱う必要があります。

## 規模・生成採点・再現性

主評価は72条件 × 12文書 = 864エピソード、冷間864照会です。各々2通りの表現を要求し、それぞれ1,728文章要求。独立な焦点場面は24件で、これを方針・予算・符号条件を変えて繰り返しています。864の独立自然文を理解できたという意味ではありません。

新方式の全予算・両記憶構成を合計した主評価は、288件中183正、0誤、105保留。生成できた366出力は独立パーサの意味照合と再読解で一致しました。冷間は288件中206正、0誤、82保留で、生成できた412出力が一致しました。これらは試験条件を混ぜた記述集計であり、普遍的な精度の推定値ではありません。

比較方式を含む全主評価には従来判定による31件の誤りがあり、各2表現で62の誤出力として記録しています。非対象セルの変更およびSSだけによる既知セルの無断変更は全件で0です。[全件監査](verification/LOG_AUDIT.json)、[失敗全件](verification/FAILURES.json) を参照してください。

単体試験86件、旧言語生成144例を維持しました。全評価を別ディレクトリで最初からもう一度実行し、実行時間以外の327ファイルが完全一致しました。固定した実装・モデル・データ・評価条件のダイジェストは `bbceb106a0687997a20c5a995dc84d3d48393b1e722e5286bfed7d31fc052db8` です。

最初の検証で監査票の行順比較が失敗しましたが、作成時とJSON保存後の行順の差だけであることを確認しました。元票を保存し、非固定対象の監査票だけを並べ直しました。評価結果・固定ソース・モデル・データは不変です。[修復記録](verification/AUDIT_ORDER_REPAIR.json) に残しています。

検証の具体的範囲、最小ランタイムでの推論分離、保存記憶と数値配列の再計算、CLI、元版不変性は [VALIDATION.md](verification/VALIDATION.md) にまとめています。ZIP展開後の実検証はZIP外のPOSTZIP証跡で報告します。

## 達成したことと、まだ言えないこと

今回の達成は、SSの照合状態を文書生成の受理判断と再確認へ接続し、必要な外部回答をSSへ更新し、回答履歴を外した保持まで比較できるようにしたことです。

一方、SS照合スコアは正答確率ではなく、質問順位と質問文は通常の手続きです。質問の価値や言い方をSSで学習していません。信頼されたローカルの確認履歴を使い、世界の真偽や教師の正しさを検証する機能もありません。正しい形式の誤教師は学習され得ます。

対象は既存語彙・文型の2～3事象、外部指定された最大2つの訂正箇所です。自由長文生成、新語・新文法の獲得、P1/S1の物理的同期復調は追加していません。全処理がSSだけで実装されたわけではありません。また、今回の冷間評価は後続確認による干渉を含みますが、さらに新規背景を大量投入した後の長期保持は測っていません。

次の候補は「確認後の保持が弱まりそうな項目を見つけ、同じ教師コストで再確認・保持を改善する」実証です。質問方策のSS学習、誤教師、遅延干渉、多数seedを比較対象に含めると、本版から一段進んだ検証になります。これは次段階の提案であり、本版の実施範囲ではありません。
