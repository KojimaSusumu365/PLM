# PLM-L1-SS-core v0.3 技術仕様

## 対象

本版は「SS化境界の監査と、読解・生成の時間波形SSコアへの統合」。以前提案した適応的再照合／段階更新のv0.3案ではない。既存の二事象・既知語彙・限定文法を対象とし、言語能力を拡大した成績と、実行基盤を移した成績を区別する。

## 共通の受信演算

言語連想は1チャネル、行動／次状態記憶は2チャネル、既存訂正記憶は4チャネルで、同じ `waveform.Receiver` を使う。2チャネルは異なる内容の係数であり独立誤り訂正コピーではない。各窓は頭16tick＋payload N tick＋尾16tick。Nは既存バンクの幅、意味信号8192、生成プログラム8192、訂正記憶736などで異なる。

各到着tick jで、候補l、チャネルcについて次を加算する。

```text
A[c,l] += conj(V[c,l,j]) * received[c,j] * phase_correction[c] * demod[c,j]
score[c,l] = real(A[c,l]) / observed_count[c]
```

バンク記憶では `demod=key_code`、訂正記憶では `demod=conj(context)`、意味パケット復元では1。キーの向きは各既存学習式に合わせる。パイロットから一定位相を推定し、頭・尾の整合、tick順、欠損、有限値、呼出し前後の係数ハッシュを検査する。finish以前はスコアを返さない。

言語側はpayload完全観測を要求する。訂正照会は継承仕様の75%以上を使う。窓位置は既知であり、本受信器単独は未知の遅延・周波数探索を行わない。別の外部P1/S1経路の検証と混同しない。

元のSSバンクは重畳係数の照合に加え、キーと候補の対に対応する証拠係数も使う。両方を波形で読み、元の閾値・候補集合・バンク分割を変えずに候補を選ぶ。公開符号のキャッシュは持つが、照会結果のキャッシュは持たない。

意味パケット復元では、必要な公開候補基底を列挙し、同一の受信窓で並列相関する。その後の最大候補、候補数、状態、残差の判定は既存の手続きと同じ。コードブック、基底配列、受信器の相関蓄積はRAM上に置くため、ストリーミング化が省メモリを意味するわけではない。

## SS遷移記憶

文内プログラムは目標焦点・肯否・仮定と現在状態、文書プログラムは提示順・出力順指定と現在状態をキーにする。

```text
K = bind(context_fields) * state_signal
W_action += conj(K) * code(action)
W_next   += conj(K) * code(next_state)
```

教師遷移ごとに全tickへ加算する。実行時はW_actionとW_nextを同一の2チャネル窓で読み、行動と次状態をそれぞれ相関選択する。次状態の位相符号を帰還し、意味の確定しない候補は保留する。

文内は8種類の抽象的な表現条件から68遷移、文書順は4例から12遷移を転写学習する。文内教師は既存モデルの学習済み語順・助詞等の対応から作る。文書順教師は従来の明示仕様から作る。人物・動詞を含む完成文をプログラムのキーや値として保存しない。ただし構造の教師は外部から与えており、自律的な文法発見ではない。

追加の永続係数は各262,144byte、合計524,288byte。追加学習は655,360write tick、2チャネル合計1,310,720個の複素係数加算。実行用保存物は候補一覧等のメタデータと係数のみで、教師の行動列・文例一覧は保存しない。

文内行動は語彙照会、記号出力、停止。文書行動は事象選択、停止。行動の解釈器、文字列組立て、重複役割チェック、最大反復数、辞書上の意味スロット取得は通常コードとして残る。

## 評価と比較

同じ保存言語モデルを使う3方式：旧配列相関＋旧生成手順、波形相関＋旧生成手順、波形相関＋SS遷移生成。前者との表層・意味一致を移行の基準とする。後二者の差で、照合基盤の変更と生成手順の変更を分ける。旧モデルの回答キャッシュは旧基準でのみ使われ、処理時間や消費量の公平な優位比較はしない。

`SUMMARY.json` の旧方式のtick／windowの0は「本計測器の対象外」というプレースホルダであり、旧方式が無演算という意味ではない。新方式のtickは入力文章の読解と出力生成の照合を含むが、ファイルI/O、コード生成、ハッシュ、通常の文字処理、初期学習などを含む総費用ではない。

開発4文書、評価24文書。各文書について順序保持／主語焦点、逆順／第1文のみ目的語焦点の2出力。3方式で評価時144出力要求。意味・関係・順序・焦点を実装の異なる限定文法パーサーで採点する。このパーサーは独立実装であって、独立の人間による評価ではない。

故障18照会、部分状態6例、外部P1/S1接続2例、保存訂正記憶からの再生成2例、無効入力4例を別枠とする。少数の補助試験で一般的な雑音耐性・安全性を主張しない。

## 残る保証の境界

通常コードが意味・構造を仲介する。旧v0.2で残った共通破損や偽教師の問題を解決する版ではない。新しい相関選択でも一貫した誤信号は誤選択を生じ得る。評価で誤出力ゼロでも、誤出力不能という保証はない。文書の長さや語彙、文法は限定のままである。
