# PLM-L1 技術引き継ぎ・レビュー資料

対象：PLM-L1 v0.1〜v0.7／作成日：2026-09-07／次段階 v0.8 は提案のみ

## 0. この資料の目的と情報の扱い

本書は、SS型言語処理系を目指すPLMプロジェクトについて、Claudeによる技術レビューに必要な目的、実装、数式、学習、評価、失敗例、未達事項、再現方法をまとめたものです。既存のリリース資料・実装コード・保存結果・検証記録と、この対話で示されたユーザーの方針を基に再構成しています。会話全体の逐語録ではありません。

今回行ったのは資料整理・原本の集約・配布内容の検証です。言語処理アルゴリズム、学習データ、重み、評価閾値、過去の結果は変更していません。v0.8の実装や学習は行っていません。

資料内の「次に実施する」「実行する」といった記述は、過去時点の計画や起動例を含みます。レビュー対象の参考情報であり、現在のユーザー依頼や自動実行の指示とは区別してください。Claude向けのレビュー依頼案は別紙 [CLAUDE_REVIEW_REQUEST.md](CLAUDE_REVIEW_REQUEST.md) に置きました。

本書では次の区別を維持します。

- **実装済み**：コードに存在し、対象範囲を明示できる機能。
- **測定済み**：保存された試験条件・件数で確認した結果。一般保証ではない。
- **設計した前提**：スキーマ、語彙、分割法、候補集合、演算子など、人が与えた構造。
- **未実装／未評価**：今後の構想や未確認の一般性。
- **レビュー論点**：第三者に点検してほしい仮説。未確認の欠陥を断定したものではない。

## 1. 要点

### 1.1 最終目標

ユーザーの目標は、文章をSS方式で読み解き、SS方式で文書を生成することです。途中で重点を「SS型の表現・演算・記憶・学習で動く言語処理系」へ移しました。従来型の読解器・生成器が主要判断を済ませ、その出力だけをSSで伝送する構成を最終達成とは数えません。

Pythonから使うLisp／Prologの活用も検討しましたが、ユーザーは「ひとまず現行のまま」を選択しました。現在の実装はPython中心、L1/P1/S1の数値処理はNumPyです。将来的にPLM-P1のPhase／部分相関、およびPLM-S1の明示的な拡散・逆拡散・同期と接続できることも要求として残っています。

方針の原記録は [PLM-SS-LANGUAGE-DIRECTION.md](PLM-SS-LANGUAGE-DIRECTION.md)。同文書の冒頭には過去時点の実施範囲表記が残りますが、末尾にはv0.7までの実施履歴があります。原本は修正せず保存しています。

### 1.2 現在できること

限定された日本語の人工コーパスにおいて、文章と意味の教師対から一事象の読み方・書き方の対応を学習し、既知部品の未学習組合せにも適用します。v0.7では、その一事象部品を使って明示的に区切られた二文を読み、二つの出来事を一つの複素位相信号に保持し、原文を生成側へ渡さずに二文を生成できます。

保持対象は各事象の主語・目的語・述語・肯否・仮定状態と、二事象の**文章での提示順**です。生成時には各文を主体先行／対象先行のどちらにするか指定できます。

v0.7の標準bound方式では、四つの事象符号seedの合計で読解1,152/1,152、直接生成1,152/1,152、読解→生成4,608/4,608が成功しました。これは同じ限定評価コーパスの符号反復です。1,152種類の独立自然文や、4,608種類の独立文書を理解したという意味ではありません。

### 1.3 現在できないこと

- 一般自然言語の理解、未知語義の獲得、任意文法・任意階層の発見。
- 自由な長文生成、内容計画、三事象以上、代名詞解決、主語省略の補完。
- 記述順と実際の時間順の区別、事象間の時間・因果関係の理解。
- すべての学習・制御をSS演算で実行すること。
- L1の言語処理経路へのP1の観測成分マスク・干渉除去やS1同期受信器の統合。
- 高負荷・偏ったキー分布での安定した記憶回復、未知照会への誤受理ゼロ保証。
- 外界に対する真偽確認、認証、R1推論の開放、Conceptの自動更新。

したがって、本実装は「SS/VSA型の数値連想・意味表現を中心に据えた、手設計の構造的前提を持つ限定実証」と位置付けるのが適切です。完成した汎用言語モデル、全SS学習器、またはSS方式の優越性の証明とは位置付けません。

## 3. 対象言語・意味スキーマ・事前知識

### 3.1 現在の一事象部品

原本：[語彙](PLM-L1-v0.7/data/lexicon.json)、[語彙と対応付けのコード](PLM-L1-v0.7/plm_l1_v06/lexicon.py)。

| 要素 | 範囲 |
|---|---|
| 個体 | 太郎、花子、次郎、美咲、健太、由紀の6人 |
| 述語 | 助け／help、褒め／praise、訪ね／visit、見つめ／gaze_atの4種類 |
| marker | が、を、もし、。、た、なかった、たら、なかったら |
| 文内語順 | subject-first、object-firstの2種類 |
| 肯否 | positive、negative |
| 様態 | asserted、hypothetical |
| 一文の意味 | subject/object/predicate/polarity/modalityの5スロット |
| v0.4以降の一文制限 | 最大256文字、最大9トークン |
| v0.7の文書制限 | 句点で終わる正確に二文、入力検査で最大514文字 |

現行lexiconは内容語10＋marker 8の18項目です。v0.1の「19語彙」はEOSを含む在庫の数え方です。同じ語彙数表記だと誤解しないでください。

例：

```json
{
  "subject": "entity:太郎",
  "object": "entity:花子",
  "predicate": "predicate:help",
  "polarity": "polarity:negative",
  "modality": "modality:asserted"
}
```

これに対応する制御文の例は「太郎が花子を助けなかった。」／「花子を太郎が助けなかった。」です。仮定形は「もし太郎が花子を助けたら。」のような、後件を伴わない実験用の条件節です。一般日本語の完結した条件推論ではありません。

### 3.2 与えた知識と学習するもの

与えるものは、文字表面形、内容語の意味IDと語種、5スロット、候補集合、内容語とmarkerに分ける規約、役割コピーと文字列化の操作です。語義は外界に接地された知識ではなく、固定の記号ラベルです。

学習対象は、これらの前提の下での役割・構造・肯否／仮定・語順／marker実現の対応です。v0.2以降は外から人手の操作列を注釈しませんが、意味教師を用いて内部で対応・教師観測を導出します。

学習時の`aligned_examples`は、内容語が意味スロットに一意に対応することを要求します。主語と目的語が同じ値で、対応が曖昧になるような例は、そのまま一般的に学習できる設計ではありません。意味codecの型検査が値を許す範囲と、教師対の自動整列が成功する範囲を区別してレビューしてください。

文字分割は登録表面形の最長一致であり、SSによる未知語分割ではありません。v0.7は二文の前後・文間の空白をstripしますが、一文内部の任意空白、未知表記、代名詞を一般的に吸収するわけではありません。

## 4. SS型数値表現の契約

### 4.1 固定位相コード

基本コードはD次元の単位複素ベクトルです。

```text
c(namespace, value, seed)[d] = exp(i * theta[d])
```

seed、namespace、値を決定的に直列化し、SHAKE256に由来する53bit位相から生成します。標準D=8192。コードは識別と結合に使う固定表現であり、意味の近さを経験から学習した埋め込みではありません。

結合は成分積、逆結合は共役との成分積、重ね合わせは加算、照合は複素積の実部平均を用います。順序や役割を持たせるには、そのための位置・field固有namespace・置換等が必要です。単に可換な成分積を使っただけでは順序は保存されません。

現行キー構築ではfieldごとのnamespaceを使います。独立のfieldコードと共有valueコードを単純に掛けるだけだと、異なるfield間で値を交換した際に区別が消える設計上の危険があります。`projection.py`の`Space.key`には、この点を避ける構成と説明があります。

### 4.2 連想記憶

基本方程式は次です。`⊙`は成分積、barは複素共役です。

```text
H = sum_q conjugate(K(q)) ⊙ V(t_q)
u(q) = H ⊙ K(q)
score(t | q) = Re(mean(u(q) ⊙ conjugate(V(t))))
```

v0.1では同じキーの教師観測を平均し、反復観測だけで振幅を水増ししません。後続の部分記憶では完全文脈の重複・矛盾を検査し、依存葉を導出して対応を保存します。

このスコアは相関振幅であり、正規化cosineとも、校正された確率とも、現実の真実性とも同一ではありません。高負荷では他の対応によるクロストークが混入します。

v0.1の基本照合条件は首位0.60以上、次位または0との差0.25以上。現行v0.6/v0.7の主要値照合は首位0.65以上、差0.25以上です。全世代で同じ閾値を使っていたとは説明しません。

### 4.3 一事象の意味信号

```text
M = sum_r Role(r) ⊙ Value(x_r)
r in {subject, object, predicate, polarity, modality}
```

否定は信号全体の符号反転ではなく、対象事象のpolarityスロットの値です。仮定も独立したmodality値です。

各役割を逆結合して公開候補と相関照合し、5スロットを決めます。現行版では再構成したclean信号との差について、`||received-clean|| / ||clean|| <= 0.20`を要求します。候補が曖昧、相関が弱い、残差が大きい場合は全体を保留します。

### 4.4 「部分相関」の二つの意味

| 言葉 | 実際の処理 | 現状 |
|---|---|---|
| L1の部分文脈照合 | 学習した依存fieldだけに文脈を射影し、その部分キーを照会 | v0.4以降に実装 |
| P1の部分観測相関 | 数値ベクトルの観測された成分を使い、公開候補の干渉を処理 | P1の別実装。L1へ未統合 |

両者を同じ「部分相関」と呼んで、L1がP1の欠測・干渉処理を統合済みであると解釈しないでください。

## 5. 一事象学習器・読解器・生成器の現行構成

原本：[features.py](PLM-L1-v0.7/plm_l1_v06/features.py)、[projection.py](PLM-L1-v0.7/plm_l1_v06/projection.py)、[training.py](PLM-L1-v0.7/plm_l1_v06/training.py)、[reader.py](PLM-L1-v0.7/plm_l1_v06/reader.py)、[runtime.py](PLM-L1-v0.7/plm_l1_v06/runtime.py)。

### 5.1 学習入力と特徴化

外部学習APIへの入力は`text`と`meaning`の対、および初期lexiconです。評価の正解トレース、fold名、除外セル、語順の教師ラベルを追加で渡しません。

学習器内部では語義IDと意味スロットを照合し、内容語の役割位置を自動整列します。内容語の前後にあるmarker列をgapとして切り分け、内容語の順序とmarker部品を分けます。この分解方式自体は学習したものではありません。

情報利得に基づく決定論的なID3型の処理で、出力を区別するのに必要なfieldを選びます。同点時の分岐はarityやfield名で決めます。木・具体的な葉のキー値・完全一致対応表は実行モデルへ残さず、選ばれたマスクと候補在庫、数値連想記憶を保存します。

通常の記号・統計学習器が依存関係を見つけているため、この構成を「全SSで依存関係を発見した」とは呼べません。

### 5.2 八つの記憶群

| 記憶 | 入出力の役割 | 主モデルでのマスク例 |
|---|---|---|
| roles | 内容語の文脈→意味役割 | right |
| polarity | 文の特徴→肯否 | predicate_markers |
| modality | 文の特徴→断定／仮定 | leading_markers |
| order_support | 内容語順序→支持 | order |
| order_output | 生成目標→内容語の順序 | goal |
| gaps | 役割位置・状態→marker列 | anchor、anchor+modality、anchor+modality+polarity |
| lexical_read | 表面形→内容語意味 | surface |
| lexical_write | 内容語意味→表面形 | meaning_value |

主モデルは八つの記憶群・計十のマスクブロックを持ちます。各マスクの総予算Dにより、数値係数本体は10×8192×16=1,310,720 bytesです。記憶群の数、ブロック数、バンク数は別の数え方です。

主モデルのlexical_readの2バンク負荷は[6,4]、lexical_writeは[9,1]です。分割数選択がキー分布を実測して均等化する方式ではないことは、通常モデルの統計からも読み取れます。これだけで通常言語試験の失敗があったとは言えず、実際その試験は通っています。

### 5.3 読解

```text
登録語彙で文字列を分割
  → 各内容語の役割・値を相関照会
  → 内容語順とgap列を構築
  → 肯否・仮定を相関照会
  → 学習した順序・gap実現との整合を確認
  → 自分の意味候補を符号化
  → 信号を復元し、その候補と一致する場合だけread
```

最後の検査はv0.5からの契約です。外部評価者のgold意味は使いません。自己整合した誤読は依然起こり得るため、読解の正しさは別の採点器で検査します。

### 5.4 生成

生成器は数値意味パケットから5スロットを復元し、生成目標から内容語順を選びます。先頭gap、各役割の語彙実現、役割後のgapを相関取得して文字列へ組み立てます。

v0.3のprefixに基づく次語自己回帰から、v0.4以降は学習した役割順序と部品列の組立てへ変わりました。現在のv0.7を、自由長の自己回帰文章生成器として説明するのは正確ではありません。

原文の全文検索・コピーや、評価正解文の転送はしません。一方、固定された内容スロットのコピー、候補集合、marker列部品、通常Pythonの制御・文字列連結は残っています。

## 6. v0.6の負荷対応記憶

原本：[仕様](PLM-L1-v0.7/vendor/PLM-L1-v0.6/SPECIFICATION.md)、[banked.py](PLM-L1-v0.7/plm_l1_v06/banked.py)、[結果](PLM-L1-v0.7/vendor/PLM-L1-v0.6/results/REPORT.md)。

### 6.1 学習時の分割

マスクごとの相異なる部分キー数Nからバンク数Bを1→2→4→8と選択します。Nが8Bを超え、次のバンク幅を128以上にできる場合に増やします。各マスクの総係数予算Dは固定です。

照会文脈を学習マスクへ射影した後、その部分キーだけをSHA-256に基づいてルーティングします。正解候補や未射影の全文脈はルート選択に使いません。全文が未登録でも必要な部分キーが既知なら、既知部品の新しい組合せを許容できます。

この「負荷対応」は学習時の固定分割です。運用中の監視、追加学習、自動再分割、偏りに応じた再ハッシュは未実装です。

### 6.2 キー／候補の確認信号

確認ありの方式は各バンク幅の3/4を値記憶H、1/4を独立namespaceの確認記憶Eに割り当てます。

```text
H = sum conjugate(K(q)) ⊙ V(t)
E = sum P(q, t)

t_hat = 値側が自分で選んだ候補
proof_score = Re(mean(E ⊙ conjugate(P(q, t_hat))))
```

値側の首位・差分条件に加え、確認側の相関0.65以上を要求します。キーだけでなく、キーと選ばれた候補の組を確認します。外部goldを照合するものでも、完全一致の登録一覧でもありません。Eも重畳信号なので、干渉による誤確認は残ります。

複数マスクから受理された値が一つに一致すれば返却し、競合または全保留なら保留します。確認を加えることで競合の一部が消える場合もあるため、モデル全体の受理集合が確認無効時の部分集合になるとは一般には言えません。受理集合の包含検査は、一マスクの独立記憶試験に限定されています。

### 6.3 比較方式

| 方式 | 分割 | 確認 | 値／確認の係数 |
|---|---|---|---|
| single | なし | なし | D／0 |
| split | あり | なし | D／0 |
| proof | なし | あり | 3D/4／D/4 |
| split_proof | あり | あり | 3D/4／D/4 |
| split_unchecked | あり | 計算するが判定に不使用 | 3D/4／D/4 |

split_uncheckedは確認判定の寄与を切り分ける対照です。運用推奨ではありません。splitとproof単独は独立記憶試験で比較し、全foldの言語試験を行ったとは主張しません。

### 6.4 同一予算の範囲

各MemoryBlockは2048+16D bytesの不変bytesを持ち、先頭2048 bytesを長さ付きJSONメタデータとゼロ埋めに使います。残りがcomplex128の数値係数です。メタデータが上限を超える場合は明示的にエラーにします。

BankedMemoryの推論キャッシュは32スロット×4096 bytes。キャッシュは訓練時の登録表ではなく、実際の照会結果を保持します。保存・fingerprintの対象外で、再ロード時は空です。独立記憶試験ではキャッシュ0です。

所有heap比較はMemoryBlock・bytes・BankedMemory・tuple・bytearray等の`sys.getsizeof`合計です。主モデルの所有量2,381,746 bytesを比較していますが、意味codec、候補基底、Model側監査統計、Python本体、学習時領域、一時配列は含みません。プロセス全体のRAM同一条件ではありません。TELEMETRYの時間・tracemallocも完全なネイティブRAMや最悪時上限ではありません。

固定Dで均等に分割すると、負荷N/Bと幅D/Bが両方減ります。N/Dが自動的に改善するわけではなく、分割しただけで容量が増えたとは言えません。

## 7. v0.7の二事象信号・情報境界

原本：[仕様](PLM-L1-v0.7/SPECIFICATION.md)、[codec.py](PLM-L1-v0.7/plm_l1_v07/codec.py)、[runtime.py](PLM-L1-v0.7/plm_l1_v07/runtime.py)、[reader.py](PLM-L1-v0.7/plm_l1_v07/reader.py)。

### 7.1 意味構造と結合

意味APIは`{"events": [event0, event1]}`という正確に二つの5スロット事象を受け取ります。これは符号化前・復元後の内部表現です。生成側への転送パケットには、この一覧を含めません。

```text
F_i = P + sum_r R_r ⊙ V(value_i,r)
z = (B_0 ⊙ F_0 + B_1 ⊙ F_1) / sqrt(2)
```

Pは存在信号、Rは文内の意味役割、Vは候補値、B_iは提示位置0/1の事象符号です。五スロット＋存在の6成分を二事象分、計12成分、一つのD次元複素信号に重ねます。

復元では`B_i ⊙ R_r ⊙ V(candidate)`を前計算した基底と相関を取ります。B_iの共役で逆結合してからR/Vと照合する式と同値で、1/sqrt(2)の振幅補正を行います。Dは128〜16384の128倍数です。

受理は存在相関0.65以上、各slot首位0.65以上・差0.25以上、全体の再構成相対L2残差0.20以下です。閾値は固定プロトコルとコードで確認できます。プロトコル値がすべて実行時設定として動的に読み込まれると仮定せず、ハードコード定数との整合もレビュー対象です。

### 7.2 事象の同一性の範囲

B_0/B_1が区別するのは文書内の**提示位置**です。永続的な出来事ID、文書をまたぐ同一事象、実際の時刻、原因と結果を表すものではありません。

同じ内容を二回書いた場合も二つの位置として保持し、重複除去しません。共通主語、共通目的語、主客逆転、別々の否定・仮定を、事象位置と文内役割の両方で区別します。

### 7.3 原文を渡さない経路

```text
入力二文
  → 句点で明示分割（設計済み規約）
  → v0.6部品で各一文を読解・意味回復
  → 二事象の候補を共有信号zへ結合
  → zの復元が両候補と一致したときだけ数値パケットを出力
  → 生成側がzから両事象を復元
  → 各事象を内部でv0.6の一事象信号へ再符号化
  → 学習済み一文生成部品で二文を生成
```

第二文で失敗した場合も、第一文だけの意味パケットや完成文を全体成功として返しません。全体単位でabstainにします。

共有重み・語彙・候補は生成側にもあります。生成器が何の知識も持たず、信号だけから日本語を発明しているという意味ではありません。

### 7.4 パケットの厳密な契約

転送schemaは`plm-two-event-signal-v1`。許可されるキーは次の六つだけです。

```text
schema
model_fingerprint
dimension
real
imag
eligible_for_inference
```

real/imagはそれぞれD個の数値からなる一次元配列です。原文、意味JSON一覧、二つの下位パケット、評価gold、照会ごとに絞った候補、読解トレースは転送しません。`eligible_for_inference`は常にfalseです。

余分なフィールド、別schema／model、次元不一致、boolを数値に見せた入力、非有限値、成分絶対値32超を拒否します。モデルメタデータは`plm-two-event-model-v1`で、部品fingerprint・D・seed・mode・event_count=2・提示順のみ等の契約を含みます。

fingerprintは取り違え・偶発変更の検出用で、暗号署名ではありません。別の有効な意味へ再符号化された信号は、その別の意味として受理され得ます。残差検査は出所・送信者・真実性を保証しません。

### 7.5 学習した部分／学習していない部分

v0.7の部品は、v0.6主モデルと同じ432の一事象対、seed=`banked-evaluation-0`、D=8192、split_proofで再学習します。コード・主部品重みが一致することを確認しています。

二事象の訓練例は0です。句点による分割、B_i、存在信号、結合式、二文の生成制御は設計した規約です。二事象コーパスから構造を獲得した実装ではありません。

四つの評価seedは新しい事象符号を変えるだけで、一事象の文法部品を四通りに学習し直した実験ではありません。EventCodecのDを変える試験でも、部品モデルは8192次元のままです。

## 8. 学習・開発・評価の分割

### 8.1 v0.1〜v0.3

一事象コーパスは学習576文・開発192文・評価192文。主体・対象・述語の組合せを単位として分割し、同じ割当ての肯否・仮定・語順違いを同じ分割へ置きます。既知語彙・既知構文の未学習組合せが対象です。

v0.2/v0.3は同じ分割を再利用します。モデルにとって未学習でも、プロジェクトの開発者が一度も見ていない評価集合とは言えません。八つの符号seedは数値符号に対する反復で、独立した八コーパスではありません。

### 8.2 v0.4〜v0.6

元の576学習対から、語順×肯否の一セル144対を丸ごと除き、432対で再学習します。四セルを入れ替える四foldです。各評価192文のうち48件が除外セル、144件が既出セルに相当します。

四fold×四seedで、除外セルの読解・直接生成は48×4×4=768要求、全往復は192入力×2生成目標×4fold×4seed=6144要求です。

すべての語彙・marker部品・語順部品は学習にあります。未知なのはその組合せです。除外セルをlearnerに教えて専用処理を作る方式ではありませんが、部品分解という設計バイアスは与えています。

### 8.3 v0.7

開発・評価それぞれ72の順序付き意味対、四つの入力語順組合せで288文書。順序付き意味対の開発／評価重複は0です。九カテゴリは次です。

### 8.4 評価者の独立性

生成文は同じ新読解器による自己採点だけでなく、別実装の制御文法で意味と語順を採点します。生成単体、読解単体、接続往復を分けることで、両側の誤りの相殺を見逃しにくくしています。

ただし採点器・コーパス生成器は同じプロジェクト系列の人工文法・語彙に基づきます。独立に収集された自然文、別担当者の盲検注釈、外部チームによる評価は実施済みではありません。「別実装の採点」と「独立した意味評価」を区別することが本レビューの重要点です。

| 必要特徴の選択 | ID3型情報利得・記号処理 | 教師対から学習するがSS学習ではない |
| 選んだ部分キーの対応保存・照会 | 複素位相重畳・結合・相関 | SS/VSA型の連想学習・回復 |
| バンク選択 | 部分キーのハッシュと分岐 | 通常処理、学習時固定 |
| キー／候補の確認 | 独立位相確認信号との相関 | SS型だが誤確認あり |
| 一事象／二事象の意味信号 | 役割・値・事象位置の位相結合 | 符号化規約は設計 |
| 二文の分割・事象結合規則 | 句点分割、固定二位置 | 未学習 |
| 語順・markerの選択 | 学習済み連想記憶から照会 | 有限部品の選択 |
| 出力文字列組立・保留・I/O | 通常Python／NumPy | 補助制御 |
| 実チップ拡散・同期 | L1の主経路には存在しない | S1別系列に実装 |

コード行数の何%がSSかではなく、主要判断のどこを数値符号が担い、どこを設計された記号処理が担うかで評価してください。特に「学習器が通常処理で見つけた対応をSS記憶にコンパイルしている」という見方の妥当性と、その構成を最終目標へどう進めるかが重要です。

## 12. P1・S1へ接続する際の技術的な境界

v0.1には、固定4チップ`(+1,-1,+1,-1)`を用い、各複素成分を`M[d]*c[j]/sqrt(4)`へ写し、既知境界・無雑音で元へ戻すデモがあります。標準D8192なら32768チップです。意味演算をチップ領域へ移したものでも、S1同期と接続したものでもありません。

既存S1 v0.2はP1の2048複素成分を4チップずつに拡散し、パイロット256チップを4か所へ配置する別wire契約です。総8480チップ・総送信エネルギー57344という固定予算で比較しています。受入周波数±2 Hz、探索±4 Hzの人工離散ベースバンド実験であり、分数チップ遅延・時計ずれ・マルチパス・RF前段などは未実装です。

L1のD8192、別namespace、意味スキーマ、model fingerprintを、そのまま既存P1/S1のwireへ渡せるとは限りません。将来必要なのは、少なくとも次です。

1. どの意味信号をどの次元・エネルギー・チップ数で運ぶかという明示契約。
2. L1の候補・意味役割とP1のquery/catalogueの対応。goldによる候補絞り込みを防ぐ境界。
3. パイロット取得・周波数／位相補正・逆拡散・意味回復の段階別保留。
4. 直接数値転送とS1経由を、同じ意味課題・適切な予算で比較する評価。
5. 通信路を通した意味保持と、言語の主要判断をSS化することを分ける監査。

同期成功、意味回復成功、文章の真偽、送信者認証は別の命題です。P1/S1を接続しても、自動で意味理解や推論を許可しません。

## 14. 起動・再評価の手順

### 14.1 環境

検証環境はPython 3.12.14、NumPy 2.3.5、Windows x64です。Python本体は同梱しません。ネットワーク・外部LLM・Lisp／Prolog・GPUは通常の実行に不要です。NumPyの導入が必要な環境だけ、内容を確認して`python -m pip install -r requirements.txt`を使用してください。

Windowsでは再帰vendorのためパスが長くなります。短い作業パス（例：`C:\plm\L1-review`）へ展開してください。以下は`L1-review/PLM-L1-v0.7`をカレントディレクトリとするPowerShell例です。出力は上書きしないため、同名が存在すれば新しい名前に変えます。

### 14.2 二事象の通常往復

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$env:PYTHONIOENCODING='utf-8'
python -B -m plm_l1_v07 read --model results/model --text '太郎が花子を助けた。花子が太郎を助けなかった。' --out work/review-packet-01.json
python -B -m plm_l1_v07 recover --model results/model --packet work/review-packet-01.json
python -B -m plm_l1_v07 generate --model results/model --packet work/review-packet-01.json --goals object subject
```

期待される生成は「花子を太郎が助けた。花子が太郎を助けなかった。」です。第一文の文内語順だけを変え、二つの出来事の提示順は変えません。

`recover`の人間向け意味表示を生成器へ転送する必要はありません。generateに与えるのは同じ数値packetです。

### 14.3 直接生成と再学習

```powershell
python -B -m plm_l1_v07 encode --model results/model --meaning examples/MEANING.json --out work/review-direct-01.json
python -B -m plm_l1_v07 generate --model results/model --packet work/review-direct-01.json --goals subject object
python -B -m plm_l1_v07 train --pairs data/folds/object_negative/train.json --lexicon data/lexicon.json --component-seed banked-evaluation-0 --event-seed events-evaluation-0 --out work/review-refit-01
```

encodeのmeaningは、生成単体試験用の意味入力です。通常の読解経路で評価goldを渡す手順ではありません。

### 14.4 検証と全評価は別

```powershell
python -B -m unittest discover -s tests -v
python -B verify_release.py --out work/review-verify-01
python -B evaluate.py --out work/review-evaluation-01
```

- unittest単体はv0.7の新規40件。
- verify_release.pyは旧版を含む381件、保存結果からの364受入条件再計算、隔離学習・隔離生成・manifestを確認。全数値評価の再実行ではありません。
- evaluate.pyは標準方式・seed・codec次元・雑音等の全数値評価を実行します。機械によって時間がかかります。結果は必ず新しい出力先へ置いてください。

過去の`release_tools.py check-baseline`は開発時の兄弟フォルダと元ZIP配置を前提とする保存点検です。今回の省重複レビュー構成で、そのコマンドまで元開発環境と同じ相対配置だとは仮定しないでください。レビュー配布物全体は`tools/verify_bundle.py`、各版はそのREADMEとverify_release.pyに従って検証します。

## 15. Claudeに優先してレビューしてほしい論点

以下はレビューの重点であり、すべてが既知のバグだという意味ではありません。

### 優先度A：主張と実装・評価が一致しているか

1. **SS中心性**：ID3による依存選択、初期語彙、分解法、候補在庫、数値記憶のどこが能力を担うか。符号化した対応表との差は何か。学習そのものをSS化する次の実験は何か。
2. **評価の独立性**：コーパス再利用、同系列文法による生成・採点、開発seedと評価seedの分離は、どの主張まで支えるか。
3. **自己整合と正答の区別**：読解ゲートや残差が、同じ誤りの再構成を受理する場合。外部意味採点が漏れなく使われているか。
4. **比較の公平性**：部分構造共有の効果をSS固有の効果と混同していないか。candidate基底・cache・一時領域・学習時間を含めると何が変わるか。

### 優先度B：数値・構造・情報境界

5. **可換性と役割束縛**：field交換、主客反転、同一内容の反復、事象位置交換に不適切な不変性がないか。
6. **干渉と保留**：N/D、バンク負荷偏り、候補数、マスク競合、固定閾値に対する失敗条件。未登録誤受理と正答保留の両方を改善できるか。
7. **二事象表現の拡張性**：提示位置B_iから、永続的な事象識別や関係の端点をどう分離するか。提示順変更時の同一性をどう保つか。
8. **パケット／モデル境界**：gold、原文、候補絞り込み、traceが迂回流入しないか。model hash検査を認証と誤解していないか。
9. **入力の上限と不正ケース**：候補在庫の検証、同一人の複数役割、未知marker、巨大値、欠損、過長入力、不完全モデル。既知テストの外で停止・保留が適切か。

### 優先度C：次の開発をどう絞るか

10. 時間関係の学習へ進む前に、独立評価セットの固定や記憶偏り対策を優先すべきか。
11. S1接続を行う最小契約と、単なる伝送の成功に終わらない評価の分け方。
12. 無制限の語彙・長文へ拡大せず、最終目的に近づいたと判定できる中間課題と受入条件。

指摘には可能な限りファイル・関数・行、数式、最小反例、既存テストとの関係、修正案、修正後に必要な独立評価を付けてください。有限の成功例から全面否定も全面肯定もせず、成立する限定命題と未検証の一般命題を分けるレビューを求めます。

## 16. 次段階 v0.8 の提案（未実装）

直近の提案名は「PLM-L1 v0.8：二事象の時間関係の学習と意味保持生成」です。

例として、次の二つの表現は提示順が異なっても同じ前後関係を表します。

> 太郎が花子を助けた。その後、花子が健太を褒めた。  
> 花子が健太を褒める前に、太郎が花子を助けた。

これは将来課題を説明する例です。現在のv0.7がこの接続表現を読めるという意味ではありません。「褒める前に」等を扱う語彙・文法・学習データは今後必要です。

提案範囲は、明示的な前後関係と順序不明に限定します。

- 出来事そのもの、文章の提示順、出来事の時間関係を分ける。
- 関係の種類と二つの端点をSS型意味信号へ結合する。
- 限定した文章／関係付き意味の教師対から、表現と関係の対応を学ぶ。
- 時間関係が書かれていなければ順序不明とし、記述順から補わない。
- 提示順を変えても関係を保つ例、関係だけ反転する例、未学習部品組合せ、否定／仮定の範囲を独立評価する。

二事象の結合規約そのものまで学習対象にするか、設計したcodec上の読み書き対応だけを学ぶかは、実施前に分けて契約化する必要があります。事象端点を単純な文番号に固定すると、提示順の変更と意味的同一性が混ざるため、設計上の主要論点です。

因果推論、代名詞、三事象以上、R1推論開放、Concept更新はこの提案へ自動追加しません。まだ評価条件・数値ゲート・実装は作っていません。Claudeのレビューで優先順位を見直す余地があります。

## 18. レビュー後に決めたいこと

求める結論は単なる「面白い／有望」ではなく、次の五点です。

1. 現時点で主張してよい限定的な成果は何か。
