# PLM-L1-SS-active-v0.2 実施報告

探索を併用した追加教師選択と訂正保持。

実施日：2026-09-08。研究用の独立実験。`eligible_for_inference=false`。

実装・比較評価を完了しました。再確認ありの条件では一部の訂正済み項目の保持が改善しましたが、探索＋再確認を組み合わせても全体成績は曖昧さのみの方式を上回りませんでした。変更項目の発見も増えておらず、本設定を一律に優れた標準方式へ昇格させる根拠は得られていません。

## 1. 目的

v0.1では、SS平均相関の曖昧さによる追加教師選択が、同じ教師予算の無作為取得より旧記憶の回復を改善しました。一方、正解が予告なく変わった項目を発見しにくいこと、訂正後にも誤りが再発すること、未登録照会や他の記憶への干渉が残ることを確認しました。

本版では共有誤差型SS記憶を変更せず、「広く確認する探索」と「教わった項目を後で再確認する機会」を教師取得の制御に追加します。両者を別々にも試し、改善があれば何によるものかを切り分けます。改善しない場合にも、その条件と費用を記録します。

これは人工的な既習キーの再学習実験です。文の読解・生成、二事象の意味構造、部分観測、依存関係マスク学習、P1/S1との接続を新たに実現したものではありません。

## 2. 維持したSS記憶

4項目・各8値の完全な文脈を、固定された複素位相符号の要素積で表します。独立生成した128次元の符号を4本使い、4ラベルを読み出します。

```text
s[k,y] = Re(sum_d conj(H[k,y,d]) * b[k,d])) / 128
mean_score[y] = mean_k s[k,y]
error[y] = one_hot(external_teacher)[y] - mean_score[y]
H[k,y,d] <- H[k,y,d] + 0.5 * error[y] * b[k,d]
```

各符号を別々の誤差で更新せず、同じ平均誤差で更新する `concat512` を使用します。学習係数は2,048個のcomplex128、32,768バイト。学習率0.5、平均相関0.5以上の候補が唯一の場合に受理する規則を維持します。全条件で同じ容量・学習率・受理規則です。符号一致による追加ゲートや、評価後の閾値調整は行いません。

前版のSSコア4ファイルと相関診断等の補助ファイル1本をバイト不変で引き継ぎ、ハッシュを検査します。正解表をSSモデルに併設せず、教師再生バッファも使いません。正解を学習するための外部教師以外に、モデルの予測を擬似教師へ変換することはしません。

## 3. 新しい教師選択

### 3.1 探索と曖昧さ優先

取得期間内にまだ尋ねていない候補を、4回に1回、文脈IDとシードから求める固定ハッシュ順で選びます。残りはSS平均相関の上位2候補の差が小さい順に選びます。ここで「まだ尋ねていない」は追加教師取得期間内の意味であり、未登録・未学習の文脈という意味ではありません。候補はすべて基礎学習で一度以上教わっています。

探索枠は0始まりの取得番号で `index % 4 == 0`。同点時も同じハッシュ順を使います。外界で正解が変わっても内部のSSが古い答えに確信を持っている項目へ、教師取得が到達する機会を残す狙いです。

### 3.2 再確認

再確認枠は `index % 4 == 3` であり、探索枠とは重なりません。次の条件をすべて満たす既取得項目を候補とします。

- 取得回数が2回未満。
- 最後の取得後に、取得教師と背景教師を合わせて64回以上のSS更新が進んだ。
- 教師直後の上位2候補の平均相関差から、現在の相関差が0.15以上低下した。

該当項目のうち現在の相関差が最も小さい項目を再確認します。該当しなければ、まだ取得していない項目の曖昧さ優先に戻ります。同じ項目は最大2回で、今回の時系列では再確認は最大4件です。再確認は無料の再生ではなく、新しい外部教師1件を消費します。

保存する台帳は文脈IDに対応する `visits`、`last_step`、`post_margin` の3値のみ。過去の教師ラベル、真の正誤、訂正成功フラグは選択器に与えません。台帳は通常のメタデータであり、SS係数ではありません。

重要な限界として、`post_margin` は「その時点の上位2候補の差」であって、「過去の教師が指定した正解の支持」を追跡した値ではありません。別の誤答が強くなれば相関差が広がる場合もあります。従って支持低下は真の誤り再発と同義ではなく、本版を完全な再発検出器とは呼びません。

### 3.3 5条件の比較

|方式|探索|再確認|
|---|---|---|
|無作為 `random_once`|常に固定ハッシュ順|なし|
|曖昧さのみ `ambiguity_once`|なし|なし|
|探索併用 `mixed_once`|あり|なし|
|曖昧さ＋再確認 `ambiguity_revisit`|なし|あり|
|探索＋再確認 `mixed_revisit`|あり|あり|

後ろ4条件が探索の有無×再確認の有無の2×2比較です。再確認の有無を切り替えた対では、最初の16件の選択とSS状態が同一になります。途中のD学習も共通なので、その後の差を同じ出発状態から比較できます。探索の有無が異なる対では、最初に訂正された項目集合も変わる点に注意します。

## 4. 学習と評価の時系列

```text
A → B → C を各4周学習
  → 追加教師4件［q4］ → 累計16件［q16］
  → 新しいD群を2周学習［post_D］
  → 追加教師を累計20件［q20］ → 累計32件［q32］
  → 新しいE群を2周学習［post_E］
```

群の大きさgは64／128。A～Eは互いに重ならないラベル均衡群で、取得候補はAの半分＋Bの半分、計g項目です。残り半分のA+Bは直接再教示しない旧記憶として評価します。C、D、Eと、別の未教示128キーは取得候補に入れません。未知の語彙を推定する課題ではなく、固定語彙からなる完全な人工キーと4ラベルの対応です。

世界は2種類です。固定世界はラベルが変わりません。変更世界は基礎学習後に候補内16項目のラベルを変更し、以後はその正解を維持します。変更通知や変更項目一覧は選択器に渡しません。教師は現在の正しいラベルを回答します。

v0.1では後続D学習が取得から切り離された分岐でした。本版のDは実際に取得途中のSS状態を変え、その後に追加教師を求めます。さらにEで最終保持を測ります。データシードも新しくしたため、v0.1と最終正解数を直接比較しません。

追加教師なしで同じD・Eを学習する対照も用意します。基礎学習とこの対照はデータ・符号ごとに一度だけ学習し、各条件で共有します。背景教師の経路で取得候補を教えると拒否されるため、追加教師の予算を迂回して訂正することはできません。

## 5. 開発条件の選定と本評価前の固定

探索頻度1/2または1/4、再確認に必要な相関差低下0.05または0.15の4組を、別の開発用シードで比較しました。64更新の待機、再確認枠1/4、最大取得2回は固定です。開発評価は5方式×4組×2負荷×2世界＝80取得系列です。

設定選定には、探索＋再確認方式の最終E学習後について、次の事前定義した評価値を用いました。

```text
utility = (旧記憶の受理正解 - 4 × 旧記憶の誤受理) / (2g)
          - 未登録誤受理 / 128
          + 0.5 × 直接再教示しない旧記憶の受理正解 / g
```

負荷・世界を等しく重み付けします。これは本実験の設計上の損失重みであって、普遍的な正しさや利用者の実損失を表すものではありません。各成分を別にも報告します。同点なら探索頻度が低く、再確認条件が厳しい設定を優先する規則も事前に定めました。

|探索頻度|低下条件|開発評価値|
|---|---:|---:|
|1/2|0.05|0.880859375|
|1/2|0.15|0.8837890625|
|1/4|0.05|0.8837890625|
|1/4|0.15|0.900390625|

1/4・0.15を選定し、全方式に共通の設定として本評価前に固定しました。設定選定の対象は探索＋再確認方式であり、各方式それぞれの最良設定を探して比較したものではありません。開発用のデータシードは1種類のため、この設定が他のデータでも最適という保証はありません。開発前のソース・試験・データのロックと、本評価前の選定結果を含む凍結を分けて記録します。

本評価は4データ×2負荷×2符号×2世界×2取得シード×5方式＝320取得系列です。各負荷・世界・方式では16系列ですが、基礎状態は8種類のデータ×符号組であり、2取得シードは同じ出発状態を共有します。反復照会を独立の文章・意味学習課題として数えず、対応差分と取得シードを平均した8基礎状態での差を記述します。有意差や母集団一般化は主張しません。

本評価1回の教師提示は、基礎学習18,432、追加教師なしの対照6,144、追加教師10,240、各取得系列のD/E背景学習122,880、計157,696です。全分岐の実験上の合計であり、1本の生涯学習列の長さではありません。開発評価は36,352提示です。

## 6. 測定するもの

暫定候補、受理正解、誤受理、保留を別集計します。未登録キーへのラベル受理は、既習キーの誤ったラベル受理と別に報告します。旧記憶全体、候補全体、直接再教示しない旧記憶、変更項目、C/D/Eの成績を分け、基礎状態からの新規回復と元の正解の喪失も記録します。これらは重複する集合で、すべてを足し合わせません。

教師取得では延べ取得件数と異なる項目数を分けます。同じ変更項目を再確認した場合に、変更を2件発見したとは数えません。

訂正保持には、最初の16件で「教師直前は暫定誤り、直後は暫定正解」だった項目集合を固定して追跡します。そのうちD学習直後に再び不正解になった集合も固定し、後半の教師取得やE学習後にどうなったかを測ります。この集合は評価側が正解から作るだけで、選択器には渡しません。再確認の有無の比較では同じ集合ですが、探索の有無を変えた比較では集合が異なるため、件数だけで保持性能を比較しません。

### 7.4 再発診断：支持差の低下と真の誤りは一致しない

結果を見た後に原因を調べる診断を行い、`verification/RELAPSE_AUDIT.json` に保存しました。この診断結果は設定選定・教師選択へ戻していません。

本評価全体の実際の再確認は482件で、その直前に暫定誤りだったのは23件、暫定正解だったのは459件、未確定は0件でした。23件は教師直後に全て訂正されました。再確認の多くは既に正しい項目の補強であり、それ自体は保持に役立ち得ますが、新しい項目を尋ねる機会を消費します。

高負荷・変更世界の再確認あり条件で、初回訂正後にD直後に再発した2件／3件は、D直後の相関差低下が閾値に達せず、後半にも一度も再確認されませんでした。D直後の判定と、後の選択時点の判定は同じではありませんが、実際の後半取得にも含まれなかったことを確認しています。

低負荷・変更世界では、探索＋再確認がD後の再発15件中5件を再度尋ね、E後にその再発集合の正解が探索併用の5件から8件へ増えました。したがって再発への再確認が全く起きないわけでもありません。ただし、その条件でも全体の受理正解は1,750→1,746、誤受理は144→153でした。局所的な訂正保持の利益と、全体の機会費用を区別します。

「教師が示した答えを忘れたか」ではなく、「何らかの最有力候補への確信が弱まったか」を測っている点が、今回明確になった制約です。この構造と観測結果は整合しますが、それだけを唯一の原因と断定はしません。

## 8. 実測費用と検証

### 8.1 時間と状態量

本評価2回が終わった後、g＝128の同じ保存基礎状態から各方式を3回ずつ、1プロセスで実行しました。下表は固定符号キャッシュを温めた代表条件での中央値です。

## 9. 結論と次の段階

今回実装した探索・再確認は、設定どおりに実行され、教師予算を守って学習へ接続できました。ただし、研究仮説が全体として支持されたわけではありません。

1. 再確認あり条件は、同じ初回訂正集合の一部について最終保持を改善しました。
2. その利益は旧記憶全体の受理正解増加にはつながらず、誤受理を増やす比較もありました。
3. 探索を併用しても、本評価では変更項目の発見は増えませんでした。
4. 真に再発した誤りを、単なる相関差低下だけで選び直す仕組みには盲点が残りました。

従って、本設定を既存の曖昧さ優先方式へ一律に置き換えることは勧めません。比較基準として曖昧さのみを残し、探索・再確認を研究用の選択肢として保管します。SS方式そのものの否定や、探索一般が無効という結論でもありません。ここで試した探索順、比率、再確認基準、固定教師予算、人工課題の範囲での結果です。

次は、探索率だけを追加調整するよりも、「以前に教わった正解の支持が失われたか」をSSで照合する仕組みを優先したいと考えます。例えば、教師が示した文脈と答えの対応を小さなSS補助記憶へ結合して保持し、現在の最有力候補への自信とは別に照合する比較です。その際は、通常の正解辞書を隠して持たず、補助SS係数・教師情報・制御台帳の費用を全て数え、同じ総容量での対照も用意する必要があります。

さらに、正しい項目の補強へ予算を使う価値と、新しい項目を尋ねる価値を比較し、再確認しない選択も含めて評価します。これらは未実装の次段階であり、本評価を見て現在の凍結条件を変更していません。

その後は二事象の読解・意味保持生成へ戻し、主体・行為・対象・時間関係のどこを聞き直すと意味を保持できるかを確認します。抽象キーの実験成績を、そのまま文章理解やP1/S1統合の達成と取り違えないことが重要です。
