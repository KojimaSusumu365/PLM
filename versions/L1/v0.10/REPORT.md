# PLM-L1 v0.10 実施報告

実施日：2026-09-07（Windows / Python 3.12.14 / NumPy 2.3.5）

## 1. 結論

「読み方・書き方を一つへ早く決め過ぎない」ため、複数の特徴候補を独立したSS型位相記憶として保持し、候補全体の意味・生成文が一致しない場合は保留する最小実装を行った。

人工的に曖昧にした二事象の生成課題では、同じ教師情報から第一候補だけを使う方式が36要求全てを誤確定したのに対し、複数候補は36要求全てを保留した。候補を区別する教師例を2件追加して再学習すると、36要求全てを正しく生成した。36要求は28一意意味を含む反復であり、36種類の独立した自然言語現象ではない。

標準の限定言語試験は読解864/864、直接生成432/432、提示順反転・再読解の意味保持864/864を維持した。ただし記号的な候補選択でも同じ主要効果が得られ、SS固有の優位性は示していない。全候補一致も正解を保証せず、候補の探索範囲を越える不確実性は残る。

## 2. 実装したもの

- `selection.py`：訓練用位相記憶の回復損失と別の教師付き選択検証によって、同率の最小特徴候補を最大4つ保持。
- `memory.py`：候補ごとの独立した位相記憶、全候補一致による照会、別データによる経験的な受理閾値調整。
- `training.py`：一事象部品の候補を文章処理全体へ組み合わせ、独立したモデルとして学習。追加教師を使うオフライン再学習。
- `reader.py` / `runtime.py`：完全な意味または全文が一致したときだけ受理。候補間で都合のよいスロットや文片を混ぜない。
- `verify_release.py`：凍結・結果・モデル指紋、隔離再学習、数値パケットのみの受け渡し、生成専用環境、旧版ZIPを検証。

SSの候補を一つの信号へ重畳する実装ではなく、候補別の位相記憶を分離している。候補列挙・教師損失集計・ID管理・一致比較は通常のPython処理。SS型表現と照会を利用する言語コアを拡張したが、全SS制御・全SS学習とはしない。

候補数が上限を越える場合は診断用の4候補を保持するだけで、確認しなかった組合せがあるため確定を禁止する。この上限処理は安全側だが、既知の簡単な文章まで一律に保留し得る。

具体的な式・閾値・契約は `SPEC.md`、評価前に固定した条件は `evaluation/PROTOCOL.json` を参照。

## 3. 言語試験

### 3.1 標準の読み書き

SS複数候補モデルは、432一事象学習対、192候補選択用検証対、216時間学習対、初期語彙を使用。選択検証にも意味ラベルがあり、追加の教師情報として数える。選択検証のラベルは重みに直接足さないが、どの重みを採用するかに影響する。

| 評価 | 正答 | 誤答 | 保留 |
|---|---:|---:|---:|
| 二事象読解 | 864 | 0 | 0 |
| 数値意味から直接生成 | 432 | 0 | 0 |
| 読解→提示順反転生成→再読解 | 864 | 0 | 0 |

864読解要求は816一意表面文・216意味記述。二事象の主客・述語・肯否・仮定、時間関係、提示順、生成語順を評価する。標準モデルには完全な文章処理候補が2つ残るが、この範囲では全て一致して回答率を維持した。

SS複数、記号的複数、同一選択検証を使うSS単一、v0.9選択規則の単一について、54代表例の読解54/54・直接生成108/108・往復54/54が全て成功した。対照方式の全文864試験を新たに行ったとは数えない。

生成専用環境での例：

```text
入力：太郎が花子を助けた。その後、花子が健太を褒めた。
出力：健太を花子が褒めた。その前に、太郎が花子を助けた。
```

生成器へ原文を渡さず、数値パケットと出力指定だけで生成した。同一人物が主語・目的語の二事象例も隔離CLIで確認した。

### 3.2 肯否と仮定を混同しやすい教師からの学習

初期教師を「肯定・断定」と「否定・仮定」だけに制限する。制限は一事象学習・選択検証・時間教師の全てへ適用し、別経路から区別の例が漏れないようにした。初期は216一事象対＋96選択検証対＋84時間対。

追加教師は次の文章と対応意味の2対であり、実験者が選んだ。学習用から保留していた例を追加し、選択検証や最終評価の例を移動していない。

```text
太郎が花子を助けなかった。       → 否定・断定
もし太郎が花子を助けたら。       → 肯定・仮定
```

| 方式 | 追加前：正答 / 誤答 / 保留 | 2例追加後：正答 / 誤答 / 保留 |
|---|---:|---:|
| SS複数候補 | 0 / 0 / 36 | 36 / 0 / 0 |
| 記号的複数候補 | 0 / 0 / 36 | 36 / 0 / 0 |
| 同条件SS第一候補のみ | 0 / 36 / 0 | 36 / 0 / 0 |
| v0.9選択規則・単一候補 | 0 / 36 / 0 | 36 / 0 / 0 |

追加前は部品候補の組合せが8通りあり、4つを診断用に実体化して確定禁止にする。実際に36要求全てで候補の全文も不一致だった。追加後は組合せ2通りとなり全候補を保持でき、生成文が一致した。全候補の後からの多数決や、正解を見て候補を選ぶ処理ではない。

この「誤答36→0」は回答率100%→0%の代償を伴う。追加前に同じ正の回答率で優れていると示したものではなく、答えられない場合に誤った確定を出さないことの実証である。追加例で正しい回答に移れた点を別に評価する。

### 3.3 読解側の追加診断と過剰保留

主評価後、保存モデルを変更せず独立評価側の文章化を用いて診断した。交差した肯否・仮定の36要求（28一意表面文）は、追加前0正答・0誤答・36保留、追加後36正答だった。

一方、従来から区別不要な「肯定・断定」へ戻した36要求（7一意表面文）も、追加前は36保留、追加後は36正答だった。**現在の組合せ上限超過の拒否はモデル全体に及ぶため、不確実性と無関係な照会まで止める。** `verification/READ_AMBIGUITY.json` にこの弱点を含めて記録した。これは主評価後の診断であり、モデル調整や受入条件の後付けには使っていない。

## 4. 新しい人工依存課題と誤受理

6二値特徴を用いた5族（単項、XOR、AND、切替、3項パリティ）×2置換。学習・選択検証・リスク調整・最終評価の完全な文脈集合を分離した。標準と少標本・訓練ラベル反転の計60データ条件を、方式・符号・次元の組合せで評価した。

標準24学習・無反転では、各方式ともD2048は320正答・0誤答・0保留、D512は314正答・0誤答・6保留。D512の保留は記号的選択でも残る。記号的対照も運用時は同じSS型記憶コンパイラを使うため、完全な非SS言語系との比較ではない。

少標本・誤ラベルの50条件、D2048、計800要求の成績：

| 方式 | 調整前：正答 / 誤答 / 保留 | 別データで閾値調整後：正答 / 誤答 / 保留 |
|---|---:|---:|
| SS複数候補 | 739 / 20 / 41 | 683 / 1 / 116 |
| 記号的複数候補 | 740 / 19 / 41 | 695 / 2 / 103 |
| 同条件SS第一候補のみ | 741 / 20 / 39 | 685 / 1 / 114 |
| v0.9選択規則・単一 | 501 / 134 / 165 | 347 / 25 / 428 |
| 学習＋選択検証をv0.9へまとめて提供 | 553 / 27 / 220 | 451 / 13 / 336 |

SS複数候補の調整後回答率は684/800=85.5%、受理誤答率は1/684≒0.146%。残る誤答も隠していない。SSと記号的方式の予測が異なるのは、標準・曖昧性を含む122対応条件中3条件。SSが有利な差と不利な差の両方がある。

この50条件ではSS複数候補が実際に2候補を使うのは1条件だけで、残り49条件は1候補だった。旧方式に対する改善の多くを「複数候補保持の効果」と帰属してはならない。損失条件・教師付き選択検証・受理閾値調整も変わっており、SS単一対照が同程度なのがその確認になる。

候補選択用Hをゼロ化した10条件は160要求全てを保留。全特徴値を2とした限定的な域外キーは、選択を有効にした依存試験450照会で受理0。各条件1キーだけの診断であり、未登録入力全般の誤受理ゼロを保証しない。

### 4.1 二つの特徴が見分けられない試験

別の4課題では、学習8・選択検証4・リスク調整4は二特徴が常に等しく、最終評価8は異なる。追加8教師は最終評価と別の完全文脈を使う。

各D・予算条件の4課題合計32要求について、SS／記号的複数候補は追加前に2候補を保持して全32を保留、追加8例後は1候補に絞って32正答。単一候補の三対照は追加前24正答・8誤答、追加後32正答だった。D512/2048と、候補ごとの係数予算／総係数予算固定の全てで同じ結果となった。

調整データで誤答0でも、単一候補の1課題は関係が変わる評価8件を全て誤った。相関の余裕や経験的な目標誤答率0.1は、分布変化下の正解確率・リスク保証ではない。

### 4.2 同数回答の補助比較

正解を見ない固定ハッシュ順で、各条件の受理回答を同じ件数に揃えた。異なる方式が答えた入力そのものは同一とは限らない。

新しい三方式の依存試験90条件では、調整前は各1,390回答に揃えて誤答19/19/19、調整後は各1,316回答に揃えてSS複数1・記号的複数2・SS単一1だった。調整後2条件は共通の正の回答数がなく、比較に寄与しない。

曖昧性の追加前16条件は全て共通回答数0で比較不能。誤答率0として勝ちと数えない。追加後は各128回答・誤答0。五方式の補助比較もraw JSONに含むが、これらは記述的分析であり、評価正解で運用閾値を調整していない。

## 5. 費用

| 文章モデル | 保持数 | 位相ブロックbytes | 固定照会キャッシュbytes | コーデック等の配列bytes | 把握したpayload合計bytes |
|---|---:|---:|---:|---:|---:|
| 標準SS単一 | 1 | 1,331,200 | 1,310,720 | 11,272,192 | 13,914,112 |
| 標準SS複数／2例追加後 | 2 | 2,662,400 | 2,621,440 | 22,544,384 | 27,828,224 |
| 曖昧性の2例追加前 | 4 | 5,324,800 | 5,242,880 | 45,088,768 | 55,656,448 |

独立したモデルを複製する実装なので、把握したpayloadはほぼ保持数倍に増える。この表はPythonオブジェクト・ライブラリ・訓練時の一時配列・全プロセスRSSを含まない。

スカラー曖昧性D512の総係数固定では、2候補に256係数ずつ割当て、追加後は1候補に512係数。数値係数は両方8,192 bytesだが、状態全体は追加前12,288、追加後10,240 bytesであり、ヘッダ込み同一予算ではない。候補ごとにD512を割り当てる場合、追加前の数値係数は16,384 bytesになる。

主評価中の標準文章モデルの学習はSS複数7.87秒、記号的複数0.79秒、SS単一7.55秒、v0.9単一3.71秒だった。54代表例の一連の評価は約15秒／15秒／9秒／9秒。これらは二回目の評価と並行したローカル計測で、安定した速度比とはしない。

主評価・厳密再学習検証の終了後に行った独立したスカラー補助計測は `verification/BENCHMARK.json` を参照。5標準課題・第一置換・D2048・3反復だけの計測であり、自然言語処理全体の速度ではない。

この補助計測では、各課題の3反復中央値を取り、さらに5課題の中央値を取った学習時間がSS複数0.881秒、記号的複数0.0372秒、SS単一0.875秒、v0.9単一0.436秒だった。SS複数は記号的複数の約23.7倍で、SS選択は安価ではない。この標準課題では全方式が1候補に絞れ、学習後の一照会は約0.80〜0.83ミリ秒と同程度だった。複数候補を実際に使う場合の速度が同じという証明ではない。

## 7. 到達していないものと次の判断

候補の保持・比較・保留・教師追加後の解消は、この限定文法と特徴設計の範囲で実装できた。一方、候補が全員同じ誤りをする場合、設計した特徴群に正しい候補がない場合、候補上限が全体停止を招く場合は残る。

次に優先するなら、候補をさらに増やす前に「どの候補差が今回の照会に関係するか」を検証し、不確実性のない部分まで止める過剰保留を減らす。ただし今回その新機能は実装していない。正解ラベルを参照しない照会別の支持検査と、誤確定が増えないかの独立評価が必要になる。

三事象以上・自由長文・未知自然文・照応・省略、一般的な時間論理、特徴そのものの自律発見、例の自動収集、オンライン更新、記憶負荷偏り対策、全SS制御、P1数値部分観測／S1チップ列・同期への言語経路接続、Linux実機実行は未実施。R1推論・Concept更新を開放せず、`eligible_for_inference=false` を維持する。

独立評価器とは別実装の制御文法による採点であり、外部の人間による自然文評価ではない。正解率・再現性の高さを、これら未実施の到達点へ拡張してはならない。
