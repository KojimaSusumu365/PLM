# PLM-L1-SS-core v0.3 実施報告

SS化境界の監査と、読解・生成の時間波形SSコアへの統合。

## 結論

**限定二事象文の読解・生成について、SS連想の照合と意味信号の復元を共通の時間波形受信器へ移し、生成の次行動・次状態をSS遷移記憶から選ぶ経路を実装した。統合版は本評価48/48件で正しく生成した。ただし、まだ「ほぼすべてをSS型で動かす」段階ではない。**

文の分割、設計済みの特徴・意味スロット、辞書による意味の受渡し、行動解釈器、保留・版管理などの通常コードが残る。詳細は `BOUNDARY_AUDIT.md` に列挙した。今回の成果は言語能力の新規獲得や汎用的性能向上ではなく、既存能力を保持してSS実行範囲を広げたことである。

## 1. 今回広げたSS処理

1. 既存の10種類の言語連想記憶を、配列一括相関／回答キャッシュから、チップごとの受信・相関積算へ移した。記憶係数と候補受理基準は変更していない。
2. component/document/partialの意味信号の候補復元を、同じ受信器による相関へ移した。公開候補基底を同時照合し、窓の完了後に判定する。
3. 文内の語彙照会・記号出力・停止、文書内の事象選択・停止を、学習済みSS遷移記憶から選ぶようにした。次状態は位相信号で帰還し、通常コードのステップ番号加算で次行動を決めない。
4. 既存の訂正記憶の再照会も同じ受信器へ接続した。旧版の学習器・更新受理方針・pending台帳を置き換えた版ではない。

共通受信器は、言語連想1チャネル、行動／次状態2チャネル、訂正記憶4チャネルに対応する。これはチャネル数だけ異なる同じ積算器であり、言語照合を4回複製して独立性を主張するものではない。

## 2. 教師と設計が残る部分

新しい文内遷移は、既存モデルが学習済みの語順・助詞等を8条件、68遷移として転写した。文書順は設計済みの順序仕様を4例、12遷移として教えた。人物・動詞を含む完成文の丸ごと連想ではないが、正しい抽象手順を教師として与えている。

したがって「生の文章だけから構文・生成制御を発見した」とは言えない。意味の全体もまだ信号だけで流れるわけではなく、復元後の辞書から各照会文脈を作る。通常の処理をSS記憶に転写した部分と、既に学習済みの対応を波形実行へ移した部分を区別する。

## 3. 主比較の結果

開発4文書とは別に固定した24文書について、順序保持／主語焦点、逆順／第1文のみ目的語焦点の2種類を生成した。各方式48要求、計144要求。意味・時間関係・事象順・焦点を別実装の限定文法パーサーで確認した。

| 方式 | 正しい生成 | 保留 | 誤った文章 | 読出し窓 | 処理tick |
|---|---:|---:|---:|---:|---:|
| 旧配列照合＋従来の生成手順 | 48/48 | 0 | 0 | 計測対象外 | 計測対象外 |
| 波形照合＋従来の生成手順 | 48/48 | 0 | 0 | 4,992 | 16,674,816 |
| 波形照合＋SS遷移生成 | 48/48 | 0 | 0 | 4,800 | 21,387,264 |

統合版は1要求あたり平均445,568tick、波形照合だけの方式は347,392tickだった。窓数は減ったが、広い遷移記憶を読むためtick数は増えた。2チャネルの積算量、符号基底、ハッシュ、通常処理、I/O等も必要で、窓数だけから効率を判断しない。旧方式の `SUMMARY.json` のtick=0は計測対象外の印で、無演算という意味ではない。

評価は既知語彙・限定文法内で、二事象の肯否および仮定／断定は相補的な組合せに固定している。過去の全データとの非重複は保証していない。これは新規一般化、自由な日本語、長文生成の成績ではない。

3方式の対応する出力は表層も全件一致した。本版は旧方式より正しい文章が増えたという結果ではなく、同じ能力を異なるSS実行経路へ移せたという結果である。

## 4. 実際に生成した文章

### 時間関係が未指定のまま、事象の提示順を変える

入力：

> 由紀が美咲を褒めた。もし由紀を健太が助けなかったら。

逆順・第1文を目的語焦点にした出力：

> もし由紀を健太が助けなかったら。由紀が美咲を褒めた。

順序を変えても時間的な先後は勝手に補わず、否定と仮定を保持した。

### 先後関係を維持して逆順にする

入力：

> 次郎を由紀が褒めなかった。その後、もし花子が健太を褒めたら。

出力：

> もし健太を花子が褒めたら。その前に、由紀が次郎を褒めなかった。

表面的な並べ替えだけでなく、時間接続の「その後」を「その前に」へ対応させ、誰が誰を褒めるかと否定を保持した。

### 文章読解→外部P1/S1→別プロセス生成

入力：

> 太郎が花子を助けた。その後、もし次郎が美咲を褒めなかったら。

波形読解の結果を部分意味信号へ写し、既存P1/S1でチップ化・同期復調した後、別プロセスで両文を目的語焦点・逆順にして生成：

> もし美咲を次郎が褒めなかったら。その前に、花子を太郎が助けた。

`examples/EXAMPLE.json`、受信数値パケット、読解・復元の波形トレースを同梱した。この例は主比較48件に含めていない。

## 5. 費用と残る制約

既存の10言語メモリの数値係数1,310,720byteは不変。追加の遷移係数は524,288byteで、文内・文書に262,144byteずつ使う。追加学習は655,360write tick、2チャネル合計1,310,720個の複素係数加算。これにメタデータと公開符号基底・一時配列が加わる。

SS遷移が停止を選ぶことと、実行基盤がSSだけで動くことは同じではない。最大反復数、意味辞書、固定の行動解釈、受理閾値、文字組立てなどは通常コードに残る。SS状態も有限個の設計済み符号へクリーンアップする方式である。

本版は離散時間I/Qシミュレーション。言語内の受信器は窓境界既知で、一定位相のパイロット補償を行う。外部P1/S1の遅延・周波数探索全体を、言語内受信器へ移植したわけではない。旧v0.2で残った共通破損、偽教師、外部S1の保留条件を解決したとも主張しない。

次にSS化範囲を広げる場合は、読解の特徴・処理順の選択と、復元した意味辞書を介するスロット操作が主要な境界になる。今回の波形照合・SS状態帰還を基盤として使えるが、さらに移行の実証が必要である。

## 6. 補助試験の結果

| 試験 | 結果 |
|---|---|
| 一定位相ずれ0.73rad | 2/2で正しい生成 |
| payloadへ実部・虚部それぞれ標準偏差1の独立ガウス雑音 | 2/2で正しい生成 |
| 尾の打切り | 2/2で保留 |
| roles、lexical_write、temporal_writeの読出しをそれぞれゼロ化 | 計6/6で保留 |
| 文内行動記憶、文書行動記憶の読出しをそれぞれゼロ化 | 計4/4で保留 |
| 文内の次状態チャネルだけゼロ化 | 2/2で保留 |
| 未観測・複数候補・競合の部分意味 | 6/6で状態を保持し、文章を断定しない |
| 既存の外部P1/S1による意味信号の伝送・生成 | 2/2で正しい生成 |
| 訂正記憶への新規登録→保存→再ロード→欠損照会からの生成 | 2/2で正しい生成 |
| 未知語・未知動詞・仮定不整合・役割重複の入力 | 4/4で保留 |

故障18例の内訳は正しい生成4、保留14、誤文章0。少数例であり、耐雑音性能全体や安全性を保証する結果ではない。特に、誤った候補を一貫して支持する破損や誤教師は、本版で解決していない。

評価器に故障条件を置き、受信器へは数値サンプル・観測マスクだけを渡す。各読出しのnonceやパイロットが違っても、誤差の独立性が保証されるとは扱わない。正常条件の配列DACのpayloadは、同じ係数なら同じ数値になる。

`results/SUMMARY.json` の事前定義した主要判定は `primary_pass=true`。主比較144要求と補助試験32例は区別し、同じ場面の反復を新しい文章能力の数として数えない。

## 7. 再現性と検証

新規22テスト＋継承53テスト＝75種類に合格。主に、チップ順・窓終端・欠損・位相補償、従来照合器や生成器への迂回禁止、SS係数と次状態の必要性、保存・再ロードを確認した。

本評価前に145個のsource/model/program/data等のファイルを固定した。2回の全評価で、実行時間記録を除く131結果ファイルがバイト一致した。新しいSS遷移記憶を再学習して保存係数とビット一致すること、代表の読解生成1例と保存訂正記憶2例が再現することも確認した。

読解器・専用学習器・評価器をコピーしない隔離ディレクトリへモデルと実行コードだけを移し、保存した数値意味パケットから別プロセスで正しく生成した。共有モジュール内の未使用の教師補助関数定義等まで完全に除去したという意味ではない。この条件と結果は `verification/ISOLATED.json` に記録した。

前版v0.2の3,281ファイルとZIPが不変であること、およびコピーした122ファイルの一致も検査した。Windows／Python 3.12.14／NumPy 2.3.5で実行。初回の全評価は約1,163秒で、反復実行と並行しており公平な速度ベンチマークではない。
