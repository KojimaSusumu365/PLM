# SS化境界の監査 — core v0.3

## 判定

**まだ「ほぼすべてをSS型で動かす言語処理系」ではない。** 今回は、限定二事象文の読解・生成が利用する連想照合と意味信号の復元を、共通の離散時間波形受信器へ移し、生成行動と次状態の選択をSS遷移記憶へ移した。通常コードで残した意味構造・前処理・解釈器をSS実装と数えない。

Pythonで実装していること自体は非SSの理由ではない。学習係数と符号の相関が選択を担う箇所をSS演算とし、言語項目を直接調べる手続き、構造を決める規則、メタデータによる受理制御と区別する。コード行数やファイル名からSS化率は算出しない。

## 読解から出力までの境界

| 境界 | v0.2の実態 | v0.3で変更した範囲 | 残る通常処理／根拠コード |
|---|---|---|---|
| 文字→語・文の分割 | 既知語彙による分割、二／三事象の文境界分解 | 変更しない | `component/lexicon.py`, `ss_document/contract.py`。文境界をSSが自律発見したわけではない |
| 局所・文全体の特徴 | 語種・左右・形状・助詞間隙を辞書／リストで構成 | 変更しない | `component/features.py`。特徴設計・役割集合は既定 |
| 語彙・役割・肯否・仮定の選択 | SS結合重畳記憶だが配列相関、再照会では通常の回答キャッシュも使用 | 読解側の連想をチップ逐次相関へ。回答キャッシュを使わない | `ss_core_v03/banked.py`。バンクのハッシュ振分けと候補一覧は通常処理 |
| 語順支持・語順・助詞等の対応 | 学習済みSS連想、呼出し順と組立てはコード | 読解照合を波形化。生成では転写学習した行動／次状態記憶を使用 | SS遷移の教師は既存学習済み語順・間隙。生コーパスからの文法発見ではない |
| 意味信号の結合／復元 | 位相結合重畳、配列内積で候補復元 | component/document/partialの候補相関を共通受信器へ | 結合の役割・事象ID・時間項目・候補数の定義、復元後の辞書化、残差・閾値判定は通常コード |
| 事象の出力順 | preserve/reverseをリスト操作して順番に出力 | SS行動記憶が事象IDと停止を選ぶ | 教師の4例は設計済みのpreserve/reverse仕様から作成。ID体系と行動解釈器は既定 |
| 文内の出力手順 | 語順リストを走査し、各役割の表記と間隙を追加 | SS行動記憶が語彙照会・記号出力・停止を選ぶ。次状態は位相信号で帰還 | 行動を解釈して辞書から対象スロットへアクセスし、文字を追加する部分は通常処理 |
| 語彙表記・時間接続表現 | 学習済みSS連想 | 波形照合で選択 | 隣接事象を文脈へ写す関数と文字列連結は通常処理 |
| 訂正記憶の再照会 | v0.1/v0.2の4チャネル波形走査 | 同じ一般化受信器で4チャネル照合。保存形式と判定は維持 | レジストリ、版、保護領域の優先、pendingは非SS。既存の更新学習器は従来の波形実装のまま |
| 外部チップ化・同期・復調 | P1/S1の離散時間実装 | 既存経路へ接続して別枠で確認 | 今回の言語内受信器は既知窓境界＋パイロット位相補償。P1/S1の遅延・周波数探索全体を内蔵したものではない |
| 受理・保留・安全制御 | 固定閾値、票、集合検査、保留台帳 | 原則維持 | 比較器等をPythonで書くこと自体ではなく、意味状態や保留を手続き管理している境界を明示 |

## SS依存性の確認方法

- 従来の `MemoryBlock.recall` と `BankedMemory.recall` を例外化しても、統合経路で読み書きできることを試験する。回答キャッシュへの迂回は認めない。
- 従来のcomponent/document復元器を例外化しても、統合経路で読み書きできることを試験する。
- 生成時に従来の生成器、語順リスト取得、間隙取得を例外化しても、SS遷移で生成できることを試験する。
- 行動係数だけ、次状態係数だけ、語彙・時間表現等の読出しだけを無効にし、出力を保留するかを試験する。単に波形トレースを追加しただけではないことを確認する。
- 各照合の受信サンプル数、候補数、チャネル数、ハッシュを記録する。1回の意味パケット復元では、全候補を同時積算した同じ窓の結果を使用する。これは異なる照会への回答キャッシュではない。

## 信号のまま保持できたもの／できていないもの

生成プログラムの反復状態は数値の位相信号として保持する。学習済み係数を相関し、選んだ次状態の符号を次の照会に帰還する。次のステップ番号を単にコードで加算する方式ではない。終了もSS記憶が選ぶが、暴走防止の最大反復数は通常コードである。

一方、文章の意味全体は復元後に辞書へ戻り、役割・時間関係の文脈を組み立てる。このため「意味・制御が最初から最後まで信号だけで流れる」とは主張しない。SS状態も有限の候補符号へクリーンアップしており、自由な状態空間を学習したものではない。

## 実装上の限界

学習済み言語モデルの元のクラス・配列実装も互換性と比較のためZIPに残している。公開の統合CLIが通る経路と、単に同梱されている旧APIを区別する。既存TemporalModelの単独API等を直接呼べば旧経路になる。今回の対象は `ss_core_v03.runtime` と `ss_core_v03.correction` を通る限定経路である。

受信器は公開の候補符号しか持たず、学習係数は配列DACシミュレータから1tickずつ受け取る。ただしシミュレータ、呼出し側の整合ハッシュ処理、保存処理は通常のRAM配列にアクセスする。実装上のプロセス隔離や物理的アクセス制約を保証したものではない。

今回の進歩は「SS化した処理範囲が増えた」ことであり、「ほぼ全SS」「自由文の生成」「実機での動作」「人間の脳の再現」を意味しない。
