# PLM-L1-SS-multicode v0.1 実施報告

2026-09-08実施。「複数符号SS照合による、干渉誤りと未登録誤受理の低減」の独立試験版。

## 1. 結論

独立したSS符号による複数読出し、系間一致による受理、別の入力／ラベル重畳信号による照合を実装し、逐次学習・忘却・誤教師・正解変更を試験した。

結果は「独立符号は役立つが、複数系へ分けて厳しく照合すれば常に良くなるわけではない」だった。

1. 同一符号の4コピーは128次元一系と同じ結果だった。コピーによる多数決では共通の誤りは消えない。
2. 独立128次元×4系の平均読出しは、単一128次元より既登録誤答と未登録誤受理を減らした。ただし学習係数量が四倍なので、この比較だけで方式の優位性を主張しない。
3. 同じ学習係数量の単一512次元と比べると、独立4系は未登録誤受理が少ない一方、古い記憶を正しく受理できる件数が大幅に減った。
4. 別のSS信号による照合は、通していた誤答・未登録照会を保留へ回せた。しかし正答も多く保留した。候補を正しい候補へ直した実証ではない。
5. 同じ四つの独立符号でも、残差を全系で共有する構成は、各128次元系を個別に更新する構成より記憶保持が良かった。符号の独立性だけでなく、更新と読出しの整合が重要だと分かった。

今回の代表条件では、単一長符号／共有残差の方が正答保持とのバランスが良く、複数独立系の全面的な採用を支持する結果ではない。既存言語コアや前版を置換せず、結果・全コード・生相関を保存した。

## 2. 比較設計と資源

### 2.1 記憶構成

入力は4項目、各値は既知の8種類、ラベルは既知の4種類。項目／値の単位複素位相符号の積を完全文脈符号bとする。係数はcomplex128。

| 構成 | 読出しと学習 | 学習係数bytes |
|---|---|---:|
| single128 | 128次元一系、残差更新 | 8,192 |
| single512 | 512次元一系、残差更新 | 32,768 |
| concat512 | 独立128次元×4ブロック、平均相関に対する共有残差 | 32,768 |
| multi4 | 独立128次元×4系、各系の残差 | 32,768 |
| clone4 | single128と同じ符号のコピー×4系、各系の残差 | 32,768 |
| checked | 独立128次元×3系＋独立512次元の入力／ラベル照合信号 | 32,768 |
| exact | 完全キーと最新の教師ラベルの正確な対応表 | キー数依存 |

SS方式に完全キーの対応表は持たせない。過去教師の再提示バッファはどの方式にもない。exactだけは明示的な非SS対照である。

同じなのは主要な学習係数の配列量である。符号キャッシュ、通常のメタデータ、総RAM、計算量、実時間、消費電力まで同じとはしない。

### 2.2 更新の違い

通常の各系更新は次のとおり。教師のラベルに1、他の既知ラベルに0を与える。

```text
s[k,y] = Re[conj(H[k,y]) dot b[k]] / D
H[k,y] += 0.5 * (target[y] - s[k,y]) * b[k]
```

concat512はs[k,y]を四系平均のs_mean[y]に置き換える。四ブロックを連結したxとH_flatについて、

```text
s_mean[y] = Re[conj(H_flat[y]) dot x] / 512
```

となるため、512次元の一系へ連結した通常の残差更新と代数的に等価である。単体テストで係数更新の等価性を確認した。concat512とmulti4には同じ四つの符号を使い、共有残差か各系残差かを切り分けた。

checkedの照合記憶Gは一本の512次元配列である。各入力／ラベル組の符号を `z[y] = 入力符号 × ラベル符号[y]` とし、

```text
c[y] = Re[conj(G) dot z[y]] / 512
G += 0.5 * sum_y((target[y] - c[y]) * z[y])
```

で更新する。一件の教師から四つの既知候補への残差を同時に訂正する。未登録キーを負例としてH/Gへ教えない。照合はSSの積結合・重畳・相関で実行するが、符号距離に基づく訂正保証や正確な会員判定機能ではない。

### 2.3 候補と受理の区別

暫定候補は各系の相関の平均のargmax。ただし上位差1e-12以下なら未定。

| 方針 | 受理条件 |
|---|---|
| mean | 平均相関0.5以上のラベルが一つだけ |
| quorum | meanを満たし、各系でも0.5以上のラベルが一つだけで平均候補と一致する系が75%以上 |
| unanimous | 同じ条件を全系が満たす |
| pair_check | meanを満たし、照合信号も0.5以上のラベルが一つだけで候補と一致 |
| quorum_pair_check | quorumとpair_checkの両方 |
| calibrated | 開発データで選び、本試験前に固定した閾値・必要一致数・照合条件 |

固定の照合ゲートは候補を保留するだけであり、別の候補へ変更しない。したがって、ゲートで誤答が減っても、そのまま「誤答を正答へ訂正した」とは呼ばない。

相関は確率ではない。教師入力は要求ID・状態指紋を持つ別のAPI応答として受け取り、予測結果を自動で教師へ転用しない。古い要求、改変要求、余分な真値、未知ラベル、source=model_predictionを拒否する。external_teacherはAPI上の宣言で、本人認証・正解保証ではない。本試験の教師は人工評価器であり、人間や外部サービスを呼んでいない。

## 3. データ・校正・試験の範囲

各データでA/B/C各64キーを四周ずつ学習し、Aを一周再訪する。その後Aの16キーの正解を変更し、それらを四周教える。各過程896教師、学習済みキーは計192種類。別の128キーは一度も教えない。

cleanと、Aの最初の一周だけ8教師回答を誤らせるnoisy_firstを比較した。全方式は同じ教師順・同じ回答を受ける。誤教師は8/896であり、継続的な高率ノイズ試験ではない。ラベルの意味付けは人工的で、自然文や未見規則の汎化試験ではない。

開発2データと本試験4データは別seedを使い、毎回新しい学習器を作る。一つのデータ内では学習192キーと未登録128キーは重複しない。一方、全4096通りの入力組合せはデータセット間で重なり得る。未知語彙や完全に分離された言語課題へ一般化したとは主張しない。

### 校正に使った情報

開発2データ、code-dev、cleanのA四周後・B四周後・C四周後を使った。既登録照会768件、未登録照会768件を各構成で評価した。これは同じキーの複数時点の照会を含み、768件の独立課題ではない。

閾値0.25〜1.25を0.05刻み、一致数0〜系数、照合なし／閾値0.25・0.5・0.75・1.0の事前固定グリッドから選ぶ。開発上の未登録誤受理率1%以下、受理した既登録回答の誤答率1%以下を満たす中で、既登録の正受理を最大化した。同数なら未登録誤受理、既登録誤答、グリッド順で決定する。全保留の退避方針も用意した。

未登録であるという検証情報は、受理基準への追加の教師情報である。全方式へ同じ情報を与えるが、H/Gの学習には渡さない。校正なしの固定方針と分けて報告する。開発グリッドは合計805候補で、全結果を配布した。

選ばれた方針はsingle128/clone4が閾値0.9、single512/concat512が0.55、multi4/checkedが0.5、exactが0.25だった。いずれも追加一致数0、照合条件なしとなった。特にcheckedのcalibratedは、Gを保存・更新・計算するが受理のゲートに使わない。この条件下の校正は追加照合を選ばなかった、という結果である。

### 本試験

4データ×2符号seed×2シナリオ×SS6構成＝96過程。exactは4データ×2シナリオの8過程。計104過程、93,184教師提示を一回の全試験で行い、同じ凍結内容から二回実行した。

各過程19時点を固定照会し、1,976スナップショットを保存した。読出し・照合の生相関に加え、各教師提示の直前・直後の生相関を保存し、計4,368配列となった。照合のない構成では幅0の照合配列も数に含む。

開発後・本試験前にコード、55単体テスト、プロトコル、データ、選択方針を凍結した。本試験結果を見て閾値や学習器を変更していない。第三者の事前登録ではなく、有限seedの記述的試験である。有意差・普遍的誤り率・本番保証は主張しない。

## 4. 主結果：干渉誤りと未登録受理

以下はclean、C四周終了後。SSは4データ×2符号＝8試行。既登録A/B/Cは合計192×8＝1,536照会、未登録は128×8＝1,024照会。正受理／誤受理／保留を分ける。

| 構成・固定方針 | 既登録正受理 | 既登録誤受理 | 既登録保留 | 未登録誤受理 |
|---|---:|---:|---:|---:|
| single128・mean | 1,098 | 50 | 388 | 245 |
| clone4・mean | 1,098 | 50 | 388 | 245 |
| single512・mean | 1,514 | 0 | 22 | 22 |
| concat512・mean | 1,514 | 0 | 22 | 19 |
| multi4・mean | 1,296 | 0 | 240 | 9 |
| multi4・3/4一致 | 935 | 0 | 601 | 3 |
| multi4・全系一致 | 655 | 0 | 881 | 0 |
| checked・照合なしmean | 1,269 | 2 | 265 | 32 |
| checked・pair_check | 976 | 0 | 560 | 3 |

### 独立符号の効果と限界

コピーでは結果が変わらない一方、独立4系のmeanでは、128次元一系に比べ正受理が増え、誤受理も減った。ただしこの比較は学習係数量が四倍である。

同じ係数量のsingle512に比べると、multi4は未登録誤受理を22→9件へ減らしたが、正受理も1,514→1,296件へ減った。正受理率98.6%と84.4%の差があり、「同じ答えられる量で誤りだけを減らせた」とは言えない。

暫定候補自体の既登録誤りはsingle128/clone4で180件、single512で2件、concat512で0件、multi4で16件、checkedで31件だった。強いゲートの追加はこれらの暫定誤りを訂正していない。

clone4の各系の生相関は、全304スナップショットでsingle128と一致した。未登録の入力／候補スコア間の系間相関もコピーでは1、異なる符号を使った構成では平均がおおむね0に近かった。ただしこの有限データの相関は、判断の独立性や誤り確率の積算を保証しない。

### 照合で消えたものを分ける

multi4の3/4一致は、meanが正しく受理した361件を保留にし、未登録誤受理6件を抑えた。全系一致は正答641件を保留にし、未登録誤受理9件を抑えた。0/1,024誤受理だけを取り出して成功とはしない。

checkedのpair_checkは、照合なしに比べ既登録誤答2件と未登録誤受理29件を保留にできた。同時に正答293件も保留へ回した。SS信号による照合は働いたが、保持した情報を上手に使い切る設計にはまだなっていない。

## 5. 校正しても同じ結論か

cleanのA四周後・B四周後・C四周後を、開発と同じ集計方法で評価した。SS各構成は既登録3,072照会、未登録3,072照会。学習前のB/Cはこの既登録集合に入れず、未登録の分母には専用の128キーだけを使う。

| 校正済み構成 | 既登録正受理 | 既登録誤受理 | 保留 | 未登録誤受理 |
|---|---:|---:|---:|---:|
| single128 / clone4 | 808 | 8 | 2,256 | 29 |
| single512 | 3,028 | 1 | 43 | 12 |
| concat512 | 3,040 | 0 | 32 | 11 |
| multi4 | 2,798 | 0 | 274 | 13 |
| checked | 2,763 | 2 | 307 | 42 |

この集計では、長符号側も閾値校正によって未登録誤受理を減らせた。複数独立系だけに校正を許して単一系に固定閾値を使う、といった比較はしていない。開発で1%以下だったcheckedの未登録誤受理は、本試験で42/3,072＝約1.37%となった。開発での制約は本試験の誤り率保証ではない。

C四周後だけなら、校正single512は正受理1,495・誤受理1・保留40、未登録誤受理9。multi4は正受理1,296・誤受理0・保留240、未登録誤受理9だった。既登録誤受理の一件差はあるものの、複数系が正答保持と未登録拒否を同時に優越した結果ではない。

注意点として、「閾値以上のラベルが一つだけ」という受理則では、閾値を上げたときに、以前は複数ヒットで保留していた候補が一つだけ残ることがある。閾値を上げれば常に受理集合が縮むわけではない。single512では固定0.5で0件だったC後の既登録誤受理が、校正0.55で1件となった。これも隠さず記録した。固定quorum/pair_checkはmeanの受理集合の部分集合だが、閾値そのものの変更は別である。

exactは符号seedを重複実行しない4試行で、この三時点合計は既登録1,536/1,536正受理、未登録0/1,536誤受理。既知の完全キーを記憶する課題におけるSS固有の精度優位性は示していない。

## 6. 忘却、誤教師、正解変更

### 6.1 Aの記憶保持と再訪

clean・mean。Aは64×8＝512照会。表の各値は正受理／誤受理／保留。

| 構成 | A四周後 | B四周後 | C四周後 | Aを一周再訪後 |
|---|---:|---:|---:|---:|
| single512 | 512 / 0 / 0 | 511 / 0 / 1 | 491 / 0 / 21 | 512 / 0 / 0 |
| concat512 | 512 / 0 / 0 | 512 / 0 / 0 | 492 / 0 / 20 | 512 / 0 / 0 |
| multi4 | 512 / 0 / 0 | 478 / 0 / 34 | 320 / 0 / 192 | 510 / 0 / 2 |
| checked・照合なし | 512 / 0 / 0 | 470 / 0 / 42 | 314 / 2 / 196 | 505 / 0 / 7 |

meanのA終了時の基準集合は各512件なので、C後の正受理脱落は順に21・20・192・198件。暫定的には正しい候補が出ても相関の強さが足りず、保留になった項目を含む。「誤ラベルに変わった数」と「正しく確定できなくなった数」を分ける。

各固定／校正方針ごとに基準集合を作り、初めから受理できなかったキーを忘却の分母へ加えない。基準集合が空の場合も成功扱いしない。今回の忘却は後続学習による干渉であり、時間減衰や意図的消去の試験ではない。

同じ独立符号でもconcat512とmulti4の保持は異なる。独立性が悪いというより、各128次元に全項目を個別に学ばせる更新と、512次元全体の残差を共有する更新の違いが大きい、という結果である。

### 6.2 最初だけ誤教師が混ざる場合

noisy_first・mean、A各512照会。最初の一周では8試行で計64教師回答が誤っている。

| 構成 | A一周後 正／誤／保 | 二周後 | 三周後 |
|---|---:|---:|---:|
| single512 | 194 / 25 / 293 | 472 / 0 / 40 | 512 / 0 / 0 |
| concat512 | 181 / 28 / 303 | 478 / 0 / 34 | 512 / 0 / 0 |
| multi4 | 113 / 20 / 379 | 470 / 0 / 42 | 512 / 0 / 0 |
| checked・照合なし | 144 / 19 / 349 | 470 / 0 / 42 | 512 / 0 / 0 |

後続の正しい教師で回復した。ただし、全系は同じ教師を受けるため、誤教師という共通原因への独立な裏付けにはならない。教師の誤りを自力で見抜いた実験ではない。

### 6.3 正解変更への適応

clean・mean。変更群16×8＝128照会。single512とconcat512は新教師前に128件とも旧記憶を受理しており、新しい正解に対しては誤りだった。一周後はsingle512で正63・誤18・保47、concat512で正60・誤11・保57。multi4は正58・誤0・保70、checkedのmeanは正70・誤3・保55。二周後には四構成とも128件すべて新しい正解を受理した。

変わらなかった48×8＝384照会では、変更群四周学習後にsingle512/concat512は384件を正受理、multi4は378件を正受理し6件保留、checkedのmeanは364件を正受理し20件保留した。変更への適応と、変わらない情報の保持を分けて評価した。

## 7. 保存量・実行時間

学習係数量が32,768 bytesで同じでも、全語彙符号を生成済みのキャッシュはsingle512/concat512/multi4/clone4で262,144 bytes、checkedで491,520 bytesだった。checkedは1.875倍のキャッシュを持つ。single128は65,536 bytes。これらは配列量であって、Pythonオブジェクト・OS・一時配列を含むピークRSSではない。

各過程の教師提示は896回。multi4/concat512/clone4は3,584回の読出しブロック更新、checkedは2,688回の読出し更新と896回の照合ベクトル更新を行う。各更新の次元・候補数が異なるため、更新回数だけを計算量としない。checkedには教師一件当たり4×512要素の照合相関が追加される。実装全体では要求の検証や予測のために同じ相関を再計算する箇所もあり、記録した更新要素数を総FLOPsと呼ばない。

独立のベンチマークデータで、最初の256教師を各構成三回、新しい学習器から実行した。二回の全試験と前版検証の終了後、一プロセスで測定した。

要求生成・検証・指紋計算・状態コピー・更新を含むPython実装の測定であり、純粋なSS演算器の速度や消費電力優位性ではない。校正checkedの照合条件は不採用だが、照合記憶の更新・スコア計算は残っているため、その費用も含む。

## 9. 配布物と使い方

`README.md`にインストール・一件学習・予測・全試験再現のコマンドがある。`ss_multicode/`に予測用と学習用のコードを分離した。`evaluation/`・`data/`・`tests/`に固定プロトコル・人工データ・校正・テストを含む。

`results/EVALUATION.json`が全104過程の指標、`results/SCORES.npz`が教師提示前後と固定照会の生相関。入力・教師・真値の系列は同梱データと `events_for`／`stream` で再現できる。`results/`内には21保存学習器を含み、その `model/` だけで予測できる。

`verification/`にはSUMMARY、全校正グリッド、対応のあるC後比較、符号間相関、計測、反復一致、既存版保全、分離検証とログを含む。`examples/`に保存済みchecked-Aに対する人工教師一件の要求・回答・期待する更新結果を別ファイルで用意した。これは自然文の読み書き実演ではない。

`vendor/PLM-L1-SS-online-v0.1.zip`は前版の元ZIPをそのまま同梱したもので、SHA-256は `8f6bc734ec6578fc7756168c298c87f43f3d8fb838f1f0104bd6c0b16a1c3c1a`。

保存モデルの標準受理方針は校正済み方針である。新規に `start --architecture checked` で作る場合の初期方針は固定pair_check。名前が同じ構成でも受理方針が違うので、`model.json` のacceptanceを確認する。

## 10. 次に進むなら

本結果からは、全系一致をさらに強めるより、「全体の残差を共有して記憶を保持し、照合の不一致を追加教師の選択へ使う」方向を優先したい。今回のゲートは答えを捨てるだけであり、不一致を有用な追加情報へ変換していないためである。

具体的には、共有残差の長符号を基準に、通常照会と曖昧照会を分け、同じ追加教師予算で、不一致の大きい例を選ぶ方式とランダム選択を比較する。教師獲得による正答への回復、古い記憶への副作用、未登録誤受理、総計算・保存量を測る。現時点では提案であり、この版で実施済みではない。

長期目標であるSS中心の言語処理系へは、今回、記憶の符号・更新・照合の選択に関する証拠が増えた。自然文、未知語彙、部分観測、二事象の依存候補、Resonatorの反復分解、SS型の教師バッファ、脳/STDP、P1/S1同期との統合は実装していない。全出力は `eligible_for_inference=false` を維持する。
