# v0.6 コーパス

## 何を学ぶ教材か

本版では、文章・意味・訂正対象・確認内容・その後の意味保持を対応付けた合成コーパスを使用します。一般の文章を大量収集したものではありません。言語モデルの語彙・文法は既存のものを保持し、今回学習するのは「どのSS照合状態で確認すると保持に役立ちやすいか」という価値です。

## 場面データ

[DELAY_DATASETS.json](data/DELAY_DATASETS.json) の分割：

|分割|用途|焦点文書|背景出来事|合計エピソード|
|---|---|---:|---:|---:|
|development|動作確認|6|96|102|
|500|選択器学習|12|320|332|
|501|選択器学習|12|320|332|
|400|未使用場面での評価|12|320|332|
|401|未使用場面での評価|12|320|332|

合計1,430エピソードです。学習・評価それぞれの焦点文書は24件。評価分割は各々2事象6件・3事象6件です。複数の符号seedと実験条件で繰り返す件数を、独立な文章数とは数えません。

各エピソードは初期意味、訂正対象2つ、確認の系列、最終意味を持ちます。焦点文書はA1→B1→A2→B2→A3の5回確認、背景は1つの対象を2回確認します。背景の2回目は同じ値を再確認するものです。初期・途中・最終・古い値を含む場面の対応を保存しています。

新しい場面は、これまでの除外対象とv0.5の全分割から得た2,431指紋を避けて作成しました。さらに、本版の異なるエピソード間でも全改訂段階の指紋を重複させません。指紋は事象ID、提示順、時間関係を捨てた事象集合なので、時間順を変えただけの同じ場面も重複と判定します。同一エピソード内で同じ状態に戻ることは許します。

[除外指紋](data/DELAY_EXCLUSIONS.json)、[監査](verification/DATA_AUDIT.json)、[再構築コード](evaluation/delay_cases.py) を含みます。語彙や文型の共有は許しており、未知語・未知文法の汎化を測る設計ではありません。

## 選択器用の576件の対比較教材

学習分割2つ × 内容SSの符号seed2つ × 内容記憶構成2つ × 背景負荷3段階 × 候補24項目 = 576件です。各教材は次のように作ります。

1. その時点のSS記憶から、候補と同じ文書内のもう一つの対象について数値特徴を取得。
2. 確認なしの枝と、その候補を1回外部確認した枝に分ける。
3. 両方へ同じ新規背景64件を、同じ順序で各2回学習させる。
4. その文書の意味がどれだけ保持されたかの差を、選択器の教師値にする。

教師値は `(2×文書正解 + 正しい対象数 − 4×誤生成可能な文書) / 4` の確認あり／なしの差です。選択した文書以外への干渉効果も記録しますが、この最小版の教師値には含めません。全体最適な選択器ではありません。

[EXAMPLES.json](training_results/EXAMPLES.json) は特徴・教師値・確認前後の意味判定・副作用の対応を持ちます。[TRAINING.json](training_results/TRAINING.json) は学習回数、損失、教師値の分布、容量を記録します。学習用の出来事IDや正解値は監査のために教材へ残しますが、選択器へ渡す入力は18個の数値特徴だけです。

これはオフラインで正解を参照して構築した教材です。576回の仮想的な確認と背景学習の計算費用を、評価時の6回の回答に混ぜたり、無料の経験として隠したりしません。実際の人間が576回回答した記録でもありません。

## 評価時の境界

評価時は学習済み選択器を固定します。選択器は正解表、教師値、確認後の未来の保持結果を見ません。選ばれた1項目についてだけ評価側が外部回答を供給し、内容SSを更新します。選択器自体のオンライン再学習は実施しません。

評価には、学習とは別の場面と3つの別符号seedを使います。ただし背景量の0/64/256、追加64件という負荷設計は共通です。未知の負荷スケジュールへの汎化や自然な実文書への対応は、今回の達成範囲ではありません。
