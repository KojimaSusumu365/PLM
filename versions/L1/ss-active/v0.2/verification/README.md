# 検証資料の読み方

このフォルダは評価・配布検証用です。予測や教師選択の実行には不要です。`ss_active` と `ss_multicode` からこのフォルダを読み込む処理はありません。

## 検証の区分

1. `tests/test_active2.py`：62単体試験。候補・台帳の入力検査、探索と再確認の割当、待機・支持低下・最大回数、教師予算、要求・回答、保存再開、共有更新の平坦512次元モデルとの一致、評価集計、開発の設定選定規則を検査します。
2. `DEVELOPMENT_AUDIT.json`：開発評価の生相関・全測定時点の指標・2世界の初回要求・再確認切替前の一致を、本評価前に検算した結果です。
3. `REPEATABILITY.json`：本評価を別出力先で2回実行し、時間記録を除く260ファイルがバイト一致したことを記録します。
4. `isolation/VERIFICATION.json`：全開発・本評価の生相関と指標を再計算し、保存対象の代表10取得系列と2基礎学習・対照を別の一時ディレクトリで再学習します。
5. 配布ZIP外側の `PLM-L1-SS-active-v0.2-VERIFICATION.json`：作成したZIPを実際に展開して検証器を実行した結果です。ZIP自身のハッシュを含むため、循環参照を避けて外側に置きます。

全320取得系列を隔離検証で再学習するわけではありません。全系列の数値再計算、全系列の二重実行、代表系列の独立プロセス再学習を区別してください。再計算でも同じ指標実装を使う部分があり、仕様そのものの独立した意味レビューの代替ではありません。

## 教師と選択器の境界

学習用の隔離プロセスには、学習に必要な基礎・背景の教師列と、選択済み項目に対する応答列を渡します。一方、選択器の入力はSSモデル、ラベルなし文脈・数値台帳・設定・現在ステップだけです。真の正誤や、未選択候補の現在の正解表を選択APIに渡しません。

予測・選択専用の一時ディレクトリには、学習器・セッションコード・教師列・評価データを置かず、保存モデルとラベルなし選択状態から実行します。ここでいう「教師なし」は、実行時に教師回答や正解表を必要としないという意味です。SSモデルは当然、過去の教師から学習した係数を持っています。

要求ID・状態指紋は整合確認用のハッシュで、電子署名ではありません。`source=external_teacher` も宣言であり、第三者の本人性・正しさを認証しません。通常のPythonオブジェクトやファイルへの悪意ある改変を全面的に防ぐOSセキュリティ機構ではありません。

## 集計上の注意

- 取得件数と異なる文脈数を分けます。再確認1件は新しい外部教師1件を消費し、変更項目の「新規発見」には重複計上しません。
- 再確認の有無だけを変えた対では最初の16件のSS状態・訂正集合が同一です。探索を変えた対では訂正集合が変わるため、その集合の正解件数差だけで保持効果を主張しません。
- 2取得シードは同じデータ・符号の基礎状態を共有します。16系列を16個の独立データ集合とは扱いません。
- 追加教師なし対照は、同じ基礎状態の2取得シードに対応させる表示上の重み付けを行います。実際の対照学習を二重に実行したという意味ではありません。
- SS相関、上位候補間の差、符号の投票割合は校正された正解確率ではありません。
- `post_margin` は過去の教師ラベルに固定した支持ではありません。誤答への確信が強まる再発を見逃す可能性があります。
- 一致試験に時間測定を含めません。教師件数と係数容量が同じでも、選択計算量・台帳量は同じではありません。

## 初回作成用スクリプト

`preflight.py` は開発結果の検算、`collect.py` は二重実行確認・保全・集計・単一プロセス測定・実例生成、`make_tables.py` は結果からの数表生成、`document_qa.py` は報告表とJSONの照合・CLI例の実行を行います。既存出力への上書きを避けるため、配布物に対してそのまま再実行すると拒否する場合があります。通常の再検証にはルートの `verify_release.py --out <新しい外部フォルダ>` を使用してください。

`BASELINE.json` は旧成果物6,021ファイルのハッシュ、`PRESERVATION.json` はその不変確認です。さらに配布直前にも旧ファイルを再チェックします。前版の検証結果は `previous/` にあり、旧版のコード・結果は変更していません。
