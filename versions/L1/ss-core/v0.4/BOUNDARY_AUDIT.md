# v0.4 SS化境界監査

結論：読解後の意味保持・役割参照・局所訂正・生成オペランドの経路をSS信号で直結した最小実証である。「ほぼ全SS」の達成宣言ではない。

|処理|v0.4 の実装|残る非SS処理・限定|
|---|---|---|
|文字入力/読解|既存v0.3の波形型SS照合を再利用|文字切出し、構造組立て、意味辞書の中間状態は旧読解器内に残る|
|意味の永続状態|内容と状態の2重畳波形|固定12アドレス/19値/5状態の公開基底|
|役割参照|事象信号×役割信号で逆結合、時系列相関|候補ランキング、閾値、既知/未確定の規約|
|局所更新|対象の旧候補和を除去し、教師信号をチップ加算|外部教師の選択、ドメイン設計、ステージングと合否制御|
|非対象保持|全11項目をSS再照合|信号和の数値一致比較|
|生成計画|旧学習済み文/文書プログラムを時間波形SSで実行|固定opcode実行器・上限・終了条件|
|生成オペランド|役割/事象/表層をSS対応記憶で回収|接続教師は設計/既存記憶から転写|
|語彙/時間接続|値/関係信号から表層信号をSS回収|既知の限定語彙・限定時間関係|
|出力|Terminalのみで表層信号を文字へ戻す|文字列連結・表示|
|学習|符号対応とドメイン証拠を加算学習|コーパス生成、符号設計、既存文法重みの再利用|
|同期復調|既存の逐次I/Q受信とパイロット検査|配列DAC、物理装置/新WMのCFO探索試験なし|

## 辞書を隠しただけでないことの検査

1. WorkingMemory は `(2,8192)` の信号だけを意味状態として保存し、値スロットの辞書を持たない。
2. Core.generateの入力はWMと数値制御信号。評価用の正解意味・文章は受け取らない。
3. 旧Model/Document/Wave系のrecover/generateと診断用observeを例外化する試験でも、新生成器は正しい出力を返す。
4. 内容信号、状態信号、語彙対応重み、操作/オペランド対応重み、ドメイン証拠を破壊する削除試験で、隠れた正解による生成継続がないか確認する。
5. 別プロセスの最小配置では、旧読解器・旧生成器・意味教師境界・IO.json・評価器・自然文/意味データを除去し、数値WM/制御信号と数値束だけから生成する。

最後の配置には既存数値ヘルパー algebra/banked/projection が依存関係として残る。これらには旧方式の汎用関数定義も含まれるが、旧言語モデル、読解/生成runtime、元文章、正解辞書は存在しない。隔離テストは「すべての旧コードがゼロ」を証明するものではない。

## 安全性の読み方

未確定状態は曖昧なまま保存するが、今回の文章生成は保留する。「不明」を含む文を能動的に書く機能はない。訂正APIの失敗時に文章を返さない一方、別リクエストで旧状態を利用する呼出側の業務制御は対象外。

独立した事実源、教師認証、悪意ある整合信号、共通原因の符号破損、長時間の学習干渉への保証はない。状態や値が数値的に整合することと、記載された事実が真であることは異なる。

## SS比率を提示しない理由

行数比・処理名の個数・内積の使用有無から「95% SS」等を算出していない。対象となる意味値の受渡しを直接追い、残る制御/教師/入出力を境界として示す。性能、機能範囲、計算コストは別に評価する。
