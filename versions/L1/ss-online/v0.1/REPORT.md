# PLM-L1-SS-online v0.1 実施報告

実施日：2026-09-08。対象：SS型の逐次誤差訂正学習と忘却の検証。

## 1. 結論

外部教師の回答を一件ずつ受けてSS記憶を訂正し、反復経験によって同じ項目への誤りを減らす最小実証を実装した。過去の全教師を使った一括再学習ではなく、現在の記憶と一件の教師回答から更新する。

代表条件のD128・誤教師なしでは、通常の逐次誤差訂正 `delta` の教師回答前の暫定誤りが、一周目290件、二周目16件、三周目0件へ減った。各周は同じ64キー×6試行＝384照会であり、384種類の独立課題や未知の自然文に対する成績ではない。

同時に、Aを学んだ後にB・Cを学ぶとAの正受理は384件から181件へ低下した。32観測の過去教師バッファを使う `replay32` では231件が残ったが、未登録照会の誤受理も183/768から224/768へ増えた。反復による改善と、新規学習による干渉、保持と誤受理のトレードオフを、いずれも隠さず記録した。

「誤るから学習できない」ではなく、「誤りを訂正でき、訂正後の回復と別の記憶への副作用を測れる」段階へ進めた、と評価する。ただしSS固有の優位性や自然言語能力を示したものではない。同じキーを正確な対応表に保存する `exact` は、本試験の清浄条件で忘却も未登録誤受理も起こさなかった。

本版は独立実験 `PLM-L1-SS-online-v0.1` とした。既存v0.13・重み付け試験版・共通履歴を変更せず、正式な言語コアへ自動昇格していない。

## 2. 実装と境界

### SS記憶と更新

4項目の項目／値を単位複素位相符号へ変換し、その積を完全文脈の符号bとする。Dは符号長。クラス別の記憶Hはcomplex128の4×D配列である。

```text
s_y = Re[conj(H_y) dot b] / D
t_y = 1（教師のラベルと一致）、それ以外0
H_y ← H_y + 0.5 × (t_y − s_y) × b
```

全クラスにこの残差更新を行う。bの二乗ノルムがDなので、正規化したLMS型の数値的な誤差訂正に相当する。係数0.5は設計値で、学習した係数ではない。SS位相代数は旧版から変更せず継承した。記憶配列には完全キーの対応表を保持しない。

| 方法 | 教師一件当たりの処理 | 過去教師の保存 |
|---|---|---|
| accumulate | 正解クラスへbを一回加算。重複も加算 | なし |
| delta | 現在の教師で残差更新を一回 | なし |
| delta5 | 現在の同じ教師で残差更新を五回 | なし |
| replay32 | 現在の教師で一回、保存した過去教師で四回 | 通常データの最大32観測 |
| exact | 完全キーのラベルを保存・上書き | 完全キー対応表 |

再提示バッファは通常の教師付き文脈データであり、SS信号ではない。観測単位のreservoir方式で、同じキーの複数観測を含み得る。選択はハッシュに基づいて再現可能にした。新しい教師が届いたキーについてのみ、バッファ内の同じキーのラベルも更新する。まだ訂正を受け取っていない別のキーを、評価用の真のラベルで書き換えることはしない。

今回検証した忘却は、後続の学習による記憶干渉・回答の脱落である。時間経過だけによる減衰、意図的な消去、重要度に応じた忘却率、睡眠モデルは実装していない。

### 教師と予測の分離

`question` は予測と教師要求を別オブジェクトで返す。要求は文脈・状態指紋・要求IDを含む。`answer` は明示的な教師応答を検証してから新しい学習器を返す。元の学習器は上書きしない。

- 予測結果を教師入力へ自動接続しない。
- 古い状態への要求、改変した要求、不明ラベル、余分な真値フィールド、不正なsourceを拒否する。
- `source=external_teacher` は呼び出し側の宣言であって、回答の正しさや人間本人を認証する機能ではない。
- 本試験の教師は人工評価器である。人間や外部サービスへ回答を依頼していない。
- 予測だけでは学習済みH・学習状態指紋は変わらない。符号のキャッシュ生成は許す。
- 予測用 `model/` と学習用 `learner.json` を分離した。予測器はバッファや教師系列なしで動く。

出力には二段階を設けた。

| 出力 | 判定 |
|---|---|
| tentative：暫定候補 | 最大相関のラベル。ただし上位差が1e-12以下なら未定 |
| accepted：受理回答 | 相関0.5以上のクラスがちょうど一つならそのラベル、それ以外は保留 |

相関値は正解確率ではない。未登録かどうかの正確な判定器もない。全出力の `eligible_for_inference=false` を維持した。暫定的に試して訂正を受けることと、外部へ事実として確定することを区別する。

## 3. 試験設計

語彙は4項目×各8値、ラベルは既知の4種類。完全キー4096通りから、A/B/C各64キーと一度も教えない128キーを重複なく選ぶ。A/B/Cそれぞれのラベル数を均等にし、対応自体は擬似ランダムにした。新しいラベルの発見や未見規則の汎化を試す設計ではない。

| 段階 | 外部教師の提示 | 累積提示数 | 観測するもの |
|---|---:|---:|---|
| A学習 | 64キー×4周 | 256 | 反復による訂正・誤りの再発 |
| B学習 | 別の64キー×4周 | 512 | Aの保持とBの獲得 |
| C学習 | 別の64キー×4周 | 768 | A/Bの保持とCの獲得 |
| A再訪 | 元の64キー×1周 | 832 | 再学習による回復 |
| 正解変更 | Aの16キーの正解を変更し、16キー×4周 | 896 | 変更への適応と不変48キーへの影響 |

清浄条件 `clean` と、Aの最初の一周だけ8回答を誤らせる `noisy_first` を比較した。各クラス2回答を別ラベルへ変える。それ以降は、その時点の正解に沿う教師を与える。ノイズは8/896提示であり、全期間の12.5%ではない。

本試験は3データseed×2位相seed×D64/128/512×SS4方式×2シナリオ＝144学習過程。exactは3データ×2シナリオの6過程で、合計150過程。各過程896教師、合計134,400教師提示を一回の全試験で実施した。これを同じ凍結内容から二回実行した。

各過程で初期状態、各周の終了、正解変更直後・新教師前を含む19時点を固定照会した。A/B/Cと未登録の計320照会について生相関を保存した。全試験の生相関配列は2,850個。学習前のB/Cを正解付き既登録照会として扱わず、未登録の受理を別に数えた。未登録128キーを負例として教えることもしていない。

忘却の基準集合は、A四周終了時に正しく受理したキーとした。その集合のうち後から正受理できなくなった数を数える。誤答と保留は内訳を分ける。初めから正受理できなかったキーや空の基準集合を「忘れなかった」と評価しない。正解変更後は、変更された16キーを安定記憶の忘却の分母から除く。

独立開発データで10過程を実行した後、本試験前に実装・試験・データ・プロトコルを凍結した。開発後に試験を追加して最終50単体テストとしたが、学習方式を本試験結果に合わせて調整していない。これは第三者による事前登録ではない。結果は有限seedの記述的比較であり、反復照会を独立標本に見立てた有意差や普遍的な保証は主張しない。

## 4. 結果

以下、特記しない表はclean・D128・3データ×2位相＝6試行の合計。各群64×6＝384照会、未登録は128×6＝768照会。「正／誤／保」は受理正解／受理誤答／保留。保留を誤答へ混ぜず、同時に正解扱いもしない。

### 4.1 数をこなすことで同じ誤りは減ったか

通常の逐次誤差訂正deltaの、各教師回答を受け取る前の値である。教師を見た直後の答えを学習前の正解率として数えていない。

| Aの周回 | 暫定正解 | 暫定誤り | 暫定未定 | 受理正解 | 受理誤り | 保留 |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 79 | 290 | 15 | 0 | 0 | 384 |
| 2 | 368 | 16 | 0 | 131 | 0 | 253 |
| 3 | 384 | 0 | 0 | 344 | 0 | 40 |
| 4 | 384 | 0 | 0 | 381 | 0 | 3 |

一周目に暫定回答を誤った290例のうち、次の提示では277例が正解し、13例が再び誤った。二周目の誤りは、新たに誤った3例を含む計16例。その16例は三周目の再提示で全件正解した。未定を誤りの再発とは数えず、正解ラベルが変わった後は別の `(キー, 現在の正解)` として追跡した。

四周目の最後まで更新した後の固定照会では、Aは384/384正受理となった。上表の四周目381件は更新前、固定照会384件は更新後であり、同じ時点ではない。

暫定誤りの各周の推移は、delta5で290→5→0→0、replay32で288→7→0→0、単純加算でも284→39→21→7だった。単純加算にも学習効果はある。ただし提示のたびに増幅するため固定受理閾値で複数クラスがヒットしやすくなり、暫定回答の改善と受理回答の改善が一致しなかった。

### 4.2 新しいことを学ぶと古い記憶が崩れるか

| 方法 | A四周後のA 正／誤／保 | B四周後のA | C四周後のA | Aを一周再訪後 |
|---|---:|---:|---:|---:|
| delta | 384 / 0 / 0 | 269 / 6 / 109 | 181 / 25 / 178 | 353 / 0 / 31 |
| delta5 | 384 / 0 / 0 | 267 / 14 / 103 | 160 / 38 / 186 | 380 / 0 / 4 |
| replay32 | 384 / 0 / 0 | 299 / 7 / 78 | 231 / 24 / 129 | 348 / 0 / 36 |
| accumulate | 126 / 1 / 257 | 88 / 2 / 294 | 84 / 5 / 295 | 79 / 5 / 300 |

最初の三方式は基準集合が384件なので、C学習後の正受理脱落はdelta203件、delta5 224件、replay32 153件。再提示はdeltaより50件多く、現在の教師を五回更新するdelta5より71件多く保持した。しかし再訪後の正受理はdelta5の方が多い。保持と素早い再獲得を一つの優劣へまとめない。

単純加算はA学習終了時点の基準が126件しかない。この方式の不受理増加全体を、新規学習による忘却と断定できない。ゲイン増加と固定閾値・複数ヒットの影響を含む診断対照であり、適切に正規化したすべての加算方式への反証ではない。

C学習終了時にはdelta・delta5・replay32のCはそれぞれ384件とも正受理した。新しい群を獲得できないという結果ではなく、新しい群の獲得と古い群の保持が両立しきらない結果である。

### 4.3 保持改善の代償と符号長

| D | 方法 | C学習後のA 正／誤／保（384件） | 未登録誤受理（768件） |
|---:|---|---:|---:|
| 64 | delta | 88 / 58 / 238 | 250 |
| 64 | delta5 | 89 / 72 / 223 | 284 |
| 64 | replay32 | 130 / 63 / 191 | 297 |
| 128 | delta | 181 / 25 / 178 | 183 |
| 128 | delta5 | 160 / 38 / 186 | 235 |
| 128 | replay32 | 231 / 24 / 129 | 224 |
| 512 | delta | 372 / 0 / 12 | 19 |
| 512 | delta5 | 375 / 0 / 9 | 33 |
| 512 | replay32 | 378 / 0 / 6 | 28 |

D128の再提示は正受理保持率を47.1%から60.2%に上げた一方、未登録誤受理率も23.8%から29.2%へ増やした。D64では既登録Aの受理誤答まで58件から63件に増えた。再提示がすべての誤りを減らすとはいえない。

D512では忘却と未登録誤受理が小さくなるが、D128に比べHと符号キャッシュの配列量は四倍である。D512でも未登録誤受理はゼロではない。

exactは位相seedを重複実行しないため3試行。clean・C学習後のA/B/Cは各192/192正受理、未登録は0/384誤受理だった。同じキーの記憶という本課題では、SS方式の精度上の優位性を示していない。SSを使う理由を今後主張するなら、部分観測・重畳信号・構成的一般化や資源制約を明示した別試験が必要になる。

### 4.4 最初に誤った教師を受けても訂正できるか

noisy_first・D128。6試行で最初の一周の教師48件が誤っている。以下は各周終了後のA固定照会、各384件の正／誤／保。

| 方法 | 一周後 | 二周後 | 三周後 | 四周後 |
|---|---:|---:|---:|---:|
| delta | 119 / 15 / 250 | 342 / 0 / 42 | 384 / 0 / 0 | 384 / 0 / 0 |
| delta5 | 320 / 48 / 16 | 384 / 0 / 0 | 384 / 0 / 0 | 384 / 0 / 0 |
| replay32 | 272 / 42 / 70 | 357 / 5 / 22 | 384 / 0 / 0 | 384 / 0 / 0 |

誤教師を受け入れた後でも、その後の正しい回答によって訂正できた。ただし強く更新するdelta5は最初の誤教師も素早く記憶した。replay32も、正しい教師を再度受け取るまでは誤教師を保持・再提示し得る。これは誤教師を自力で見破った実証ではない。継続的・敵対的な誤教師への耐性、教師の信頼度学習、教師同士が矛盾する場合は未検証である。

### 4.5 正解自体が変わった場合

Aを再訪した後、16キーの正解を別ラベルへ変更した。D128の変更群は16×6＝96照会。新しい正解を教える前の暫定回答は三方式とも96件すべて新しい正解に対して誤りだった。真相の変更を外部情報なしに検知できたことにはしていない。

| 方法 | 新教師前 正／誤／保 | 変更群を一周学習後 | 二周後 | 四周後 |
|---|---:|---:|---:|---:|
| delta | 0 / 82 / 14 | 47 / 7 / 42 | 96 / 0 / 0 | 96 / 0 / 0 |
| delta5 | 0 / 96 / 0 | 96 / 0 / 0 | 96 / 0 / 0 | 96 / 0 / 0 |
| replay32 | 0 / 83 / 13 | 41 / 13 / 42 | 96 / 0 / 0 | 96 / 0 / 0 |

一方、変わらなかった48キー×6＝288照会への影響は次のとおり。

| 方法 | 変更学習前の不変群 正／誤／保 | 変更群四周学習後の不変群 |
|---|---:|---:|
| delta | 271 / 0 / 17 | 241 / 0 / 47 |
| delta5 | 284 / 0 / 4 | 279 / 0 / 9 |
| replay32 | 265 / 0 / 23 | 244 / 5 / 39 |

変更群への適応は成立したが、別の安定記憶への副作用は残った。この条件では再提示が常に有利ではない。古い教師の再利用や記憶干渉がそれぞれ何件の誤りを生んだかを切り分けた実験ではなく、原因の寄与率は主張しない。

## 5. 計算量・保存量

各過程の外部教師は全方式896回。内部更新はaccumulate/delta/exactで896回、delta5で4,480回、replay32で4,476回。replay32は最初の空バッファ時に一回だけ更新し、その後895回×4＝3,580回の過去教師再提示を行った。

delta5は「同じ現在教師を強く学ぶだけでも改善するか」を確認するための、数値更新回数に近い対照である。バッファ管理や相関計算を含めた総FLOPs・実時間・全RAMが等しい対照ではない。

| 配列／保存物 | D128 | D512 |
|---|---:|---:|
| SSのH：complex128、4×D | 8,192 bytes | 32,768 bytes |
| 32個の符号を生成済みのキャッシュ | 65,536 bytes | 262,144 bytes |
| replay32の教師バッファJSON | 2,625 bytes | 2,625 bytes |

clean・D128・最終時点のreplay32学習状態JSONは2,976 bytes、deltaは348 bytes。バッファJSONは学習状態に含まれるため、両者をそのまま足すと二重計上になる。バッファは32観測だが、最終時点の異なるキー数は30〜32、中央値31だった。JSON長・配列量はPythonオブジェクトや実行環境を含むピークRSSではない。

独立ベンチマークデータの最初の256教師を、各方式三回、同一プロセスで新規学習器から実行した。D128の一教師当たり中央値はaccumulate 0.514 ms、delta 0.560 ms、delta5 0.734 ms、replay32 1.369 ms、exact 0.655 ms。要求生成・指紋・状態コピー・バッファ管理を含む実装全体の時間で、純粋なSS演算速度や汎用ハードウェア優位性ではない。測定値は環境依存である。

環境：Windows 11、Python 3.12.14、NumPy 2.3.5、OPENBLAS_NUM_THREADS=1。Linuxは未実行。

逐次再学習の検証ハーネスは教師系列を入力ファイルとして持つが、学習器APIに渡すのはその時点の一回答だけである。「将来教師が検証環境のファイルに存在しない」という主張ではない。一方、予測専用の環境からは教師系列自体を除去している。

配布時の検証器は150過程すべてをもう一度学習し直すものではない。全過程の保存結果を再計算し、保存対象の三方式を逐次再実行する。ZIPの実展開・CRC・ファイルmanifest検証の最終結果は、ZIPと同じ場所の `PLM-L1-SS-online-v0.1-VERIFICATION.json` と `.md` に記録する。これらの外側記録を、内側の検証結果と混同しない。

## 7. 配布物と再実行

- `README.md`：導入・CLI・境界。
- `ss_online/`：SS予測・逐次教師更新・保存復帰の全コード。
- `evaluation/`・`data/`・`evaluate.py`：固定プロトコル、開発／本試験データ、評価コード。
- `tests/`：50単体テスト。
- `results/EVALUATION.json`：全150過程の教師提示前後の回答、教師と真値、集計、保存状態情報。
- `results/SCORES.npz`：2,850個の固定プローブ生相関配列。
- `results/`内の9学習状態：delta/delta5/replay32のA後・C後・正解変更後。
- `examples/`：既存delta-Aから一件教える人工教師例。

- `verify_release.py`：配布物の検証器。
- `RELEASE_MANIFEST.json`：manifest自身を除く配布ファイルのハッシュ一覧。

## 8. 次に行うとよいこと

次の優先課題は「訂正後の記憶保持と、未登録照会の誤受理を同時に管理する」検証と考える。再提示が正解保持を改善しても受理の信頼性まで改善するとは限らなかったためである。

具体的には、再提示の容量・選択方針を振り、同じ外部教師・符号長・追加更新予算の下で、既登録誤答・保留・未登録受理・正解変更への適応・保存量を並べて評価する。閾値を調整するなら開発データだけで校正し、別の最終データに固定する。さらに訂正履歴や教師の矛盾をどう扱うかを検証し、保留して追加教師を求めるv0.13の機構への接続を検討する。

長期目標の「SS型の表現・演算・記憶・学習で動く言語処理系」に対しては、今回は記憶・学習の小さな構成要素を実証した段階である。全SS制御、SS化した再提示バッファ、自然文の読み書き、二事象の依存候補、Phase/部分相関P1、SS型復調S1との統合は、この実験では進めていない。これらを実現済みとして扱わず、境界を保ったまま次の接続試験へ進む。
