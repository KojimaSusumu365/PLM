# PLM-L1 v0.3：意味・文章対から学ぶSS型生成器

限定された範囲で、読解と生成の両方を、手作業の状態列・操作列を逐一与えずに学ぶ実証です。
読解はv0.2の文・意味対学習済みモデルを固定し、生成は今回の新しい文・意味対学習器に置き換えます。旧v0.1生成器を新パイプラインで使用しません。

評価結果は `results/EVALUATION_REPORT.md`、到達点と限界は `results/RELEASE_DECISION.md` に記録します。本READMEは固定評価前に凍結するため、成功率は記入しません。

## 何を教え、何を学ぶか

各学習例は `text` と `meaning` のみ。意味は主体・対象・述語・肯否・断定形/仮定形の5スロットです。`order`、`goal`、`actions`、`states`、役割位置や操作列などを例に付け加えると拒否します。

内容語の意味IDと語種、助詞等の表面記号、意味スロットの定義は初期知識として与えます。
学習器が文中の内容語と正解意味を照合し、「主体に対応する語」「対象に対応する語」「そのまま出す表面記号」を自動で対応付けます。最初に現れた内容語の役割から出力目標も導出します。
その列の各prefixと次の抽象出力記号、文末の終了記号の対応を位相連想記憶へ学習します。

したがって、内部で次記号の教師信号を導出する教師付き学習です。「すべての教師や設計上の前提がなくなった」「文法を無から発見した」という主張ではありません。
一意に語役割を照合できない学習例や、多義的な語彙実現は拒否します。語義と表面の対応を未知の文章から発見する実装ではありません。

## 生成時

生成器の入力は数値意味パケットと先頭に出したい役割（`subject` または `object`）です。
意味信号の回復、生成途中の抽象語列prefix、肯否・仮定、先頭役割から、次の出力記号または終了を相関で選びます。選んだ内容役割の語は別の語彙連想記憶から出力します。
生成時は自分自身の出力prefixを使い、正解prefix・原文・正解文章を参照しません。未知の対応・弱い相関・競合・役割の欠落/重複・停止失敗は保留し、不完全な文章を最終出力しません。
旧生成器、外部LLM、全文検索、手書きの日本語文法へフォールバックする経路はありません。

モデルには全文やprefix→記号の対応表を保存せず、数値重み・候補記号・公開語種・統計とハッシュを保存します。同一数値照会の実行時キャッシュは使用します。
有限の学習済みprefix対応を用いるので、未知構文への一般化を実証したわけではありません。

## 実行方法

Python 3.12.14 / NumPy 2.3.5で検証します。Python本体は同梱しません。ZIPを展開したPLM-L1-v0.3フォルダで実行してください。
出力名は未使用のものを指定します。既存のモデルとパケットは上書きしません。

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$env:PYTHONIOENCODING='utf-8'
python -B -m plm_l1_v03 train --pairs data/train.json --lexicon data/lexicon.json --out work/my-writer
python -B -m plm_l1_v03 read --model work/my-writer --text '太郎が花子を助けた。' --out work/meaning.json
python -B -m plm_l1_v03 generate --model work/my-writer --packet work/meaning.json --goal object
```

出力例：`花子を太郎が助けた。`。`--goal subject` は主体を先に出す目標です。
付属生成モデルは `--model results/writer` で利用できます。`read` コマンドは固定v0.2読解器で読み、意味信号を新生成器の符号へ橋渡しします。

生成器だけを試す場合、5スロットの意味JSONを用意して、次のように意味信号へ符号化します。この経路に読解器は不要です。

```powershell
python -B -m plm_l1_v03 encode --model results/writer --meaning examples/MEANING.json --out work/direct-meaning.json
python -B -m plm_l1_v03 generate --model results/writer --packet work/direct-meaning.json --goal object
```

保留時は終了コード2、形式誤りや既存出力への上書き要求は終了コード1。生成成功以外で完成文を捏造しません。

## 評価と再検証

```powershell
python -B -m unittest discover -s tests -v
python -B evaluate.py --out work/evaluation-repeat
python -B verify_release.py --out work/verification
```

学習576文、開発192文、評価192文はv0.2/v0.1から変更せず再利用します。学習とは主体・対象・述語の組合せを分離していますが、プロジェクトにとって初見のコーパスではありません。
生成単体は評価にある96種類の意味×2先頭役割、読解接続は192入力文×2先頭役割を別々に採点。新生成器の符号seedを8通り変え、読解器は固定します。
主客・否定・仮定の保持に加えて、先頭役割の指定も満たすことを成功条件とします。採点は新読解器ではない別実装の限定文法を使います。独立した人手の自然文評価ではありません。

文対学習・prefix・状態条件を除去する比較、意味教師の主客/状態を反転する比較、助詞等の無意味記号への置換、否定例の除外、通常表引き・旧生成器との比較を実施します。
意味教師の人工反転は通常の日本語意味の正答率ではなく、学習情報に出力が追従するかの検査です。表引き方式が成功してもその結果を報告します。
別途128/512/2048次元で失敗と保留を観測しますが、容量適応型の閾値学習は今回実装しません。

`verify_release.py` は新テスト、v0.2/v0.1の回帰テスト、保存した数値結果の整合性、教師・旧モデルなしの再学習、読解器なしの生成専用環境を検証します。全数値評価の再実行は `evaluate.py` が担当します。
ソース・仕様・データ・同梱旧版は `SOURCE_MANIFEST.json` で固定し、変わると固定評価を拒否します。

## 対象と非対象

6名・4動詞・2語順・肯否×断定形/仮定形・1出来事を対象にします。仮定形は後件を持たない「もし…たら。」という実験用の条件節です。
既知語彙の組合せ学習であり、未知語の語義獲得・未知文法・長文・照応・複数出来事・自由作文は未実装です。
SS型の言語演算はPhase/VSA領域です。文字分割・語種の参照・役割のコピー操作・数値計算の反復制御・入出力・型検査は通常のPython補助処理であり、全演算を通信SSの明示チップ列で実装したわけではありません。
R1推論・Concept更新・S1同期受信器への接続は行わず、出力の `eligible_for_inference` は常に `false` です。
`vendor/PLM-L1-v0.2/` は元のv0.2配布フォルダをそのまま保存しています。旧成果物は変更しません。
