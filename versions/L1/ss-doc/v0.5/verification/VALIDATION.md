# 検証範囲と証拠の読み方

## 実装・データの固定

[FREEZE.json](../evaluation/FREEZE.json) は、開発試験の後、本評価に入る前に固定したソース・モデル・データ・評価条件のハッシュです。本評価後の閾値調整や主評価場面の差替えは行いません。例、説明資料、事後集計用の監査コードはこの固定対象外であり、最終の `RELEASE_MANIFEST.json` で別途全ファイルを固定します。

[DATA_AUDIT.json](DATA_AUDIT.json) は566エピソードの全改訂段階と古い既知値入力の場面重複監査です。1,279件の過去場面指紋を除外しています。評価データを再構築して固定JSONと完全一致することも検証します。v0.4の過去の重複監査結果を改変していません。

最初の検証実行では、開発→300→301の作成時の行順と、JSON保存後の300→301→開発という順序の差で監査票比較が失敗しました。[元の監査票](DATA_AUDIT_PREFILE_ORDER.json) と [原因・修復記録](AUDIT_ORDER_REPAIR.json) を保持しています。非固定対象の監査票の行順だけを正規化し、各行の値・主評価結果・固定ソース・モデル・プロトコル・データは変更せず再検証しました。

## 試験と全評価

- [TESTS.json](TESTS.json)：固定前の86単体試験。従来の62件と新規24件。
- [FINAL_TESTS.json](FINAL_TESTS.json)：固定後の86試験再実行。
- [DEVELOPMENT.json](DEVELOPMENT.json)：開発用の小規模確認。主評価成績には含めません。
- [INDEX.json](../results/INDEX.json)：全72条件、主評価864件、冷間照会864件、それぞれ1,728文章要求の索引。
- [SUMMARY.json](SUMMARY.json)：3方針・2記憶構成・3教師上限の全18集計。生成成功だけを抜き出した評価ではなく、誤りと保留を含みます。
- [FAILURES.json](FAILURES.json)：比較対象も含めた全誤生成場面。誤りは非表示にしません。
- [LOG_AUDIT.json](LOG_AUDIT.json)：全件の教師予算、対象・改訂対応、非対象不変性、既知値をSSだけで無断変更していないこと、冷間照会に回答履歴がないことの監査。
- [V04_FAILURE_REGRESSION.json](../results/V04_FAILURE_REGRESSION.json)：旧版で誤生成した3件を固定した別回帰試験。新しい主評価データには混ぜません。
- [LANGUAGE_REGRESSION.json](../results/LANGUAGE_REGRESSION.json)：旧言語生成144例。

主評価の1件は1つの文書照会です。生成できれば提示順保持と逆順・焦点変更の2出力を要求します。保留も要求分母に残します。独立な焦点場面は24件で、符号seedも2つです。864件を独立標本とみなす有意差検定は実施していません。

## 再現性と推論分離

[REPEATABILITY.json](REPEATABILITY.json) は、別ディレクトリで最初から2回目の全評価を走らせたファイル単位の一致比較です。実行時間だけを除外します。

[VERIFY.json](VERIFY.json) は次の範囲の再実行です。

- 基底SS記憶8件と最終SS記憶72件を読み込み、フィンガープリントを照合。
- 各条件の最初の2エピソード、計144件の教師予算を伴う逐次確認を基底記憶から再実行。
- 各条件の最初の2冷間照会、計144件を保存済み最終記憶から再実行。
- 同梱したすべての参照数値配列を再計算し、要素単位で完全一致を確認。
- データ生成を再実行し、固定されたデータと照合。

これは3回目の全864件評価ではありません。全条件を最初から学習し直すのは、元実行と2回目実行の2回です。

[ISOLATED.json](ISOLATED.json) は別の最小ランタイムでのCLI実行です。教師・評価データ、読解器、学習モジュールを置かず、読み込まれたプロジェクトモジュールがすべてそのディレクトリ内にあることを検査します。2事象・3事象の各最初の場面を事前に固定した選択規則で使い、両方欠測の数値信号とSS記憶から新しいセッションを作成します。成功した場面への選び直しはしません。ここで使う局所数値補完モジュールは含みますが、長期SS係数を更新する学習モジュールは含みません。

## 操作・保持・元成果物

[CLI_WORKFLOW.json](CLI_WORKFLOW.json) は、実際の7別プロセスで start → plan → 保留generate → confirm → generate → 冷間start → 冷間generate を試した記録です。読みやすい小例であり、主評価と別です。質問だけを提示する状態では文章を出力しません。

[INFERENCE_AUDIT.json](INFERENCE_AUDIT.json) は生成前後の数値信号、モデルとSS記憶の不変性、および永続記憶3ファイルの保存・再読込一致を確認します。時間測定は小例1件に対してウォームアップ1回後7回を測ったもので、方式間の性能優位性を示すベンチマークではありません。

[PRESERVATION.json](PRESERVATION.json) は旧版の451ファイルとZIP、および本版へコピーした68ファイルの不変性確認です。旧言語重みを再学習・変更していません。[ENVIRONMENT.json](ENVIRONMENT.json) にPython、NumPy、OS、数値演算スレッド設定を記録しています。

## ZIP検証の境界

最終ZIP作成時に全ファイルをハッシュ化し、CRC検査後に別の明示的作業フォルダへ実際に展開します。全展開ファイルの一致を確認し、展開側で86単体試験と上記 `verify_release.py` を再実行します。その事後記録はZIPを書き換えず、ZIPに隣接する `PLM-L1-SS-doc-v0.5-POSTZIP.json` と検証サマリーに保存します。ZIP内から自分自身の最終ZIPハッシュを証明する循環構造にはしません。

チェックサムの一致は配布物の同一性の確認であり、信頼できる署名者の認証ではありません。ここでの試験成功は、任意の自然文・誤教師・長期運用・悪意あるファイル編集に対する安全性を保証しません。
