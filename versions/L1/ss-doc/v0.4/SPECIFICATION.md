# v0.4：複数訂正と連続改訂の仕様

## v0.3からの変更

v0.3の対象別キーは、対象以外の全観測を含む。一つの項目を訂正すると他の項目のキーも変わり、特に二項目を同時に未観測として再照会すると一致しなくなる。

v0.4は外部で指定した一～二項目を変更可能集合として固定し、それ以外の意味を文脈の基準にする。変更可能な項目同士の値・候補・状態を基準に混ぜない。ただし変更可能集合、出来事ID、事象数、提示順、その他の意味が変われば別文脈である。似た意味の自動同一視はしない。

```text
root = hash(episode ID, declared mutable targets, count, presentation, fixed cells)
versioned SS key = hash(root, target, target revision)
stable SS key    = hash(root, target)
```

固定項目は全てknownが必要。変更可能集合はモデルが推定するのではなく呼出し側が宣言する。文書中のevent IDも外部スキーマに沿った局所IDであり、同一人物の照応や事象対応を新しく学習していない。出力の順序反転は、照合と補完の後に行う。

## SSが保持するもの

外部確認の内容（役割と値）は既存v0.3の4チャネルSS記憶へ学習する。役割／値ラベルは主体6・対象6・行為4・肯否2・仮定2・時間3の23候補。学習されるのは係数で、符号は固定。

結合型では文脈符号とラベル符号の積を重畳する。

```text
Z[k,y] = context_code[k,SS_key] * label_code[k,y]
s[k,y] = Re(vdot(Z[k,y], H[k])) / D
e[y] = onehot(confirmed_value)[y] - mean_k(s[k,y])
H[k] += sum_y(e[y] * Z[k,y])
```

ラベル別型はラベルごとの係数へ文脈符号を加算し、同じ4チャネル平均誤差で更新する。既存の `ss_retention/learning.py` は変更していない。推論中に出力を教師として学習しない。

改訂別の方式では古い改訂の重畳成分も残る。最新改訂のキーだけを照合するが、古い成分の干渉を数学的に消したわけではない。過去の文書全体を保存する機能、過去版の完全再現、履歴消去、圧縮、有限件数への自動整理は未実装。

## 通常メタデータとSSの境界

`revision.json` には方式・符号seed・SS指紋に加え、rootハッシュごとの変更可能target→現在の整数改訂番号と保護フラグを保存する。教師値、完成文、訂正済みパケット、原文、正解意味配列は保存しない。

内側のSS記憶には固定候補語彙、係数、ラベルなし登録キーハッシュ、更新回数がある。固定語彙一覧は正解辞書ではない。数値係数をゼロ化し、通常台帳と改訂番号だけを残しても値を復元できないことを試験する。

改訂番号の順序検査、対象集合の管理、ハッシュ、登録ゲート、保護指定、出力制御は通常のPython処理。SS型の内容保持と、設計した制御機構の接続実証である。全ての判断をSSが学習したという主張ではない。

## 確認プロトコル

初期改訂番号は対象ごとに0。確認メッセージは次のフィールドを持つ。

| フィールド | 用途 |
|---|---|
| schema | `plm-ss-revision-confirmation-04` |
| scope_sha256 | 外部IDと固定文脈・変更可能集合への結び付け |
| packet_sha256 | 今回確認対象とする数値パケットのハッシュ |
| target | 確認する事象／役割、または時間関係 |
| base_revision | 呼出し側が確認した対象の現在の改訂番号 |
| revision | base_revision + 1 |
| value | 外部で確認した既知語彙の値 |
| operation | supply、revise、resolve |

公開Python APIの `ss_revision.learning.request(model, memory, scope, packet, target, value, operation)` で作成できる。requestはメッセージ作成であり、その値の真偽を検査しない。

teachは文脈・パケット・現在改訂番号との一致を検証し、v0.2の局所数値更新と事後条件を通したknownの確認だけを学習する。SS係数更新が成功した後に改訂番号を進める。古いbase_revision、重複、未来への番号の飛び越しは拒否する。同一番号を前提とする二つの要求では先に有効な処理を完了したものだけが通り、後の要求は再確認が必要となる。並列書込プロセスの排他ロックまでは実装していない。

通常のsupplyが既知値と食い違った場合、矛盾を勝手に教師とせず拒否する。既知値の変更はrevise、明示的な矛盾の解消はresolveを要求する。別の変更可能項目が未観測でも、固定文脈がknownなら確認処理を行える。

古い確認を現在パケットへ結び直しても、古い改訂番号のままなら拒否する。しかし、誤った値へ新しい有効な改訂番号を付けて明示確認すれば学習してしまう。番号は真実性・本人性・実世界の日時の証明ではなく、最新の到着情報を自動的に真とするルールでもない。内部のprepare済みレコード用learn APIは信頼済み呼出し側向けであり、認証境界ではない。

## 推論の受理と局所補完

変更可能項目ごとに通常メタデータの現在改訂番号を取り、そのSSキーを照合する。登録ゲートを通り、平均相関0.5以上の候補が一つ、次点（負なら0）との差0.15以上、4本のうち3本以上が同じ最大候補を支持した場合に受理する。相関値は確率ではない。

保護記憶が登録されていれば保護側の支持を使う。ただし共有側も強く別の値を支持すれば保留。保護側が弱い場合に共有側だけへ自動フォールバックしない。

- ambiguous：支持値が現在の候補に含まれるときだけ補完。
- unobserved／unreadable：現在改訂への支持が十分なら補完。
- conflict：自動解決せず保留。
- known：現在入力の値を上書きしない。十分なSS支持と違えば保留。共有／保護の不一致も保留。弱い記憶で確定値を取り出せない場合、現在の明示値を使うことはある。

全対象への判断を揃えてから、v0.2の局所数値差分で補完する。一つでも保留なら部分的に書き換えたパケットを返さない。元の入力は変更せず、補完対象以外の意味も変更しない。生成器へ渡すのは補完後の数値パケットだけで、教師原文は渡さない。

## 比較方式と費用

| 方式 | 照合キー | SS構成 | 学習係数bytes |
|---|---|---|---:|
| none | 改訂別 | SSなし | 0 |
| legacy_context | v0.3の対象以外全項目 | 共有pair736＋保護pair736 | 94208 |
| stable_overwrite | 固定文脈＋target | 共有pair736＋保護pair736 | 94208 |
| versioned_shared | 固定文脈＋target＋改訂 | 共有pair1472 | 94208 |
| versioned_pair | 固定文脈＋target＋改訂 | 共有pair736＋保護pair736 | 94208 |
| versioned_bank | 固定文脈＋target＋改訂 | 共有pair736＋保護bank23×32 | 94208 |

全SS方式は4チャネル、複素128bit係数。legacy_contextにも共通の通常改訂管理を付け、同じ教師列を渡す。従って比較するのは旧照合キーを保持した対照であり、v0.3全体を変更なしで再実行した成績ではない。

保護記憶は訂正対象の文脈だけを学習し、背景教師は共有へ学習する。通常台帳や改訂メタデータは件数とともに増える。改訂別方式は旧改訂のキーも残るため、stable_overwriteと登録件数・負荷・時間・全RAMが同じではない。固定ラベル基底も構成により異なる。等容量なのは学習係数だけである。

## 限界

二つの項目の独立した確認を同じ文脈に保持することと、二項目間の未確定な論理的依存関係を学習することは別。本版は前者の実証。教師が矛盾した意味を別々に正式確認した場合、その世界知識的整合性まで保証しない。外部IDの誤指定、固定文脈の自動更新、対象集合の自動拡張、時制・照応・未知語・自由長文・P1/S1・SS-active全体統合も対象外。`eligible_for_inference=false`。
