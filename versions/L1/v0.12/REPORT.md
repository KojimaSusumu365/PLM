# PLM-L1 v0.12 実施報告

2026-09-08。Windows / Python 3.12.14 / NumPy 2.3.5。

## 1. 結論

「残った情報だけで確定してよいか」を、**学習済みの予測記憶と裏付け記憶から調べるゲート**を実装した。

v0.11の標準部分入力で出ていた114件の誤確定を、正答1,262件を一件も失わず保留へ変えられた。必要な特徴が欠けたら一律に止める対照より、148件多く正答を維持した。二特徴欠落の新しい分割でも、有効な回答を残しながら誤確定を止めた。

ただし、特徴選択が未知の依存関係を見落とす二世界の試験では誤確定が残った。今回得たのは「学習した依存・語彙の範囲での十分性確認」であり、真の意味が常に一意だという保証ではない。

主要な改善は、SS裏付け記憶を追加しない補完一致判定でも得られ、記号的対照でも再現した。SS固有の優位性や全SS学習とはしない。v0.10の言語系へはまだ接続せず、独立した記憶部品としての実装・比較実証を完了した。

## 2. 何を実装したか

v0.11の学習器・予測器は無改変で再利用する。元の確定値を固定し、欠けた選択特徴を訓練語彙内で全て補ったときに、全保持候補の予測が同じ値を返すか検査する。さらに各補完が、訓練で見た選択キー／ラベルのSS裏付け記憶に支えられるかを調べる。

裏付け記憶は、重複を除いた完全な選択キーの位相積をクラスごとに加算する。SS実行時にキー対応表は置かず、数値の相関ヒットを使う。対照の記号的方式だけは、同じ訓練キーの0/1表を使う。評価用完備化表、真の依存関係、部分入力の正解教師は学習・判定へ渡さない。

新方式は拒否専用で、元の保留を確定へ変えず、値を別ラベルへ変更しない。候補上限・不支持による停止は解除しない。補完数上限256を超えた場合も、途中まで見て成功にせず保留する。

具体的には、ANDで片方が偽なら他方不明でも偽を維持し、片方が真で他方不明なら結果が分かれるので保留できる。ただし、その依存が学習できている場合である。

## 3. 試験条件

主要評価は295モデル。旧データの21課題／段階×2表現×5数値条件で210、新しい分割と二世界の14課題×5で70、特徴選択なしの3課題×5で15。5数値条件はSSのD512／2048×2符号と、記号的対照一回。記号的方式を次元・符号で重複実行しない。

同じモデルに四ポリシーを適用した。

| ポリシー | 判定 |
|---|---|
| baseline | v0.11のまま |
| observed_only | 全選択特徴が観測されているときだけ許可 |
| consensus_only | 学習予測の全補完一致だけを要求 |
| completion | 全補完一致＋学習済み裏付け記憶。新しい既定方式 |

旧データでは一特徴削除、新分割では一特徴と二特徴削除を別々に評価。全特徴なしも一特徴削除群へ含める。各群で部分文脈を重複除去する。可能ラベルが複数なら、隠れた元の正解へ偶然合っても確定を誤りとする。

標準は24訓練・16選択検証・8calibration・16最終評価の完全文脈を分離する。少標本は訓練8。相関曖昧性は追加教師前後も分ける。未知相互作用の二世界は21／14／7／22で、二世界の訓練・選択・calibrationは完全に同じ。いずれも人工的な有限構造化課題であり、新しい自然文の読解実績ではない。

## 4. 旧版と同じ入力での改善

標準5依存課題×2置換、D2048・二符号の部分文脈1,750要求。一意に決まる1,262要求、複数解の488要求。表は「正答／誤確定／保留」。

| 方式 | 正答 | 誤確定 | 保留 |
|---|---:|---:|---:|
| v0.11 hybrid3 | 1,262 | 114 | 374 |
| 選択特徴が全て観測済みの場合だけ許可 | 1,114 | 0 | 636 |
| hybrid3＋全補完一致のみ | 1,262 | 0 | 488 |
| **hybrid3＋全補完一致と裏付け記憶** | **1,262** | **0** | **488** |
| v0.11 product | 1,114 | 0 | 636 |

新方式は、元の正答を全て保持し、114件の誤確定だけを拒否した。一律の完全観測要求やproductと比較すると、一意な入力148件を追加で正答した。回答数をただ減らして得た結果ではない。ただし同じ有限課題に対する結果であり、一般のリスク上限ではない。

標準の完全入力320要求は、hybrid3の全ポリシーで320正答を維持した。productへ同じゲートを付けても、その部分入力の1,114正答・636保留は変わらない。拒否専用なので、productが失った回答を取り戻す機構ではない。

D512でも、hybrid3の1,262正答・121誤確定・367保留を、1,262・0・488へ変えた。記号的hybrid3も631正答・57誤確定・187保留から631・0・244へ改善。記号的は一回、SSは二符号なので要求数が半分である。

構造化主客・肯否／仮定の354要求では226正答・68誤確定・60保留から226・0・128へ改善。少標本の868要求では538正答・54誤確定・276保留から538・0・330へ改善した。少標本の一意な628要求のうち90件は引き続き保留で、全てが読めたわけではない。

## 5. 新しい分割と二特徴欠落

同じ課題族の別分割、D2048・二符号、hybrid3の結果。

| 対象 | 要求数 | 旧判定：正答／誤り／保留 | 新判定：正答／誤り／保留 |
|---|---:|---:|---:|
| 標準・一特徴欠落 | 1,756 | 1,260 / 110 / 386 | 1,260 / 0 / 496 |
| 標準・二特徴欠落 | 3,508 | 1,762 / 396 / 1,350 | 1,762 / 0 / 1,746 |
| 構造化主客等・一特徴欠落 | 338 | 214 / 67 / 57 | 214 / 0 / 124 |
| 構造化主客等・二特徴欠落 | 658 | 246 / 216 / 196 | 246 / 0 / 412 |

これらでは一意に決まる要求を全て正答し、複数解の要求を全保留にできた。完全入力も標準320／320、構造化64／64を維持した。D512も標準一特徴で1,260正答・115誤確定から1,260・0、二特徴で1,762・410から1,762・0となった。

標準二特徴欠落のobserved_onlyは1,352正答・0誤り・2,156保留。新方式は正答を410件多く維持した。新分割の記号的対照でも、標準一特徴630正答・55誤確定から630・0、二特徴881・198から881・0と同じ傾向だった。

新しい分割は新しい自然言語・語彙・課題構造ではない。この結果を未知の言語規則への一般化へ拡張しない。

## 6. 追加裏付け記憶の効果と過剰保留

主要な選択済み課題では `consensus_only` と `completion` が同じ結果になった。したがって、改善の全てを追加したHの効果とは言えない。主な貢献は、部分相関の強さだけでなく**補い方に対する予測の不変性**を調べた点にある。

特徴選択なしの単項・XOR・ANDの三課題、D2048二符号では、全6特徴が選択キーになる。完全入力96要求は旧判定44正答・1誤答・51保留に対して、H付きは全96保留。部分入力530要求では次のようになった。

| 判定 | 正答 | 誤り | 保留 |
|---|---:|---:|---:|
| baseline | 178 | 18 | 334 |
| consensus_only | 168 | 1 | 361 |
| completion | 0 | 0 | 530 |

完全文脈は訓練と評価で分離しているため、全6特徴の一致を裏付け記憶へ要求すると、既知部品の新しい組合せまで止める。Hはこの対照で誤答を抑えたが、正答も全て失った。これは性能上の勝利ではなく、適切な特徴選択への依存と過剰保留の弱点である。

相関で区別できない候補の試験は、全追加ポリシーで旧版の保留を維持した。D2048二符号では追加教師前32要求を全保留、各課題へ別の8教師を追加後32要求を全正答。候補を打ち切って無理に確定させる変更はしていない。

## 7. 未知の依存関係は防げなかった

訓練・選択・calibrationが同じ二つの世界を用意した。一方は学習した単項規則で十分、もう一方は未観測の組合せにだけ追加の依存がある。学習器には二世界の違いを示す情報がない。

両世界で、全5数値条件の学習モデル指紋と全ポリシーの予測が同じになった。それでも真の正解は異なる。隠れた依存がある世界のD2048二符号では、新旧とも次の誤りが残った。

| 入力 | 正答 | 誤答・誤確定 | 保留 |
|---|---:|---:|---:|
| 完全入力44要求 | 28 | 16 | 0 |
| 一特徴欠落210要求 | 116 | 56 | 38 |
| 二特徴欠落362要求 | 166 | 76 | 120 |

裏付けがあることは、その**選択キー**を教師と一緒に見たことを意味するだけで、選択外の特徴が本当に無関係である証明ではない。今回のゲートを「誤確定ゼロ保証」「推論を開放してよい根拠」としない。

## 8. SS裏付け記憶の負荷診断

64キーから4・16・48キーを格納し、D128／512／2048×二符号と記号的対照、計21条件を測った。これは裏付けメモリ単体であり、前節の言語的な誤答率とは別である。

4・16キーでは全SS条件で既知キーを一意に正しく回復した。48キー・D128の二符号では、既知の一意正回復が38／48と46／48へ下がり、他ラベルのヒットも一条件で1件あった。D512／2048では各条件48／48。今回の未格納キーへのヒットは全条件0だが、未格納誤受理が原理的にない保証ではない。

記号的対照は全既知キーを正確に支持し、未格納キーへのヒット0。Hを実際にゼロ化した五つの対照は、新ゲートで確定0だった。これはHが経路に使われている検査で、Hを使うこと自体の有利さを示す検査ではない。

## 9. 費用

二クラス・D2048・一候補なら、基礎Wの65,536 bytesにHが65,536 bytes追加され、数値重みは合計131,072 bytesになる。符号帳・JSONメタデータ・Pythonオブジェクトは別。全RAMや同一総係数予算を揃えた改善ではない。

全数値評価終了後、単独プロセスで単項・AND・3項パリティの第一置換、D2048第一符号を各3回計測した。次表は各課題の3回中央値を求め、さらに三課題の中央値を取った照会時間。

| backend・入力 | baseline | 補完一致のみ | 補完一致＋裏付け |
|---|---:|---:|---:|
| SS・完全入力 | 1.214 ms | 1.339 ms | 1.370 ms |
| SS・一特徴欠落 | 1.225 ms | 1.422 ms | 1.455 ms |
| 記号的・完全入力 | 0.053 ms | 0.106 ms | 0.127 ms |
| 記号的・一特徴欠落 | 0.045 ms | 0.115 ms | 0.131 ms |

符号帳を暖めた構造化照会で、SS側は基礎の符号化・パケット検証も含む。各ポリシーは同じGuardedModelに対して実行し、baselineでもHはロード済みだが利用しない。純粋な相関カーネル同士や、本物の文章系・大語彙・最大256分岐の負荷での比較ではない。小規模条件ではSS方式が記号的方式より高速とは示せなかった。生計測と配列費用は `verification/BENCHMARK.json`、全条件の費用は `results/PERFORMANCE.json` とモデルのstorage欄に保存した。

## 10. 検証・保全

新規40＋無改変で再利用したv0.11の57、計97テストが通過した。主要295モデルに対する5,741検査項目の内訳は、分割整合1・前版照合1・対照9・会計3,820・拒否専用等の契約1,910。独立した能力を5,741種類証明したという意味ではない。

前版と同じ225モデルの基礎指紋と21,570照会のbaseline判断が、v0.11アーカイブ結果と一致した。これはv0.11の683条件全てを再実行したという意味ではない。

最終凍結の全数値実行を2回行い、結果JSONと四つの保存モデルの16ファイル、計17ファイルがbytes一致した。PERFORMANCE.jsonは一致対象外。

配布前の隔離再学習では四モデルの基礎W・裏付けHとも係数差0で、厳密指紋が一致した。891文脈×4ポリシー＝3,564の離散的判断が一致。両版の学習器とデータ・評価器を外した照会専用環境で、一意な部分入力の確定・曖昧な部分入力の保留・空入力の保留・不正項目の拒否も確認した。この隔離照会は構造化特徴を渡すもので、数値のみの意味不足判定ではない。

別途、元のv0.11配布物自身の57テスト・三モデルの隔離再学習・214入力比較・数値のみの復号を再実行して通過した。v0.10以前のテスト群と全数値評価は今回は再実行していない。旧成果物4,901ファイルのハッシュ不変を確認し、共有履歴だけを追記する。

## 11. 採用判断と次の課題

要求された機構は独立部品として実装でき、学習された依存の範囲では、一律保留より多くの有効な答えを残す改善を確認した。ただし、現状のままv0.10言語コアを置き換えたり、R1推論を開放したりはしない。

次の優先課題は、**選択済みの特徴だけで十分だと見なす根拠を監査すること**。未知の依存を含む候補をどこまで残せるか、区別に必要な追加教師をどのように選ぶかを、回答率と費用を含めて検証する。評価側の真の完備化表を実行時へ移すことで解決したことにはしない。

SS裏付け記憶の追加は標準条件で必須ではなかったため、常に使う構成の費用対効果も再検討対象とする。さらに数値信号だけの経路へ接続するには、観測された意味情報の扱いと新ゲートを別途設計する必要がある。P1/S1統合、量子化・疎化、スパイク/STDP、一般自然文、Linux実機は未実施。`eligible_for_inference=false`を維持する。
