# PLM-L1-SS-doc v0.2：未確定意味の保持と追加情報による局所訂正生成

## 結論

**二／三事象の短文書で、未確定項目をSS信号に保持し、外部確認後にその項目だけを訂正して文を生成する接続を実装・評価した。** 主評価1008件で候補・状態を保持し、確認前の完成文を出さず、正しい追加情報によって対象外の意味を変えずに訂正できた。訂正後2016生成要求で、人物・対象・行為・肯否・仮定・明示された時間関係を保持した。

ただし、これは小さな制御言語と手設計の状態遷移での実証である。**自然文の曖昧さの自動発見、確認手順の学習、訂正の長期学習は達成していない。** 候補内から基準と異なる教師を与えた18件は全てその値を文章化し、基準の意味と不一致になった。内訳は主体・肯否の変更12件と、未記述の時間関係の追加6件である。全18件を現実の偽の事実と判定したわけではなく、教師の真偽を判定する仕組みではない。

## 1. 実際に書けるようになった文章

次の二文書を、外部で指定された読み候補として与えた。自然文からモデル自身が二つの解釈を発見した例ではない。

> 太郎が花子を助けた。その後、花子が健太を褒めた。その後、健太が美咲を訪ねた。

> 太郎が花子を助けた。その後、由紀が健太を褒めた。その後、健太が美咲を訪ねた。

SSから復元した確認対象は、第二事象の主体 `event:1/subject`、候補は「花子／由紀」だった。この段階ではneeds_informationを返し、完成文は出力しない。

外部から「第二事象の主体は由紀」と構造化情報で確認した後：

> 太郎が花子を助けた。その後、由紀が健太を褒めた。その後、健太が美咲を訪ねた。

同じ訂正済みSS信号から、提示順を反転して生成：

> 健太が美咲を訪ねた。その前に、由紀が健太を褒めた。その前に、太郎が花子を助けた。

その後、改訂であると明示せずに「主体は花子」という追加情報を与えると、矛盾を保持して再び保留した。明示的なresolveで由紀を選んだ後に再生成できた。実行例は `examples/demo.py`、実際の出力と数値パケットは `examples/EXAMPLE.json` などに保存した。説明用の例を主評価の独立標本には数えない。

## 2. v0.1から変えたもの

v0.1の言語読解・生成コア27 Pythonファイルを変更せず継承し、保存された既存学習済みモデルを使用した。新しい言語教師対を与えて再学習したわけではない。

今回追加したのは、各意味項目に対するknown、ambiguous、unobserved、unreadable、conflictという観測状態と候補集合のSS保持、未確定項目の照会、外部確認による局所更新である。状態と候補数も位相符号に結合して重畳し、生成器に渡す通常メタデータで答えを添付しない。

一つの不確かな自然文を入力して候補を自動発見する機構ではない。二つの明示的な読み候補、または構造化した観測を入力する。欠落・読み取り不能の状態も外部で指定する。確認対象はSSから復元した未確定項目の列挙であり、学習済みの能動選択や情報利得による質問順位ではない。

現在も語彙・発生ID・役割・文書の骨組み・状態遷移・閾値は手設計である。SS言語記憶を使った生成を継承しているが、全処理をSSだけで実装したとは言わない。詳細は [SPECIFICATION.md](SPECIFICATION.md)。

## 3. 「記述なし」と「分からない」を区別する

時間関係がknown＋unspecifiedなら、「明示された前後関係がない」という観測を保持し、質問せず生成する。unobservedなら、その項目の観測が不足しているため確認を求める。unreadableは読み取り不能と指定された意味状態で、数値信号そのものの復元失敗とは別である。

信号から候補が物理的に欠落したときに、その箇所を自動的にunobservedと呼び替えて生成を続けることはしない。復元不整合ならabstainとする。非隣接の時間関係はv0.1と同じくknown＋unspecifiedで、時間の推移的推論を行わない。

## 4. 主評価の設計と結果

二／三事象各4種類、計8種類の出来事構成を用意した。完全な出来事の組合せは、旧学習対・旧v0.1主評価・今回の開発集合と重ならない。ただし単語・一事象部品・文法・意味スキーマは既知の限定範囲である。

二事象は五役割×2事象＋隣接時間1項目＝11対象、三事象は五役割×3事象＋隣接時間2項目＝17対象。それぞれ一項目だけをambiguous／unobserved／unreadableに変えた。4×11×3＋4×17×3＝336観測を、三つの文書符号で繰り返して1008件となる。

開発は別の4構成から168観測、一つの開発符号で試した。主評価前に主要コード・データ・モデル・条件を凍結し、結果を見て閾値や次元を選び直していない。主評価の文書信号と既存言語記憶は8192次元。

| 対象 | 訂正例 | 訂正前の完全復元 | 訂正後の意味一致 | 対象外の保持 | 意味保持生成／要求 |
|---|---:|---:|---:|---:|---:|
| 二事象 | 396 | 396 | 396 | 396 | 792 / 792 |
| 三事象 | 612 | 612 | 612 | 612 | 1224 / 1224 |

1008/1008で確認対象を特定し、確認前の完成文は0件。三つの未確定状態はそれぞれ336件で、いずれも正しい教師後に訂正できた。元パケットは全件不変で、数値更新が対象項目の差分に一致することも1008/1008で確認した。

訂正後は「元の提示順・全て主体先行」と「逆順・対象先行／主体先行を交互」の二通りを生成した。2016/2016で意味・指定語順が一致し、再読解でも意味を保持した。採点器は生成器とは別コードの制御文法を用いる。ただし人手の独立注釈や実世界の真偽検証ではない。

**1008は8種類の出来事構成からの項目変更と符号の繰返しを含む。1008種類の独立した自然文に一般化したという意味ではない。** 新しい語彙や自由構文での精度は測っていない。

## 5. 矛盾・古い回答・誤った教師

代表の二／三事象各1構成、三対象（主体・肯否・隣接時間）、三符号で状態遷移を検査した。分母は繰返しを含む小さな検査集合である。

| 条件 | 結果 |
|---|---|
| 既知値と食い違う通常の追加情報 | 18/18でconflictとなり完成文を保留 |
| conflict中に同じ候補を通常のsupplyで再提示 | 18/18で矛盾状態を維持。繰返しだけで確定しない |
| 明示的なresolve | 18/18で指定候補へ解決・生成 |
| 明示的なrevise | 18/18で既知値を改訂・生成 |
| 古いパケット用の追加情報を再適用 | 18/18で拒否 |
| 未登録値 | 18/18で拒否 |
| 二候補の外の追加情報 | 第三候補がある12/12でconflictとなり保留 |
| 候補内から基準と異なる教師を提示 | 18/18で受理・生成し、基準の意味と不一致 |

最後の行は本版の重要な限界である。外部が誤った教師情報を確認した場合、この系だけでは真偽を判定できない。「矛盾を検知して勝手に上書きしない」ことと、「教師の誤りを見抜く」ことは別である。

**採点名の注意**：固定評価コードの `in_candidate_wrong_teacher` と `world_score/world_wrong` は、実際には基準の意味注釈との差を測っている。18件のうち主体・肯否12件は指定した基準値を変更し、時間6件はunspecifiedからbeforeを追加していた。後者は基準にない明示関係の追加であり、現実に偽の時間関係と証明されたわけではない。元コード・結果・設定は変更せず、`TEACHER_REFERENCE_AUDIT.json` に区別を残した。18件全てを偽の世界事実と呼ばない。

教師の操作は対象パケットのハッシュへ結び付ける。ただしこれは同じ内容・同じ版であることの検査であり、教師認証・改ざん防止署名・異なる実世界の同内容文書の識別ではない。

## 6. 文章経路・複数項目・旧課題

主評価の構造化観測だけでなく、二つの明示的な制御文をSS読解する経路を8構成×3符号＝24件で試した。主体の候補を保持し、外部で選んだ主体に訂正して生成する経路は24/24で意味を保持した。

未観測の主体と読み取り不能の肯否という二項目を持つ6例では、一つの確認後は6/6で保留を続け、二つとも確認した後に6/6で意図した意味と生成を得た。多数の不確かさや依存した候補組合せの処理を保証する試験ではない。現在の候補集合は項目ごとで、複数項目間の「この主体ならこの対象」という依存を表現していない。

旧v0.1の144制御文について完全な読解と逆順・交互語順の生成を試し、読解144/144、意味保持生成144/144、再読解144/144だった。旧864件全体を今回再評価したわけではない。

## 7. 負荷と破損の診断

二／三事象の先頭構成だけで各対象・三状態・三符号を試し、二事象99件、三事象153件を各条件で評価した。

| 条件 | 二事象：正しく訂正／99 | 三事象：正しく訂正／153 |
|---|---:|---:|
| 文書信号1024次元 | 54 | 40 |
| 文書信号128次元 | 0 | 0 |
| 値と事象IDの結合を除去 | 0 | 0 |
| 観測状態の符号を除去 | 0 | 0 |

1024次元では訂正前の観測を復元できたのは二事象71/99、三事象57/153だった。その中にも更新後の整合条件を満たせず拒否した例がある。成功した計94訂正から188件の生成が意味を保持し、診断集合で誤った完成文は0件。他は復元保留または更新拒否で、全件が正常生成できたわけではない。

ここで減らしたのは新しい文書観測信号の次元だけで、既存の言語記憶やv0.1生成用信号は8192次元のまま。状態符号を除く診断では読取側は状態を要求し続ける。この結果は設計した情報経路の依存を示す検査であって、SSの一般的優位性や学習による状態獲得の証明ではない。

数値のゼロ化・半分消去・強い複素雑音・候補の消去・候補の無断追加という5条件×二構成×三符号＝30件は、30/30でabstainとなり生成しなかった。軽い雑音を残した局所更新は単体試験で検査した。広い雑音分布や実通信路での頑健性は未検証であり、P1/S1接続の結果ではない。

## 8. 再現性と情報境界

主評価1008記録、診断1008記録、15保存モデル、全生成文と採点、各初期・訂正信号のSHA-256を保存した。生信号は事前指定した各事象数・各符号の先頭12例の初期／訂正後、計144配列を保存する。残りの信号はケース・モデル・固定コードから再計算できるが、全パケットを生JSONで保存したとは言わない。

主要コードの凍結指紋：`428af4dc3807a2816fe53cc74acea4e3a08128157dd858925fb1b5b652376ed5`。

全評価を二回実行し、時間記録以外の94ファイルがバイト単位で一致した。さらに15保存モデルの再読込・144基準配列の再計算、独立したプロセスでの二／三事象各1例の局所訂正と生成に通った。更新用プロセスには数値パケットと構造化した教師だけを、生成用プロセスには訂正済み数値パケットだけを渡した。生成側にはreader・updater・教師・採点器を置かず、goals引数で事象数も知らせていない。単体試験は41件通過。詳細な完了記録は [VALIDATION.md](verification/VALIDATION.md) に示す。

## 9. 費用と学習の境界

8192次元の複素信号本体は131072bytes。新しい観測符号の基底は33947648bytes、既存生成用の文書基底は10747904bytes、合計44695552bytesを別途持つ。学習済み言語係数、語彙、キャッシュ等はさらに必要となる。信号が一つであることを、省メモリや高速性の優位性とは解釈しない。

三事象の説明例でキャッシュを温めた7反復の中央値は、確認対象の検査18.66ms、局所更新50.69ms、訂正後の生成26.30msだった。外部教師を待つ時間やモデルの初回読込を含まず、他のホスト負荷も隔離していない。費用は `verification/BENCHMARK.json` に記録した。全RSS、電力、全FLOPs、他OS、通常方式との同費用比較は未測定。

更新対象はその文書の観測信号であり、学習済み言語係数ではない。説明例の検査・更新・生成後に保存したモデル6ファイルも、変更前とバイト一致した。訂正前のパケットをもう一度照会しても未確定のままで、別の文書へ訂正を自動で一般化しない。現時点では**正しい追加情報を使ってその場で文章を完成できるが、経験として訂正を長期学習したわけではない**。

この区別を保ったうえで、今後は背景学習を挟んだ後の訂正保持や、同じ対応の再発を実際の生成文で測る土台にできる。本版ではそこまでを達成に含めず、`eligible_for_inference=false` を維持する。
