`verify_release.py` は、全入力の生成全文・復元意味・採点と数値配列を保存結果と比較する。不正入力42件、信号破損15件、局所編集6件も再計算した。単体試験はこれとは別に実行した。

隔離再学習には以前の保存モデル、reader、採点器を置かなかった。隔離生成にはreader、trainer、SS選択器、評価器、教師データ、原文、意味JSONを置かなかった。SS文書パケットと学習済みモデル、および生成に必要な最小Pythonコードだけを渡した。goals引数で事象数を知らせることもしていない。これらは別ディレクトリ・別プロセスでの依存関係検査であり、仮想マシンやOSアクセス制御による敵対的サンドボックス検査ではない。

隔離生成の最初の二例は、明示された時間方向がない評価例である。時間方向を含む三つの説明用パケットの別途配布検査は、配布ZIPと同じ場所に置く外部の `PLM-L1-SS-doc-v0.1-VERIFICATION.md` に記録する。

## 数値と解釈の境界

主評価は144入力文×3文書符号＝432読解要求であり、提示順2通り×語順3通りで2592接続生成要求となる。2592種類の独立した文書ではない。学習と異なるのは完全な出来事の組合せで、語彙・文法・意味スキーマは既知の限定範囲である。採点器は別コードの制御文法であって、独立した人手・実世界検証ではない。

`RELEASE_VERIFY.json` の `manifest_files_checked` はnullである。これは全数再計算を最終マニフェスト作成前に実行したためで、未実施のZIP検査を通過扱いにしていない。最終ZIPのCRC、展開後の全ファイルハッシュ、展開物での単体試験・隔離生成は外部の配布検証記録で区別して示す。ZIPに含めた検証結果そのものを書き換えて自己検証することはしない。

## 事前計画と異なった局所編集の扱い

凍結された主評価の `clean_edge_edit` は、既知の向きの反転ではなくunknownからbeforeへの変更だった。主結果やコードは修正せず、その相違を [REPORT.md](../REPORT.md) に明記した。

主評価後の補足検査で、明示されたbeforeを反対向きに変えるSS数値編集を三符号に実施し、意図した意味・生成・再読解が3/3で一致した。`EDGE_REVERSAL.json` と `EDGE_REVERSAL_SIGNALS.npz` に入力・出力・数値を保存した。補足は主評価の独立標本に追加していない。

自由な長文生成、SS-activeの言語統合、P1/S1の信号経路統合、通常方式との同費用比較は未実施。`eligible_for_inference=false` を維持する。
