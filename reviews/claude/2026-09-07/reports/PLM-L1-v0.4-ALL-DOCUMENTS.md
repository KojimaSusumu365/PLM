````markdown
# 数値仕様・学習と補助処理の分担

## データと分解の前提

各学習例はtext/meaningのみ。内容語語義と意味値の一致を使って一意な役割対応を導出する。markerは語種だけを持ち意味値はnull。
内容語の順序と、その前後の連続marker列への分解は手設計。語尾＋句点のような複数markerも1つの学習対象部品とする。
正解の状態/操作列や部品境界を外部から渡さないが、初期語種と分解規約から境界を自動導出している。これは教師なし文法獲得ではない。

## 学習される対応

8種の対応を扱う。

| 記憶 | 全特徴の候補 | 学習する値 |
|---|---|---|
| roles | 語種、直前・直後、文全体の抽象形 | 内容語の役割 |
| polarity / modality | 先頭marker、各役割後marker、役割順序、文全体抽象形 | 肯否 / 仮定 |
| order_output | 先頭に出す役割 | 内容役割の順序 |
| order_support | 内容役割順序 | 学習済みであること |
| gaps | anchor、肯否、仮定、出力先頭役割 | marker列 |
| lexical_read / lexical_write | 内容語表面 / 語義ID | 語義ID / 表面 |

全特徴が同一の重複観測は統合する。異なる正解値があれば拒否する。
通常の情報利得による決定木型の分類で、教師値を一意にする特徴の組合せを学習する。同率なら分岐数の少なさ、特徴名の辞書順で決める。
純粋な葉の経路が、必要な特徴だけを残した照合マスクになる。根から全ラベルが同じ正例だけの場合は全特徴を残す。正例だけを見て何にでも支持を返す空条件は作らない。
この選択は通常の記号・統計計算で行う。決定木や葉の特徴値/正解対応は学習後に保存せず、マスクごとの数値記憶へ移す。

## 位相符号と部分手掛かり照合

v0.3とバイト同一のalgebra.pyを初期位相生成に用いる。標準8192次元、単位複素位相。
特徴値は特徴ごとに異なる名前空間で符号化する。独立なfeature符号と共有value符号を可換な積で結合するだけでは、異なる特徴間で値を交換した際に区別が消えるため、その方式は用いない。
順序付きの列は長さ符号と位置/階層の名前空間、17*iの成分巡回置換で構成する。文全体を1つの不透明なハッシュへ変換するのではなく、要素から構成する。ただし回復候補の部品列一覧は学習から得た有限カタログである。

マスクmごとに、射影した特徴キーk_mと候補符号vを使ってH_m=Σ conj(k_m)×vを保持する。
取得はH_m×query_mと候補符号の実部平均相関。相関0.65以上、次点（少なくとも0）との余裕0.25以上で採用する。
複数マスクが異なる候補を受理したら保留。同じ候補に一致した場合だけ採用する。未受理の場合も保留する。
同一照会の数値結果キャッシュを使うが、外部の全文や教師対応表へ検索しない。

この「部分」は文脈の特徴を選ぶことであり、P1の欠測した数値成分上の相関・干渉除去を組み込んだものではない。S1の明示チップSS処理でもない。

## 読解・生成

読解は局所的な役割回復→語彙回復→役割順序確認→状態回復を行い、観測したmarker列が学習した各部品で再構成できるか確認する。原文と正解意味の照合は学習時/評価時だけで、実読解には正解を渡さない。
再構成確認は、仮定prefixと断定語尾の混在、助詞や句点の重複等の拒否に使う。これは学習した部品による検証で、手書きの日本語規則ではない。ただし共通部品を読解・生成で使うため、独立単体採点が必要である。
生成は数値意味を回復し、学習した役割順序、先頭marker、各内容語と各役割後markerを組み立てる。v0.3の逐語自己回帰とは異なる、有限の構造部品組立て方式。
語順やmarker選択は数値記憶による。分割・ループ・コピー・型/容量検査はPython補助処理。最大3内容役割、9トークン、256文字の範囲。

## 信号契約

M=Σ_r code(semantic_role,r)×code(value,x_r)。主体・対象・述語・肯否・仮定の5値を役割逆結合と相関で回復する。最小0.65、余裕0.25、再構成に対する相対残差0.20以下。
パケットはschema/model_fingerprint/dimension/real/imag/eligible_for_inferenceのみ。原文・意味ラベル・trace等の余分な項目、モデル違い、非有限値、成分絶対値32超、長さ違いを拒否。
fingerprintは整合性検査であって認証ではない。意味パケットと意味を持つ外部結果はeligible_for_inference=false。

## 受入と限界

除外4条件×4符号seed。各条件で学習432、評価の未学習組合せ48/既出組合せ144。
比較方式も同じデータと同じ初期知識で再学習。full_contextは全特徴を保持、no_learningは語彙以外の数値重みを無効化する。
新旧表引きの比較を別に行う。同じ部分手掛かりの表引きも成功するなら、SSの独自優位ではなく構造共有の改善と解釈する。記憶本数や総メモリ/速度の予算は揃えていない。
標準条件では全単体/往復区分の正解率98%以上、誤受理/誤出力なし。旧方式と全特徴比較の既出組合せ正解率も98%以上、未学習組合せは新方式から50ポイント以上低下することを確認する。
低次元128/512/2048の試験は非合否であり、失敗・誤受理を記録する。未知語義・任意の階層・長文・全学習のSS化・容量適応・P1/S1統合・R1推論は未実装。
````

````markdown
## 実行

```powershell
python -B -m unittest discover -s tests -v
````

````markdown
## 結論

限定された言語範囲で、既知の語順・役割・助詞/語尾部品を、学習から丸ごと外した語順×肯否の組合せへ再利用できました。読解と生成の双方を新しい部品学習方式に変更しています。

例えば付属モデルは『対象先行・否定』を一切学習していません。それでも『花子を太郎が助けなかった。』を読み、主体先行の『太郎が花子を助けなかった。』へ生成できます。対象先行のままの生成や仮定形、主客を交換した例も確認しました。原文は生成器へ渡さず、数値意味パケットだけを受け渡します。

## 固定評価

学習576対のうち、対象とする語順×肯否の144対を除き、432対で再学習。除外セルを入れ替えた4分割×4符号seedです。開発データで実装を検証した後に、ソース・データ・閾値・評価を凍結して実行しました。

| 方式 | 未学習組合せの読解 | 未学習組合せの生成単体 | 両側が未学習組合せの往復 | 既出組合せの読解/生成 |
|---|---:|---:|---:|---:|
| partial | 768/768 | 768/768 | 768/768 | 2304/2304 / 2304/2304 |
| full_context | 0/768 | 0/768 | 0/768 | 2304/2304 / 2304/2304 |
| no_learning | 0/768 | 0/768 | 0/768 | 0/2304 / 0/2304 |
| old_ss | 0/768 | 0/768 | 0/768 | 2304/2304 / 2304/2304 |

新方式の全往復は 6144/6144。誤った意味の受理・完成文出力は 0 件。不正文の受理は 0/496、不正パケットからの生成は 0/192 でした。保留は成功に含めません。

事前受入条件は 209/209 合格。機能・旧版回帰テストは 198 件（新版46＋v0.3の53＋v0.2の52＋v0.1の47）。全数値評価を2回実行し、結果JSON、結果報告、モデル情報のバイト列と数値重み配列が一致しました。

比較のfull_contextは部品分割を同じにして全特徴を必要とする方式、old_ssは旧v0.2読解器とv0.3生成器を同じ432対から再学習した方式です。両者は既出組合せでは動作し、未学習組合せでは保留しました。全学習済みの旧重みを渡した比較ではありません。no_learningは初期語彙だけ残し、それ以外の数値重みを無効にしています。

## 何による改善か

通常の表引きでも、同じ部分特徴の選択と部品共有を使えば、各分割で未学習組合せの読解・生成・往復がそれぞれ48/48、4分割合計192/192でした。旧来の全文型/prefix表引きはそれぞれ0/192。したがって、改善の根拠は部品の分解と学習した依存関係の共有にあり、SS方式だけの汎化・速度・容量優位性は示していません。

v0.3の次語自己回帰から、役割順序とmarker列部品を組み立てる生成へ変えました。分割規約そのものは手設計です。教師は文と意味の対と初期語彙で、手順・語順ラベル・除外セルを学習APIに与えていませんが、語種・語義・意味スロット・一意に対応できる内容語などの前提があります。

対応に必要な特徴は、学習時に通常の情報利得による記号・統計処理で選択します。選ばれた対応を位相連想記憶に保存し、実行時は部分キーで相関照合します。特徴値→正解の表や決定木を実行モデルに残してはいませんが、全学習処理をSS化したわけではありません。

### 付属モデルが選んだ手掛かり

| 判断 | 学習で残した特徴 |
|---|---|
| 内容語の役割 | 直後の記号 |
| 肯否 | 述語の後の記号列 |
| 断定形/仮定形 | 先頭の記号列 |
| 出力語順 | 先頭に指定した役割 |
| 助詞・先頭・語尾部品 | 付く役割、必要に応じて仮定・肯否。語順指定への依存は除去 |

付属モデルは 10 本の8192次元複素ベクトルを持ち、重み本体は 1,310,720 バイトです。候補符号・キャッシュ・メタデータ等を含む総メモリではなく、従来版との同一メモリ予算比較でもありません。

読解・学習の実行ファイルを配置しない生成専用環境でも、数値パケットのみの転送で4例が正しい意味と語順を保持しました。共通の数値モデルと特徴補助コードは残ります。読解に関係する知識まで一切消した検査ではありません。
````
