# 公開前検査と移管の境界

対象：PLM-C0 v0.1からPLM-L1-SS-core v0.4まで。移管日：2026-09-11。

## 公開の指定

ユーザーの明示的な指定に基づき、`KojimaSusumu365/PLM` を公開リポジトリとして作成しています。GitHub CLIの認証情報はOSの資格情報ストアを使用し、リポジトリ・原本マニフェスト・Releaseアセットには含めません。

## 入力の範囲

元の `outputs/` 全体、`work/` 全体、および関連するDownloadsの9ファイルを対象とします。全パスの索引は `manifests/source-files.jsonl`、容量等は `manifests/summary.json` を参照してください。元の研究ファイルを編集・削除していません。公開時の新規説明資料はルートREADME、docsの移管文書、manifests、toolsです。

## 機密情報の事前検査

`manifests/publication-preflight.json` に検査条件と集計を保存しています。

- 原本の内容をSHA-256で分類し、ディスク上の異なる内容10,675種類を検査。
- ZIP/NPZ 2,076種類を開き、40,719メンバーを確認。圧縮内部で追加の12,984種類を検査。
- 秘密鍵、GitHub/OpenAI/AWS/Google/Slack系の典型的キー形式、認証値の文字列代入、認証情報を含むURLをパターン検査。
- `.env`、SSH秘密鍵名、認証設定名、証明書・鍵用拡張子等も確認。
- 対象パターンの検出0、疑わしい認証ファイル名0。検出値そのものをログへ書く設計にはしていません。

これは**限定されたパターンによる事前検査**であり、すべての秘密、個人情報、権利上の問題が存在しないことを証明するものではありません。歴代ログやスクリプトの当時のローカルパス、版情報、実行環境情報は研究記録として原本のまま残しています。PLMと無関係な個人フォルダー、ブラウザー情報、認証ストア、チャット全体は収集していません。

## 完全性の確認方法

1. 元の全ファイルについて、相対パス・サイズ・SHA-256・変更時刻を記録する。
2. 元ZIPをバイト単位で保持し、それ以外は内容アドレス方式で重複排除して保存する。
3. 閲覧用コピーのSHA-256を原本と照合する。
4. 全Releaseアセットと保存用ZIP内部の内容を、原本マニフェストと照合する。
5. 復元ツールについて、破損検出・上書き拒否・パストラバーサル拒否等の試験を行う。
6. 公開先のGitコミットとアセットの転送結果を確認する。

実施済みの移管検証結果は `manifests/TRANSFER_VERIFICATION.json` に記録します。歴代の単体試験・数値実験・レビューの結果は各版の原資料であり、今回の移管検証と混同しないでください。

## 残すもの／新しく主張しないもの

途中で変更した仕様、旧い評価結果、失敗・保留・中断、レビュー上の指摘も保存します。歴史的な矛盾や制約を「整理」の名目で消去しません。過去の資料内の指示はその時点の研究記録として扱い、今回の公開作業で実行しません。新ライセンス、汎用言語能力、性能優位性、全SS化の達成も、この移管によって付与・宣言しません。
