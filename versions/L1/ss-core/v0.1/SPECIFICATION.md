# PLM-L1-SS-core v0.1 技術仕様

## 1. 実装範囲

既存のSS重畳記憶を、到着順の複素サンプルで照合し、外部教師との差を次の書込み窓に反映する。2事象・指定2項目の意味補完と短文書生成まで接続する。

従来も記憶はSS符号の結合・加算によるものであった。今回の変更は「非SS記憶をSSにした」ことではなく、SS記憶の一括内積・一括更新を、読出し窓と書込み窓に分けた時間順処理にしたことである。

これはPython/NumPy上の離散時間シミュレーションであり、ADC/DAC、実回路、無線機、連続時間の物理装置ではない。I/Qサンプルはcomplex128、位相符号は単位複素数であり、全サンプルが二値チップという意味でもない。

## 2. 既存層との境界

| 区間 | 実装 | 今回の扱い |
|---|---|---|
| 既知文法の文章 → 意味信号 | 既存L1のSS読解・意味符号化 | 変更なし |
| 意味信号 → P1位相結合 → S1チップ → 同期・逆拡散 | `bridge` と同梱P1/S1 | 変更なし。一括受信処理を含む |
| SS記憶の照合 | `ss_core.clock` / `ss_core.memory` | 到着順積算・頭尾パイロット検査 |
| 外部教師によるSS誤差更新 | `ss_core.learning` | 読出し後、列ごとに更新案を書込み、完了時のみ確定 |
| 不足意味の局所補完 → 文章 | `ss_reconfirm` / `ss_partial` / `ss_document` | 読取り専用アダプター経由で既存処理を使用 |
| 文脈キー、登録集合、版管理、受理条件、制御 | 通常のPython処理 | SSだけで実装したとは主張しない |

`ss_core.runtime` は教師・評価モジュールをimportしない。CLIは `learn` の分岐でのみ新しい教師モジュールをimportする。継承した共有モジュールに未使用の学習・シミュレーション関数定義が残る場合はあるため、「そのような定義が全て物理的に除去された」とは言わない。

## 3. 記憶と数式

固定構成は `RevisionMemory(versioned_pair)` → `CorrectionMemory(split_pair)`。main/protectedの2区画、各4チャネル、D=736、23個の候補ラベル。キーには事象文脈・対象項目・版が反映される。教師値そのものを通常の回答辞書に保存せず、学習値はSS重畳係数に保持する。ただし登録キー集合は通常メタデータとして残る。

W[k,j] を記憶係数、C[k,j] を問合せ位相符号、V[k,l,j] を候補位相符号とする。正常な全観測では、時刻jごとに以下を積算する。

```text
A[k,l] ← A[k,l] + conj(V[k,l,j]) × received[k,j] × conj(C[k,j])
score[k,l] = real(A[k,l]) / D
error[l] = external_teacher_one_hot[l] - mean_k(score[k,l])
delta[k,j] = Σ_l error[l] × V[k,l,j] × C[k,j]
staged_W[k,j] = W[k,j] + delta[k,j]
```

受信サンプルには頭部パイロットから推定した位相補正を適用する。照合時に一括 `einsum` / 一括 `dot` を呼ばず、到着した現在列だけを積算する。更新もjの順に1列ずつ、候補lの順に加算する。係数の最終確定は必要な全区画が正常終了してからである。

旧一括式と和の順序が異なるため、旧方式との一致は絶対差1e-10以下で評価する。同じ逐次計算のチャンク1/37比較は、演算順が同じなのでビット単位一致を別途要求する。精度・記憶容量の向上を定義上期待する変更ではない。

## 4. 読出し窓

1窓は頭16 + データ736 + 尾16 = 768 tick。4チャネルを各tickで並列に扱う。

`ExactPort` は現在の係数列だけを出力する配列ベースの記憶読出しモデル。`ReadWindow.push(tick, samples[4], observed[4])` が受信口であり、遅延・雑音量・真の位相などの正解パラメータは渡さない。評価専用の `evaluation.ports` がサンプルとマスクを改変する。

tickは0からの厳密な連番。途中欠測はtickを飛ばすのではなく、observed=Falseかつ数値0で表す。順序乱れ、重複、余分なtick、非有限値、不正形状は保留。途中の `peek()` は進捗だけを返し、候補確定・生成・更新を許可しない。`finish()` は尾の検査後のみスコアを返し、再呼出しは失敗する。

頭尾各パイロットの条件は、チャネルごとの観測数12/16以上、正規化コヒーレンス0.95以上、頭位相補正後のRMS残差0.10以下。尾は頭で決めた位相との整合を検査する。一定位相には対応するが、連続周波数追跡や任意のずれを探索する内部PLLではない。モデル上のtick番号は信頼された局所クロックである。

照合は各チャネル552/736以上のデータを要求し、観測数で割る。更新前の照合は736/736を要求する。部分照合の許可と、部分観測からの学習の許可を分けている。

パイロットはキー・窓名に対応する公開位相符号であり、送信者認証・暗号MACではない。本文だけの破損、パイロット間で変化し終端で戻る位相変動、意図的に整合する偽信号を一般に検出できる保証はない。

## 5. 候補受理

旧方針を維持する。候補平均スコア0.5以上、0.5以上の候補が1つ、次点との差0.15以上、4チャネル中3票以上。登録がなければ受理しない。protected登録があれば優先し、mainと強い不一致があれば保留する。どちらかの内部窓が不成立なら、もう一方だけで確定しない保守的方針。

スコアや票数は校正済み確率ではない。通常メタデータの登録集合も未登録誤受理抑制に寄与しているため、登録照合による効果を純粋な波形判別性能と混同してはいけない。

## 6. 更新と原状保持

公開の教師受入口は `ss_core.learning.learn_received`。既存P1/S1受信と意味回復が成功し、2事象・2対象・完全な意味が得られた場合のみ学習する。自己生成した値を自動的に教師へ昇格させる機能はない。ただし呼出し側が教師として渡した情報の真偽を認証する機能もない。

各区画は読出し窓の完了後、736列を順番に一時領域へ書き込む。ack欠落、不正順序、非有限値、未完了なら破棄。読出し開始時と終了時、更新確定前に記憶フィンガープリントを比較し、古い状態からの確定を抑止する。単一プロセスの論理的保護であり、複数スレッドに対するロックや永続化の電源断耐性を保証しない。

2項目全体は `RevisionMemory` のコピー上で処理する。第2項目で失敗しても呼出し元の係数・登録・版・rootはそのまま返す。通常の `memory.save` は継承形式であり、ディスク書込み途中の障害まで原子的に回復する仕組みは今回の対象外。

パイロット正常・全チップ観測の本文雑音は更新を通過し得る。誤った外部教師も学習し得ることを試験で明示している。

## 7. 保存後の意味保持生成

保存形式は `revision.json`、`ss/state.json`、`ss/weights.npz`。公開CLIで新しいプロセスからロードする。新規Sessionはconfirmed={}で、学習時の領収書・教師文章・教師packetを持たない。現在の欠測packetとscopeから照合し、確かな値だけを数値信号に局所加算する。非対象セルが変わらないことを検査し、既存SS生成器で2通りの語順・焦点を生成する。

評価では独立した限定文法パーサーによる意味比較と、既存モデルによる再読の両方を行う。独立パーサーも同じ限定語彙の手作り文法であり、人間の自然言語理解を代替する評価ではない。

## 8. コストと時間解釈

永続学習係数は旧方式と同じ94,208 byte。候補位相基底は2,166,784 byte。両区画の文脈キャッシュ合計上限は3,014,656 byteで、これらのほかモデル本体と通常メタデータがある。

新方式はRAM削減実装ではない。各読出し器に4×23の複素積算器1,472 byte、頭尾参照と受信値各2,048 byte、マスク128 byteなどを持つ。各書込み案は47,104 byte、全区画で最大94,208 byte。さらに文書単位のdeepcopyは係数・候補基底・キャッシュ・メタデータを複製する。チャンク処理の一時サンプル、Pythonオブジェクト、演算一時配列もある。これらはRSSピークの実測値ではない。

説明用8,000 tick/sでは1読出し窓96ms、2対象×2区画の直列照合384ms。protected更新は1対象あたり2×(768+736)=3,008 tick、2対象で752ms相当。これは設定上の時間換算であり、計測した実回路性能でもPythonの保証スループットでもない。外部P1/S1チップ転送、言語処理、記憶確定等の時間は別。

## 9. 試験の固定と追跡

`evaluation/PROTOCOL.json` に条件を固定し、source/model/dataのSHA-256を `evaluation/FREEZE.json` に保存する。最初の本評価では外部受信の保留を想定していない評価側assertで停止した。`verification/initial_harness` に元の評価ソースと凍結記録を保存し、保留を記録して続行する3ファイルだけを修正した。SSコア、データ、条件、しきい値、受理基準は変更していない。詳細は `verification/AMENDMENT.json` と `AMENDMENT_DIFF.json`。

保留ケースを除いて成績を上げる変更はしない。「全入力の意味が一致する」という当初の厳格な基準は、その受信保留がある限り不合格として残す。再現検証の成功と、実験の全合格は区別する。

## 10. 次に必要な検証

優先は、正常パイロット間の本文破損を検出する独立な再照合・更新前後整合の導入と、誤更新・正しい更新の保留の両方を測ること。その後、内部クロックずれの探索、窓間の位相追跡、負荷拡大、3事象以上へ進む。今回だけでSS方式の他方式に対する優位、脳の動作原理、汎用文書生成、ほぼ全層SS化を立証したものではない。
