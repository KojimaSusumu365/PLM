# PLM-L1-SS-active v0.3：教師対応のSS保持と再発照合

## 1. 本版の境界

今回は**観察専用**である。補助記憶からの照合は、主記憶の更新、回答の受理、追加教師の取得順序を変えない。従って本版の検出成績を、訂正保持の改善や教師取得効率の改善と呼ばない。`eligible_for_inference=false`。

外部教師は正しいものとして提示する。`source=external_teacher` は入力の宣言であり、本人性や教師の正しさを認証するものではない。実行時に評価用の正解表を読む機能はない。

## 2. 主記憶

文脈は四項目 `f0`〜`f3`、値は文字列 `0`〜`7`、答えは `0`〜`3`。項目値を固定された複素位相符号へ変換し、要素積で文脈ベクトル `b[k]` を作る。独立符号は四本。

```
s[k,y] = Re(sum_d b[k,d] * conj(H[k,y,d]))) / D
e[y]   = onehot(external_teacher)[y] - mean_k(s[k,y])
H[k,y] += 0.5 * e[y] * b[k]
```

平均相関で最大と次点の差が `1e-12` 以下なら暫定回答を保留する。平均相関0.5以上の候補が一つだけの場合に受理する。この受理規則を補助照合によって厳しくすることはしていない。原版の複素位相生成・共有誤差更新との係数完全一致を単体試験で確認する。

## 3. 教師対応を保持する補助SS記憶

`pair` 方式は、四本×128次元の複素ベクトル `T[k]` に文脈と教師ラベルの結合を重畳する。主記憶とは別の符号を使う。

```
z[k,y] = auxiliary_context[k] * label_code[k,y]
t[k,y] = Re(sum_d z[k,y,d] * conj(T[k,d]))) / 128
T[k]  += sum_y((onehot(external_teacher)[y] - mean_k(t[k,y])) * z[k,y])
```

四候補の残差を更新するのは、一件の外部教師が与えた四クラスone-hotを使うためである。モデルの予測を教師として自習する意味ではない。利得1は本評価前に固定した。以前の対応を正解辞書で取り出して差し引くのではなく、現在のSS読み出しとの差分で改訂するため、古い答えの除去や最新教師の完全保持は保証しない。

補助記憶は32件の追加教師だけで更新し、A/B/Cの基礎学習とD/Eの背景学習では更新しない。主記憶と異なる更新対象を持つ**保護された記憶**であり、この保護効果と符号結合方式の効果を分ける必要がある。

その対照が `bank` 方式である。四本×四ラベル×32次元で同じ8192バイトを使い、同じ追加教師だけを利得1の共有誤差更新で保持する。通常の正解辞書ではなく、ラベル別係数を持つ別形式のSS記憶である。

## 4. 通常メタデータと教師情報の境界

保存する台帳は、文脈IDごとの `context`、`last_step`、`post_margin`、`visits` のみ。`post_margin` は主記憶の教師直後の上位二候補の差。教師ラベル、真の正誤、訂正済みの印は保存しない。台帳はラベルなしの通常のJSONであり、SS符号ではない。

モデルファイルは `state.json` と `weights.npz` の二つだけ。重みは主記憶と補助記憶。符号のキャッシュには項目値・ラベルの固定位相原子だけが入り、学習した文脈ラベル対応は入らない。連続する教師取引の履歴はハッシュのみで、教師を再生する履歴ではない。ハッシュは電子署名ではない。

評価ファイルには検算のため教師ラベルと正解を保存するが、ランタイムへ渡さない。隔離実行で学習器・評価器・教師データを除いて同じ観察結果を得ることを検査する。

## 5. 観察する三つの検出器

- `gap_drop`：前回の教師直後から、主記憶の上位二候補の差が0.15以上小さくなった。
- `ss_disagreement`：補助記憶が十分に支持する候補と、主記憶の暫定回答が異なる。主記憶の同点保留も不一致に含む。
- `ss_weak_support`：補助記憶の支持候補について、主記憶のその候補と他候補の最大値の差が0.15以下。誤りの前の弱まりも拾い得るため、単なる誤答検出とは別の目的が含まれる。

補助支持の条件は、平均相関0.5以上が一候補だけ、かつ上位二候補の差0.15以上。全検出器は台帳に登録され、前回教師から64更新以上経過した文脈だけを対象にする。

未登録照会では台帳条件によって再確認アラームは出ないが、それを補助SS記憶の誤受理ゼロとは呼ばない。台帳を使う前の補助支持を別途測る。

## 6. 比較条件と費用

| 方式 | 主係数bytes | 補助係数bytes | 合計bytes |
|---|---:|---:|---:|
| main384 | 24576 | 0 | 24576 |
| main512 | 32768 | 0 | 32768 |
| main640 | 40960 | 0 | 40960 |
| main384_pair | 24576 | 8192 | 32768 |
| main512_pair | 32768 | 8192 | 40960 |
| main512_bank | 32768 | 8192 | 40960 |

等容量比較は主＋補助の学習係数の比較であり、符号原子キャッシュ、台帳、作業配列、計算時間まで同じではない。符号数、更新要素数、原子キャッシュ、JSONサイズは別計上する。RSS・消費電力・全FLOPsは測定しない。

全方式へ同じ外部教師列を提示する。取得文脈列は、別のmain512参照モデルが作る固定列を全方式・両世界で共有する。従って各方式の自律的な能動選択を比較する試験ではない。参照モデルを作る追加計算・教師提示は別に数える。

## 7. 誤りの分類

「最後の外部教師との不一致」と「現在の世界の正解との不一致」を別々に採点する。後者は、教師の対応を忘れなくても起こる。q16直後に、既に尋ねた8文脈と未照会8文脈の正解を変更する世界を用意する。重みも台帳も変えない `drift_only` 時点では観察値が全く同じでも正解は違う。これは変更検出の一般性能ではなく、観測だけでは分からない場合を明示する対照である。

主評価は、固定世界・post_E・教師直後に暫定正答だった追加教師群の教師対応再発検出。post_D、初回の真の誤答→正答訂正群、世界変化、未登録照会は併記する。事前の設定は `evaluation/PROTOCOL.json`、コード凍結は `evaluation/FREEZE.json`。

同一データ、符号、文脈、測定時点を共有する結果は独立試行ではない。空分母はnull／該当なしとし、100%と数えない。最後まで主記憶を変えないため、アラーム後の再確認費用は仮想上位4件の数だけを示し、実際の追加教師や改善としては数えない。
